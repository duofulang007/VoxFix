## 本轮实现

1. `ScreenOcr.kt` + `ScreenTextPaddleRecognizer.java`：两个正式取字入口共用 ML Kit 16.0.1 定位 + PP-OCRv6 small 识别，不再采用 ML Kit 识别出的正文。复用独立对比包的 BGR/CHW、48px、5% 行边距和 CTC 解码。检测到倾斜四角时做四点校正；未接入 Paddle 独立检测器，ML Kit 完全漏检仍无法补救。识别在截图 worker 上串行运行，结束关闭会话、回收裁剪图，失效会话逐行退出。
2. `tools/prepare_screen_ocr.py`、`build.gradle.kts`、`tools/build_android.ps1`：只准备和打包 small，固定 SHA256 `6f327246b50388f3c176ae304bd95767ea6dc0c9ae92153ef8cbe210b3c14884`，模型 21234383 字节；包内摘要已核验，没有 medium。ONNX Runtime 从 1.17.3 升至固定 1.20.0，保留许可在 `android/app/src/main/assets/licenses/screen-ocr/`。模型和运行库仍在忽略目录，不提交二进制。
3. `ScreenshotParagraphs.kt`：空白切分多栏阅读顺序，合并几何相邻的换行；中英连接不同，标题/列表有基础保护。`ScreenshotCaptureOverlay.startTranslation()` 先合并，再逐段请求模型；段内已有上下文，但段与段仍串行，没有整页共享上下文/并发推理，也没有长页面性能达标结论。
4. `ScreenshotTextLayer.kt`：译文在选区内按段以 16sp 重排，可滚动；保存导出全部重排内容，图片高度可超过原选区，受既有 1600 万像素上限限制。原文仍用原图行坐标，统一文档编辑保留。译文重排会覆盖所选区域背景，不是精细保留复杂背景的修复算法，也不是逐行原位还原。
5. `ScreenshotEditHistory.kt`：原文/译文各自最多 50 个会话内快照；编辑状态工具条增加撤销/重做，隐藏保存和眼睛以腾出位置，完成编辑后恢复。历史不落盘，未做旋转后的撤销栈恢复。
6. 下载修复：首次目录未创建时查询父目录剩余空间，校验 HTTP 206 Content-Range 起点/总长度/边界、拒绝超长响应和不安全跳转；完整 `.part` 可直接校验恢复；取消完成前不允许并发重启下载。`TranslateDownloadRange.kt` 有边界测试。
7. 翻译/语音：保护 native cancel/free 的句柄生命周期；翻译拒绝重入；预热不在翻译占内存时启动，翻译加载前同步释放空闲语音及共享 CTC；主动语音在后台等待取消/释放翻译。JNI 达到 token/context 上限报错，不将截断文本当完成，运行时会对过长段拆分重试。**这些接线尚未完成真实键盘与翻译交替的端到端验收。**

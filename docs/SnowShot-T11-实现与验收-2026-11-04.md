## 2. 本轮修改

- 新增 `ScreenshotArrowhead`（按原版顺序 15 档，含 Circle／Triangle／Diamond 三个 *Outline）与 `ScreenshotDrawingStyle.startHead/endHead`（默认 NONE／ARROW，即原来只有终点一个头的行为）。工程编解码与参数记忆同时覆盖；旧工程缺键读成该默认值，外形不变。
- 新增 `ScreenshotArrowRendering`：尺寸／角度／缩放／比例／头长上限全部按上表；`draw()` 逐形状绘制，`hitTest()` 让圆头按半径、其余按肩线段命中，`boundsPoints()` 让选中框覆盖头部。
- **空心三款的填充语义**：原版用文档背景色刷（会盖住下层元素），手机画布是任意截图、没有背景色，因此改为**露出截图本身**——绘制时把该多边形裁剪后重绘截图位图，再把轮廓描边。效果等价于「在这个箭头上挖一个洞看到原图」，且同样盖住下层标注。
- 渲染器：`ARROW` 的干线与首尾两个头分开绘制；删掉原来写死的 `arrowHead()`（两点折线当三角头）。
- 新增 `ScreenshotArrowControls`：起点／终点各一行 12 档（可访问名为「起点三角」「终点菱形」等）＋描边色／线型／线宽。

## 7. 锥形轴（2026-11-05 第五次接续）

### 8.1 逐档图标（原版 SVG 直用）

- 新增 `ScreenshotArrowGlyphs.kt`：`VectorDrawable` 不支持描边，而这些图标是描边优先的，所以保留原版 path 数据、viewBox、每个元素的 stroke-width、cap/join 与组的 0.3 透明度，用 `Canvas` 描边绘制，而不是把描边压成填充轮廓。自带一个只覆盖这批图标语法的路径解析器（M/L/H/V/Z 及相对形式 + 椭圆弧 `A`），椭圆的端点参数按 SVG F.6.5 换成圆心参数后 `arcTo`，旋转用矩阵约化。
- `-start` 文件与其基础文件的差别只有外层 `translate(40,0) scale(-1,1)`；**crowfoot 三档与 none 是例外**，它们的基础文件本身带头朝左的镜像，所以只有它们的「终点」形态需要翻。表里用 `flipForEnd` 表达，绘制时按 `start != flipForEnd` 施加。
- `arrowhead-square.svg`、`arrowhead-inverted-triangle.svg` **原版不存在**（404），面板也从不提供这两档：`PANEL_HEADS` 固定为原版 `arrowheads` 向量的 14 项顺序（无／箭头／横杠／圆点／圆／空圆／凹三角／三角／空三角／菱形／空菱形／单叉／多叉／双叉）。`SQUARE` 仍可解码，图标复用菱形（原版 `get_arrowhead_points` 本就用菱形分支画方块）。

### 8.2 两端头在极短线段上不重叠

取证结论：**原版没有单独的「两端防重叠」分支**。`get_arrowhead_points` 把每个头限制在 `min(尺寸, 所在线段长度 × 0.5)`（菱形族 0.25，圆头直径同受此限），每个头只占自己所在那一半线段，两端因此最多在中点相接、不会互相覆盖。`arrowhead_scaling.rs::short_arrow_endpoint_sizes_remain_bounded` 就是这条性质的断言（20 长箭头＋20 宽描边，任何端点图元的点距端点不超过 10），`arrow_ratio_preserves_short_arrow_limits...` 另外要求比例不能放大已被截断的头。锥形轴另有 `min(全长 × 0.8)` 截断，两端截断之和吃掉全长时 `clipped_centerline` 返回空，渲染回退普通箭身——这两处此前已按原版移植。

- 把这条限制从内联表达式提成 `ScreenshotArrowRendering` 的 `headReach` / `headLength` / `headDiameter` / `strokeScale`，让渲染与断言走同一个公式；数值与旧实现逐项相同（`min(base·ratio, 半段)`、圆头 `(base+adj)·ratio ≤ 半段+adj`）。
- JVM 新增 `ScreenshotArrowHeadScaleTest`（5 项：短箭头半段上限、比例不能放大已截断头、长线段上比例与粗细缩放、零长线段无头、圆头的描边补偿）与 `ScreenshotArrowGlyphDataTest`（5 项：14 档面板、档档有图标、viewBox 与 none 的 0.3、只有左侧起稿的四档需要为终点翻转、箭身/截面/比例图标在位）。
- 设备断言：15 档逐个在 20 长箭头上同时挂两端，起点头肩点 x ≤ 中点、终点头肩点 x ≥ 中点；控件断言改为触发器 ＋ 弹层 14 项（并含「方块不在面板里」），选项文本、数量、点击改样式都在设备上验证。

### 8.3 参数行按原版顺序、比例按钮图标与弹层定位（同一轮补完）

- **行序对齐 `buildArrowStyleEditor`**：原版依次是 描边颜色／样式 → 线宽 → 箭身三档单选 → 比例 → 起点触发器 → 截面 → 终点触发器。手机改为四行同一顺序：`描边`、`线宽`、`箭身＋比例`、`起点＋截面＋终点`。原来「起点／终点各占一行、箭身与截面在另一行」的排布作废。
- **比例按钮**：原版是 `IconNumericValuePreviewButton`（`arrow-ratio` 图标＋数值，滚轮 0.1 步进、点击回 1.0）。手机原先只有文字「比例 1.0」，现改为自绘图标＋数值，滚轮与点击行为、`contentDescription` 不变。
- **弹层位置**：原版 `AdPopover` `setPlacement(Bottom)`（悬停展开）；手机点按后按锚点计算位置，先试下方、放不下就翻到上方，再按屏幕边界夹紧——参数行贴在屏幕底部，实际总是翻到上方。`showAsDropDown` 在这种情形不会自动翻转（实测被裁掉半屏），因此改为 `showAtLocation` 自行计算。
- 设备实机验证（`adb` 驱动真实窗口，非套件）：展开胶囊 → 框选 → 选箭头工具 → 参数行出现四行且顺序如上 → 点起点触发器弹层出现在触发器上方且完整可见 → 选「菱形」后弹层关闭、触发器图标变成菱形。

### 8.4 修正：曲线箭身丢头部（设备实拍发现）

- 现象：默认箭身是 Curve，实画一条箭头两端**只有圆头线帽、没有箭头**（`.android/snow-t22-arrow/end-zoom.png`）。此前套件只数点数与直线箭头的像素覆盖，未覆盖这一项。
- 根因：原版曲线箭头是**点击式多点创建**（`creation_workflow.rs`：`committed_points` + `AwaitingEndpoint` + 双击收尾），存的是少量点击顶点；手机是拖动绘制，按 1.5×unit 采样存了几十个点。而 `get_arrowhead_points` 的头长上限是「所在线段长 × 0.5」——采样点之间的 1.5 unit 成了「线段」，头长被压到 0.75 px。
- 修法（保留原版规则，不改规则）：`ScreenshotArrowRendering.simplifyCurve` 用 RDP 以**采样步长**为容差把拖动路径折回顶点集（直线段塌成两端点、折角保留、偏离不超过一个采样步），抬起时只落顶点；锥形轴的头部尺寸改按**存储顶点**取 `get_segment_length`（与 `head_geometry` 一致），尖端位置仍取展平路径末端。
- 断言：JVM `ScreenshotArrowCurveSimplifyTest` 5 项（直线塌缩、折角保留、超容差弯折保留、任一点偏移不超容差、退化输入原样返回）；设备 `arrow-gesture` 增加「曲线落成顶点集（<12 点）」与「曲线箭头端部像素比无头多 40 以上」。
- 实机复验：拖一条直线状曲线箭头与一条真正的弧线箭头，两端菱形／箭头都正常，弧线头部沿末端切向（`.android/snow-t22-arrow/drawn-arrow2.png`、`drawn-arrow3.png`）。

## 二、手机实现（本轮第一段）

平台事实：Android 的 `MediaProjection` 只能整屏采集，没有区域参数，也没有"排除某个窗口"的公开能力；系统声音只能通过 `AudioPlaybackCapture` 录到**允许被捕获**的应用。

实现选择与差异：

| 项 | 手机实现 | 与原版差异 |
| --- | --- | --- |
| 区域录制 | `VirtualDisplay` 全屏 → `SurfaceTexture` → EGL 按选区裁剪/缩放 → `MediaCodec` 输入 Surface | 原版后端直接按区域采集；手机在 GL 阶段裁剪，裁切范围与截图选区同一坐标系 |
| 输出格式 | 第一段只做 MP4（H.264 + AAC） | GIF/APNG/WebP 动画格式待第二段；动画格式本来也没有音频 |
| 帧率/清晰度/质量 | 读取设置（默认 30fps、1080p、质量 80），按选区尺寸等比缩放到清晰度上限 | 无 h265/预设选择；硬件编码器由系统选择 |
| 音频 | 麦克风或系统内录二选一（默认系统内录，与原版默认一致）；系统内录录不到禁止捕获的应用时降级为静音轨并在结束时提示 | 原版可两路混音/分轨；手机第一段不做混音 |
| 暂停/恢复 | 停止送帧、停止送 PCM，PTS 扣除暂停时长，容器时间轴连续 | 行为对齐原版 |
| 控制栏 | 选区外浮条：录制时长、暂停/继续、停止保存、取消、麦克风开关；开始前可切麦克风 | 原版工具条含绘制工具，手机第一段不含录制中标注 |
| 成品落地 | 保存到 `Movies/VoxFix/`（MediaStore），Toast 提示；控制条可再打开成品 | Android 剪贴板不支持视频文件，原版"复制到剪贴板"无对应能力，改为保存后即可在相册查看 |
| 光标/键盘特效 | 不做：手机无鼠标、无外接键盘浮显语义 | 原版桌面专属 |
| 延迟录制 | 第一段固定 0 秒 | 倒计时与延迟设置待第二段 |
| 旋转 | 录制中检测到屏幕旋转即收尾保存并提示 | 原版区域固定不随屏转 |

保存与命名：`VoxFix 录屏 yyyy-MM-dd HH-mm-ss.mp4`，与截图命名风格一致；单文件失败时保留临时文件并提示，不静默丢弃。

## 四、验收

- JVM：清晰度尺寸、方向转置、裁切几何、暂停补偿、时长格式、命名；`./gradlew test` 全量零失败。
- 设备：`screenshot-recording` 断言覆盖编码器可用性、MP4 容器与轨道、裁剪帧尺寸、保存库插入与删除。
- 真机：K60 录 10 秒区域视频 → 暂停 3 秒 → 继续 → 停止；核对成品时长≈13 秒、画面为选区内容、音轨存在；再验拒绝授权、录中取消、录中旋转、麦克风开关。每次安装后重绑无障碍，`dumpsys accessibility` 的 `Crashed services` 为空，默认输入法与用户数据摘要不变。

## 六、第二轮：导出设置、延迟倒计时、打开录制文件夹（2026-11-06）

原版录制工具条的导出参数行（`screenshottoolpalette.cpp:5944-6192`）和延迟编辑器（`6110-6130`）已按手机形态落地：

| 子项 | 原版 | 手机实现 | 差异 |
| --- | --- | --- | --- |
| 参数入口 | 工具条常驻一行：格式、轨迹色、点击色、光标、按键、延迟、设置 | 控制条「设置」展开六行面板 | 手机屏窄，改为展开面板；录中禁用 |
| 格式 | MP4/GIF/APNG/WebP | 仅 MP4，面板不列其余格式 | 动画格式编码器未接，见第五节 |
| 清晰度 | 4k/2k/1080p/720p/480p | 同 5 档，点按循环 | 无滚轮，改为点按 |
| 帧率 | 任意整数（默认 30） | 15/24/30/60 四档 | 触屏循环取值，减少误调 |
| 质量 | 0–100 连续，默认 80 | 40/60/80/100 四档 | 同上；码率换算沿用 `bitrate()` |
| 声音 | 麦克风/系统声独立开关 + 分轨 | 麦克风→系统声音→静音三态互斥 | 不做混音/分轨 |
| 延迟 | `startDelaySeconds`，选区窗口倒计时 | 0/3/5/10 秒；投影就绪后控制条倒数，可取消；倒数结束才创建编码器 | 倒计时期间系统「屏幕共享」已生效，无法提前隐藏 |
| 打开录制文件夹 | `openScreenRecordingFolder` | 面板底部「打开录制文件夹」，打开相册视频列表；无处理应用时提示 | Android 无文件夹浏览器 |

参数改动只在空闲状态可编辑，录制中禁用「设置」；面板值写入 `voxfix-recording` 偏好，下次录屏生效（控制条会提示「已记住，下次录屏生效」）。投影授权后的倒计时期间旋转屏幕会取消本次录制并提示重新选区域。

已知可用性问题：录屏图标在默认工具栏布局里位于末段（默认 21 个可点项，屏上只显示两行约 11 个），有选区时会被挤出可视区，需要在工具栏内**向上滚动**才能露出（`ScreenshotToolbarPanel` 的 ScrollView，滚到底后最后一行是贴图／分享／长截屏／录屏）。原版桌面宽度足够，这属于手机小屏适配的既有行为。设备断言与 JVM 不覆盖该布局，真机走查时优先确认能否滚到。

本轮证据：JVM 379 项 0 失败，`screenshot-recording` 复跑 `SCREENSHOT_RECORDING_PASS:media-store`，主包 sha256 `1bc9566352322c0191914146f60a9b10df05badd238e2e45c7b489adc00ea634`（设备一致）。设置面板与倒计时尚未真机点按走查；`screenshot-tool-memory.xml` 因走查时点选了工具而更新，其余 14 项用户数据与安装前一致。

## 七、录制区域边框（2026-11-06，用户反馈「看不到在录哪一块」）

用户反馈：开始录制后选区提示消失，屏幕上只看到整屏，无法确认录制范围（成品实际仍是选区）。原版没有这个问题——它有独立的 `ScreenRecordingAreaWindow`：窗口比选区外扩「边框宽 + 间隙」，选区本身保持透明，边框按状态换色。

取证（`screenrecordingareawindow.cpp:866-900`、`screenrecordinggeometry.cpp`）：

| 项 | 原版 |
| --- | --- |
| 边框宽度 | `kPhysicalBorderWidth = 2` 物理像素 |
| 边框与选区之间 | `kPhysicalBorderPadding = 1` 物理像素透明间隙（给编码器奇数尺寸扩张留位） |
| 颜色 | Idle `#4096FF`；录制 `#F5222D`；暂停与倒计时 `#FAAD14` |
| 形状 | 直角，无抗锯齿（`Antialiasing false`，四条 `fillRect`），不遮罩选区内容 |
| 交互 | 区域窗口负责绘制与录制中标注；边框本身不拦截空白区点击 |

手机实现 `ScreenRecordingAreaView.kt`：全屏 `TYPE_ACCESSIBILITY_OVERLAY` 窗口、`FLAG_NOT_TOUCHABLE`（触摸穿透到下面的应用），在选区外 2dp 处画 2dp 描边，内沿距选区 1dp，因此**边框完全落在 GL 裁剪之外，不会进入成品**。倒计时与暂停用橙 `#FAAD14`，录制用红 `#F5222D`；开始录制时创建，暂停/继续切换状态，停止、取消、服务销毁时移除。

差异：原版 2 物理像素，手机用 2dp（K60 密度下约 5px，2 物理像素只有 2px，触屏几乎看不见）；原版区域窗口还承载录制中标注画布，手机未接（见第五节）。原版没有「触摸穿透」需求，这是手机 overlay 的必要属性。

设备断言 `screenshot-recording-area`：离屏绘制边框并逐像素校验——描边中心为 `#F5222D`、选区内保持透明、暂停切换为 `#FAAD14`，结果 `SCREENSHOT_RECORDING_AREA_PASS:stroke=115px:inside=clear`。

主包 sha256 `337e53d8217eeed2dccd7bc7ae761d1c9aff9fb321b240813a7a3326db0ff360`（设备一致）。本次装机后系统状态一致；用户数据里 WebView Local Storage 的 leveldb 因进程重启轮转（`LOG.old`、`000622.ldb`），其余文件一致。

## 二、手机实现（本轮第一段）

平台事实：Android 的 `MediaProjection` 只能整屏采集，没有区域参数，也没有"排除某个窗口"的公开能力；系统声音只能通过 `AudioPlaybackCapture` 录到**允许被捕获**的应用。

实现选择与差异：

| 项 | 手机实现 | 与原版差异 |
| --- | --- | --- |
| 区域录制 | `VirtualDisplay` 全屏 → `SurfaceTexture` → EGL 按选区裁剪/缩放 → `MediaCodec` 输入 Surface | 原版后端直接按区域采集；手机在 GL 阶段裁剪，裁切范围与截图选区同一坐标系 |
| 输出格式 | 第一段只做 MP4（H.264 + AAC） | GIF/APNG/WebP 动画格式待第二段；动画格式本来也没有音频 |
| 帧率/清晰度/质量 | 读取设置（默认 30fps、1080p、质量 80），按选区尺寸等比缩放到清晰度上限 | 无 h265/预设选择；硬件编码器由系统选择 |
| 音频 | 麦克风或系统内录二选一（默认系统内录，与原版默认一致）；系统内录录不到禁止捕获的应用时降级为静音轨并在结束时提示 | 原版可两路混音/分轨；手机第一段不做混音 |
| 暂停/恢复 | 停止送帧、停止送 PCM，PTS 扣除暂停时长，容器时间轴连续 | 行为对齐原版 |
| 控制栏 | 选区外浮条：录制时长、暂停/继续、停止保存、取消、麦克风开关；开始前可切麦克风 | 原版工具条含绘制工具，手机第一段不含录制中标注 |
| 成品落地 | 保存到 `Movies/VoxFix/`（MediaStore），Toast 提示；控制条可再打开成品 | Android 剪贴板不支持视频文件，原版"复制到剪贴板"无对应能力，改为保存后即可在相册查看 |
| 光标/键盘特效 | 不做：手机无鼠标、无外接键盘浮显语义 | 原版桌面专属 |
| 延迟录制 | 第一段固定 0 秒 | 倒计时与延迟设置待第二段 |
| 旋转 | 录制中检测到屏幕旋转即收尾保存并提示 | 原版区域固定不随屏转 |

保存与命名：`VoxFix 录屏 yyyy-MM-dd HH-mm-ss.mp4`，与截图命名风格一致；单文件失败时保留临时文件并提示，不静默丢弃。

## 七、录制区域边框（2026-11-06，用户反馈「看不到在录哪一块」）

用户反馈：开始录制后选区提示消失，屏幕上只看到整屏，无法确认录制范围（成品实际仍是选区）。原版没有这个问题——它有独立的 `ScreenRecordingAreaWindow`：窗口比选区外扩「边框宽 + 间隙」，选区本身保持透明，边框按状态换色。

取证（`screenrecordingareawindow.cpp:866-900`、`screenrecordinggeometry.cpp`）：

| 项 | 原版 |
| --- | --- |
| 边框宽度 | `kPhysicalBorderWidth = 2` 物理像素 |
| 边框与选区之间 | `kPhysicalBorderPadding = 1` 物理像素透明间隙（给编码器奇数尺寸扩张留位） |
| 颜色 | Idle `#4096FF`；录制 `#F5222D`；暂停与倒计时 `#FAAD14` |
| 形状 | 直角，无抗锯齿（`Antialiasing false`，四条 `fillRect`），不遮罩选区内容 |
| 交互 | 区域窗口负责绘制与录制中标注；边框本身不拦截空白区点击 |

手机实现 `ScreenRecordingAreaView.kt`：全屏 `TYPE_ACCESSIBILITY_OVERLAY` 窗口、`FLAG_NOT_TOUCHABLE`（触摸穿透到下面的应用），在选区外 2dp 处画 2dp 描边，内沿距选区 1dp，因此**边框完全落在 GL 裁剪之外，不会进入成品**。倒计时与暂停用橙 `#FAAD14`，录制用红 `#F5222D`；开始录制时创建，暂停/继续切换状态，停止、取消、服务销毁时移除。

主包 sha256 `337e53d8217eeed2dccd7bc7ae761d1c9aff9fb321b240813a7a3326db0ff360`（设备一致）。本次装机后系统状态一致；用户数据里 WebView Local Storage 的 leveldb 因进程重启轮转（`LOG.old`、`000622.ldb`），其余文件一致。

## 八、红线入镜与画质修复（2026-11-06，用户反馈）

用户反馈三件事：录制范围里出现一条红横线、疑似把选区框录了进去；「屏幕共享」后不少内容录不到、发虚。

### 8.1 红线入镜

根因是边框与选区的间隙只有 1dp（约 3px），而缩小采样与编码器对奇数尺寸的 1 像素扩张都可能把边界外像素带进来。修复两层：

1. `ScreenRecordingAreaView` 的间隙从 1dp 改为 3dp（描边外移 4dp），红框离录制区足够远；
2. `cropFraction` 新增 `insetPx`，录制时向选区内部再收 2px，吸收任何边缘混合与对齐误差。

设备断言随之更新为 `strokeCentre = region.left - 4dp`，结果 `SCREENSHOT_RECORDING_AREA_PASS:stroke=109px:inside=clear`。

### 8.2 码率与清晰度

- 旧码率用自拟的 `像素×帧率×0.07×质量` 系数，1080p30 质量 80 只有约 4.3 Mbps，动态画面发虚、块效应明显。现按上游 `snow-crates/.../video_quality.rs::smart_quality_bitrate_kbps` 逐行移植：1080p30 参考阶梯质量 80 约 14 Mbps、质量 100 约 18 Mbps，按像素数 `^0.92`、帧率 `^0.85` 缩放，并有小区域下限。`ScreenRecordingGeometryTest` 同步改为按该公式断言。
- 清晰度默认从 1080p 改为 2K。原版桌面屏幕一般不超过 1920 高，而手机竖屏是 1080×2400；1080p 档会把整屏录制缩到 864×1920（丢 20% 分辨率）。2K 档在 K60 上保持原生像素，更大区域才缩放。这是手机侧与上游默认值的差异。
- 「部分内容录不到」若指某些应用画面黑屏或模糊，那是该窗口设置了 `FLAG_SECURE`（支付、密码、部分视频与系统界面），Android 在 MediaProjection 层强制屏蔽，任何录屏应用都一样，无法通过代码绕过；若指包含这些窗口的整屏，其余区域仍正常录制。

主包 sha256 `7b596065c1d012631f8be0025cfc53e32faeb52e144d0bf3d49eedd78402eb3a`（设备一致），JVM 380 项零失败，`screenshot-recording` 仍通过，系统状态一致。

## 九、交互修正：拖动只画框、探查可跟手、控制条可移动（2026-11-06 下午）

用户反馈三条：拖动被智能探查抢走、探查预览看不清、控制条固定挡住内容。

### 9.1 手势分工（重写）

| 手势 | 行为 |
| --- | --- |
| 拖动（未到长按阈值） | 手动画框，**永不吸附**，越过 touch slop 后锁定为手动 |
| 点按 | 选中命中的元素，继续点逐层深入 |
| 按住不动超过长按阈值 | 进入探查：显示命中预览；**探查中移动只切换目标**，不会退回画框 |
| 抬手（探查中） | 提交当前预览对应的元素 |

实现：`ScreenTextRegionView` 新增 `exploring` 状态；按下不再立即预览；拖动越过 slop 后 `smartTracking` 关闭且整段手势保持手动；探查建立后 MOVE 只刷新预览。实测 800ms 慢速拖框，框与手指范围一致（误差来自注入插值）。

### 9.2 探查预览可读性

预览改为 3dp 蓝色虚线 + 淡蓝填充（`0x2E4096FF`），确认后恢复实线 + 四角控制点；相邻命中差异小于 6dp 时保持当前预览，减少抖动。

### 9.3 命中框外扩

无障碍边界与 ML Kit 文字行框紧贴字形，直接当选区会切掉笔画、导致后续 OCR 识别不到。新增 `ScreenshotSmartSelection.padded`，预览与提交统一外扩 6dp。

### 9.4 录屏控制条可拖动

控制条任意非按钮区域按住拖动即可移动（越过 touch slop 才接管，按钮点击不受影响），位置被手动移动后不再自动回到选区下方。控制条落在录制区域内时提示「会被录进画面，可按住拖动移开」。

实现要点：控制条是窗口根 View，计时文字等不可交互子视图不消费 DOWN 会让整串手势被系统丢弃，因此由根容器在 DOWN 时接管、MOVE 时按 slop 判定拖动。

### 9.5 录制偏移与红线（同日修复）

`glCrop` 把选区从「屏幕自上而下」换算到 OES 纹理「自下而上」坐标；设备日志 `region=Rect(60,960,1020,1660)`、输出 960×700，抽帧确认无红线、内容与选区一致、控制条未入镜。区域边框按窗口真实屏幕位置绘制，窗口加 `FLAG_LAYOUT_NO_LIMITS`。

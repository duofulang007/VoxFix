## 4. 当前失败与接续第一步

### 已知失败，不能跳过

当前失败日志：`.android/snow-parity-20261104/color/picker.log`。

```text
SCREENSHOT_COLOR_PICKER_FAIL
android.view.WindowManager$BadTokenException:
Unable to add window -- token null is not valid; is your activity running?
ScreenshotColorPickerSmoke.sampling → ScreenshotCaptureOverlay.show
```

失败发生在新测试用普通targetContext开启无障碍覆盖窗口；它没有有效窗口token。它证明**当前测试装载方式未打通**，不能直接推导用户真实服务窗口也必定失败，更不能当滴管已通过。
测试的输入分支执行到采样分支前未抛异常，但整体套件没有PASS；之后的滴管返回、取消、历史与导出断言尚未运行到。

此前一次测试的色相中点偏差已在源码修正：同一左右内边距须以两倍相同取整值计算，避免K60密度取整令中点偏色。失败历史不可误写为当前尚未编译的修复。

### 先检查这些未收尾处

1. 为新增套件提供有效的Activity窗口或真实服务窗口上下文，不通过新增权限／改安全设置绕开token问题，再跑完实际采样链路。
2. 已生成的设备控件图 `color/palette.png` 中，HEX／百分比输入内容未显示、顶部点线预览不清晰。需检查测试切换格式后未重新布局与实际UI各自的影响；**这些现象未修复，也未证实仅是测试问题**。
3. `ScreenshotColorPanel.sync()` 中 `surface().apply { setColor(color) }` 的接收者作用域值得核查：可能取到GradientDrawable自身颜色而非面板当前颜色。暂停时未修。
4. 采样现在由导出型 `colorSamplingBase` 与当前标注组合；尚未证明滚动OCR／长译文／缩放贴图时与实际可见画面一致。应核对坐标、可见裁切、偏移与采样层自身不入采样。
5. 验证颜色面板与滴管切换不提前提交，返回／外部关闭／锚点分离不泄漏弹窗或位图；编辑已有对象只产生一条历史，取消恢复，不污染新建默认值。
6. 对用户参考图完整列子项，复核所有状态、透明度精度、HEX 6／8位、输入范围及HEX／RGB／HSB切换；别只证明类已创建或字段能赋值。

下一项若用户明确指定其他图标，可按其范围接续，但必须识别它是否依赖当前未通过的共用调色板。不要误把共享WIP当稳定底座，也不要擅自清掉它；无新图标指令时先收拢共用调色板的失败项最稳妥。

## 67. T28 GIF 帧间差分与体积（2026-11-06 第九轮）

- **上游依据**：FFmpeg 默认 `gifflags = offsetting | transdiff`（`gif_crop_opaque` 裁变化矩形 + 相同像素写透明索引），Snow Shot 只在调色板与上一帧一致时保留（`gif_palette.rs::GifDeltaState`），并把调色板第 255 项留作透明色。

## 74. T25 滤镜补齐上游六种（2026-11-07 第十六轮）

- **上游事实**：`DisplayFilterType` 共六种——`Mosaic`、`GaussianBlur`、`Grayscale`、`Inversion`、`Emboss`、`Brightness`（`snow-draw-engine-display/src/lib.rs:180-186`）；手机此前只有马赛克与模糊。

  1. 浮雕逐像素算 double 时全屏一帧要几秒（设备套件直接 3 s 超时）。按上游 `EmbossResponse` 的做法把 1531 个 delta 取值预计算成表，并对 alpha=255 的不透明像素再预生成一张 Int 表——截图里绝大多数像素走这条路径。

## 75. 强度语义与马赛克／模糊算法对齐上游（2026-11-07 第十七轮）

- **起因**：§74 结尾列的「强度语义统一」独立待办。旧实现里马赛克是「按强度缩小再放大」，模糊是「缩到 900px + 三次 box 再放大」，两者强度都是 4..64 的像素量，与上游定义不同。
- **上游取证**（固定提交，拉到 `.android/snow-filter-20261107/reference/`）：`snow_draw_engine_qt/crates/snow-draw-engine-display/src/lib.rs` 的 `FilterRenderSpec::resolve`（`mosaic_block_size = 2+10s`、`blur_sigma = 0.5+18s`，灰度/反色强度恒 1.0）；`snow_shot/src/presentation/tools/screenshottoolpalettestylecontrols.cpp:2894` 的强度滑杆 `initialValue = 50` 与回调 `qBound(0, value/100, 1)`；`snow_draw_engine_qt/src/rendering/snow_canvas_filter_render.cpp` 的 `mosaicGrid` / `collectMosaicSamples` / `downsample` / `horizontalBoxBlur` / `axisSample` / `interpolatePixel`。
- **强度语义**：`ScreenshotDrawingStyle.strength` 从 `Int 4..64` 改为 `Float 0..1`，与上游字段同名同域；面板滑杆改为 0..100、默认 50，回调 `/100`。
- **马赛克**：块边长 `round((2+10s) × density)`，网格锚在图像原点（不是选区左上角），每块取**中心像素**铺满——所以拖动选区时块图案不跟着动，与上游一致。旧实现每帧按 crop 重新缩放，块会随拖动抖。
- **高斯模糊**：新 `ScreenshotGaussianBlur.kt` 完整移植 `blurMasked` 管线——`crop ± support` 取源、按倍率把矩形对齐网格、四抽样降采样、三次水平+垂直盒滤波（边缘 clamp、上游 `BoxAverage` 定点倒数）、双线性重建。倍率分档 `<2/4/8/16/32/128 → 1/2/4/8/16/32/64`，`gaussianBoxRadii` 连 `qRound` 的负数舍入都按 Qt 语义实现。
- **迁移**：工程 JSON 与工具记忆都改存新键 `filterStrength`（double，0..1）。缺新键时读旧 `strength`（Int 4..64）按 `(old−4)/60` 换算一次；键名不同而非升 `version`，旧工程照常打开。真机上 05 图滤镜面板显示「强度 18」正是旧记忆值 15 迁移后的结果。
- **顺带修掉一个既有布局缺陷**：详细栏原来按「工具栏下方剩 104dp」决定贴下、按剩余空间限高且内容不可滚动，滤镜三行（类型／面积／强度）时最后一行落到屏幕底部之外——**看得见强度滑杆却点不到**（实测拖动落到桌面，触发系统编辑模式）。改为先按内容测高，放不下就翻到工具栏上方（`detailsAbove`），阈值从固定 104dp 换成实测内容高度。
- **顺带修掉一个测试缺陷**：`screenshot-selected` 的滤镜断言横跨 `130..270` 取 `y=200` 一行，旧源图是黑白横条纹且该行恰为纯黑——§74 新加灰度后「灰度不改变黑色」导致假失败。源图改为蓝/品红条纹（品红是为高亮的 `MULTIPLY` 混合选的两色都带非零蓝分量）。

## 76. 绘图工具下的快速选择：已画元素可直接拖动（2026-11-07 第十八轮）

- **用户报的问题**（2026-11-07）：「滤镜元素无法直接拖动，非要点那个选择元素才能移动，操作逻辑非常反直觉」。实测成立：本地只有 `SELECT` 工具在 `ACTION_DOWN` 里做命中测试，其余工具一律走创建分支，所以在滤镜工具下按住刚画好的马赛克只会再画一条。
- **上游依据**（固定提交，已存 `.android/snow-filter-20261107/reference/`）：
  - `snow_draw_engine_qt/crates/snow-draw-engine-editor/src/input/pointer_intent.rs::resolve_primary_pointer_intent`——**任何工具**下先 `resolve_canvas_hit`，命中 `EligibleElement` 就返回 `BeginElementSelectionMove { id }`，只有 `CanvasHit::Empty` 才是 `EmptyCanvas`（创建）。
  - `input/policy.rs::tool_policy_for`——每种工具带 `selection_scope`（`All` / `RectangleOnly` / `FilterOnly` / `PenFilterOnly` / `SpotlightOnly` …）与 `quick_selection_enabled`，`AutoFilter` 之外默认开启；`set_quick_selection_disabled_tools` 允许宿主按工具关掉。
  - `input/hit_resolution.rs`——命中按 `document.paint_order().rev()` 倒序（最上层优先）逐元素 hit test，再用 `selection_scope_matches_document` 过滤，所以「命中但不属于本工具作用域」不算命中。
- **实现**（`ScreenshotDrawingLayer`）：
  1. 新 `quickSelectionCandidate(active, point)`：按工具映射作用域后取 `candidates(point)` 的最上层命中。作用域：`RECTANGLE`→矩形元素、`LINE`→直线、`ARROW`→箭头、`FILTER`/`HIGHLIGHT`→按当前 `area`（矩形 / 画笔）分开、`SPOTLIGHT`→聚光灯，其余返回 -1。
  2. `ACTION_DOWN` 的创建分支先问命中：命中则 `quickDrag=true`、`selection.press(...)`、`style=it.style`；空白才走原来的 `pending` 创建。`MOVE`/`UP` 优先分派给 `selection.move/release`；`POINTER_DOWN`/`CANCEL`、工具切换、`resetCanvas` 都会清掉这个标志。
  3. 选中框：`onDraw` 从「仅 SELECT」放宽到「SELECT 或 `selectedIndex!=null`」，抬手后框保留；在空白处起笔时 `selectedIndex=null` + `selection.select(null)`，等于放弃选择后画新对象。
- **画笔（`PEN`）刻意不启用快速选择**：本地已按上游 `free_draw` 实现了「贴着已有笔迹端点继续画」并在真机验收（§T08），与快速选择互斥。首版对 PEN 也开了，`screenshot-pen-feedback` 直接崩在 `native lens not created`——因为按下不再走 `ScreenshotPenContinuation.find` + `penFeedback.grab`，放大镜根本没建。按上游 `set_quick_selection_disabled_tools` 的等价语义对 FreeDraw 关闭快速选择；要移动笔迹仍用「选择」工具。
- **测试修正**：`screenshot-parity-foundation` 的「一像素拖动仍落下箭头」原本落在上一组测试残留的箭头上，快选生效后变成拖动旧箭头。这两条验的是**空白处**起笔的退化行为，断言前先清空该层对象。
- **验收**：JVM **436 项 0 失败**（本轮未动纯函数）；设备 17 组 PASS——`screenshot-editing`（新增 `quick-drag`：滤镜块上拖动只移动不新建、空白处仍新建、拖动后保持选中）、`selected`、`history`、`refinement`、`parity-foundation`、`pen-feedback`、`filter`、`document`、`project`、`memory`、`toolbar`、`overlay-suites`、`selection-resize`、`linear-handles`、`selection-style`、`smart-tools`、`recording-annotation`、`recording`。装机 `3f8cf26a…058c4`，默认输入法仍 VoxFix，包列表摘要未变，`Crashed services` 为空。
- **真机对比**（`.android/filter-20261107/`）：`22-drawn.png` 画完一条马赛克笔迹；`23-dragged.png` 在同一工具、不切选择的情况下按住笔迹拖动——原位置整条消失、新位置出现，没有新增第二条笔迹。
- **仍未做**：原版用光标形状（`CursorStyle::Move`）提示「按这里会移动」，手机没有指针形状，靠选中框与结果反馈替代；该差异已在本文记录，不写成复刻完成。

## 77. T12 多指同擦（2026-11-07 第十九轮）

- **为什么做这项**：T12 记录 §5 第 1 条把「原版多指同擦」记成手机侧有意差异。按复刻红线，有原版依据的行为不该停留在差异——上游 `eraser_workflow.rs::process_eraser_pointer_event` 明确按 pointer id 分别擦、最后一根手指离开才提交，手机有多指能力，属于可复刻而非平台限制。

## 81. T03 复制文字取证（2026-11-07 第二十三轮）

- **原版没有「复制文字」按钮**：`screenshottoolpalette.cpp` 的主栏动作只有表格／markdown／latex／html／录屏／贴图／OCR／文字翻译／滚动截图／保存／快速保存／`copy_to_clipboard`（**复制图片**）；结果栏按钮族是 Edit／Text translation／Jump／Formatting／Punctuation／Reset／Translation settings，也没有复制文字。复制文字在原版是**快捷键动作** `copy_text`／`copy_text_and_end_screenshot`（`ScreenshotSettings::autoExecuteAfterTextRecognition`）。手机端把该动作做成结果栏可见入口，属手机侧扩展（因为手机没有全局快捷键），不是原版按钮的复刻。
- **原版复制什么**（`ScreenshotOcrController::copyRecognitionToClipboard` → `ScreenshotRecognitionSessionController::recognitionClipboardMimeData`）：
  - 有可见内容优先走 `copyVisibleContentToClipboard()`，否则按模式生成 mimeData；

  - `applyOcrTextTransforms`（`screenshotocrtexttransform.cpp`，全文已读）：`formatting == "remove"` 时删掉所有 `\n`；`punctuation == "half"/"full"` 时按 32 个 ASCII 符号与全角一一映射互转；**默认两个设置都是空串 ⇒ 恒等变换**。

## 贴图为什么跳到左上方

手机实际调用链：`ScreenshotCaptureOverlay.pinImage()` → `ScreenshotPins.show(context,currentImage())` → `Pin.show()`。

1. 调用方只传裁切后的 Bitmap，丢弃 `picked` 的位置和屏幕显示尺寸。
2. `ScreenshotPins.kt` 的窗口参数把位置写死为 `x=24dp, y=100dp`。
3. `show()` 每次调用 `resize(240dp)`，所以不只是位置跳了，尺寸也变了。
4. `resize/clamp` 又强制避开系统栏并保留边距；直接只改 x/y，整屏或靠边选区仍可能被缩放、挪位。

因此这不是用户框选不准，也不是缺一段过渡动画。窗口创建前必须保留来源区域的屏幕几何，首次显示与用户后续拖动/缩放的约束必须分开。

原位验收标准：选区屏幕矩形为 `(left,top,width,height)`，贴图首帧使用同一矩形；截图坐标先按截图层实际显示大小换算，再加实际窗口屏幕原点。Android WindowManager 使用像素，此处不能把截图像素再当 dp 乘密度。默认不自动居中、不统一缩到 240dp、不为普通安全区挪位。系统确实无法覆盖的区域须按实测处理并记录，不能承诺所有系统界面均可覆盖。

## 不应被误列为缺失 / 需要继续验证的边界

- 已有无标题栏、边角等比缩放、双指焦点缩放、单指接续、橡皮路径补采样、工具组选完收起/返回关闭，不重新实现。这些已有测试不覆盖初始原位，不能用旧 PASS 掩盖第 1 项。
- 原版控件是鼠标进入时出现，且有小窗口尺寸门槛；手机采用点按/长按适配，不能照抄 hover 或 383 物理像素门槛导致小贴图无法关闭。
- 当前锁屏、服务销毁会关闭贴图，旋转会重排；需纳入行为记录。本轮不自动增加持久化、后台恢复或保存用户贴图到磁盘。
- 多选/任意旋转属于对象编辑扩展；贴图穿透、贴顶隐藏、分组管理、镜像旋转、桌面快捷键属于更大能力；先记录差距，不借控件细化扩入此前未选范围。若未来做穿透，必须同时提供可靠退出入口。
- 长截图、录屏、表格、额外形状/箭头、水印、Markdown/HTML/LaTeX、另存为继续按此前约定暂缓。
- 现有聚焦将多个区域共同作用、按最后一个聚焦对象的遮罩色/透明度渲染；本轮未完成与原版多对象样式语义的逐项核实，不能据此断言是 bug，先纳入待核查。

## 改动触点与验证顺序

单线复用当前工作区，不建并行分支、不并行构建、不改已有用户数据。

1. 贴图：`ScreenshotCaptureOverlay.kt` → `ScreenshotPins.kt`；必要的小型几何逻辑放独立文件；`ScreenTextService.kt` 只核对生命周期，不改输入法管线。
2. 样式与呈现：`ScreenshotDrawing.kt`、`ScreenshotDrawingControls.kt`、`ScreenshotDrawingLayer.kt`、`ScreenshotDrawingRenderer.kt`；扩展当前历史快照，不另建绘图引擎。
3. 公共栏：`ScreenshotToolbarPanel.kt` / `ScreenshotToolGroupView.kt` 及相关图标；继续复用已有 Snow Shot 许可资源。
4. 回归：补贴图入口到首帧几何测试，覆盖真实调用链，不能继续只反射调用 `resize()`。扩展 `ScreenshotSelectedToolsSmoke.kt` 的原位/尺寸/小图/恢复检查；样式扩展 `ScreenshotDrawingTest.kt` 与原生渲染检查；回归 `ScreenshotToolbarSmoke.kt`、`ScreenshotEditingSmoke.kt` 的原有文字/OCR/导出行为。
5. 当前计划全在 Android 原生截图模块，`preview/*.test.mjs` 无直接受影响项；不为凑检查跑无关网页。如果后续确实改到前端，再补对应网页回归和 `tools/build_preview.py` 打包，并报告分发产物是否变化。
6. 调研后实施前先取得一条能捕获“从偏离左上角的选区贴图后首帧应在原位”的失败回归，再改调用链。源码断言、JVM、APK 构建、安装、K60 用户触摸验收分别报告。

## 实施中追加：稳定主栏与同级第二栏

用户在实施过程中补充：识别/翻译不能替换主栏、把入口跳到另一层；眼睛、编辑等应在主栏下方共享的第二栏，其他工具也按相同层级呈现详细选项。

重新核对固定版本 `screenshottoolpalette.cpp`：

- `setSecondaryToolbarVisibility`（约1356行）保持 `m_mainPanel`，按当前工具切换 `m_selectActionPanel` / `m_rectangleStylePanel`；OCR和翻译共用动作面板，隐藏其他工具的控件和间隔，而不是替换主栏。
- `activateToolFromToolbar`（约4319行）重复点当前绘图/动作工具回 `Select`；录屏模式有独立例外，本轮不套用到未选的录屏。
- `createShowOriginalImageButton`（约7430行）把眼睛插入 `m_selectActionPanel`，`setShowOriginalImage` 只同步选中态。
- `setTextTranslationState`（约2486行）同步编辑、翻译、历史可用性；主工具按钮保持其工具身份。

统一实施调整：主栏入口、图标和位置稳定；处理时仅禁用不安全动作，保留取消路径；识别/翻译再点回原图，缓存文本/译文不丢；眼睛只做当前结果内的原图对照。复制、编辑、语言选项移入结果第二栏。绘图详细选项与结果第二栏共用下方区域，不新增“更多样式”层级。宽度不足时在这一面板内滚动；不靠反复重排主栏腾空间。语言选择等临时选项在同面板内替换内容，不跳转页面。

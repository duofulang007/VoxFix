## 界面还原的直接依据

发现 `assets/layout/720/port/` 下的布局配置，包括 `py26.ini`、`py9.ini`、`en26.ini`、`digit_panel.ini`、`symbol_panel.ini`、`edit_panel.ini`、`cand_panel.ini`、`switch_panel.ini`、`speech_keyboard.ini` 和 `speech_panel.ini`。其中部分文件已经保存在本目录的 `reference/` 下，保持原始字节。

实际读取 `py26.ini`，可见布局参考矩形 `0,0,720,550`、按键矩形 `Rect`、点击文字 `Click_Input`、点击动作码 `Click_Code`、长按文字 `LongPress_Input`、背景与前景样式及动画编号。例如 Q 键矩形为 `0,99,72,212`，点击文字为 Q。这里是布局参考坐标，不能直接当作用户手机上的像素或 dp。

主题目录包含 default、white_v4、white_v5、black_v4、black_v5、elderly_mode 等样式和按键图片。样式文件可见颜色、按下状态颜色、图片编号等。说明布局、长按文字和部分外观不是完全藏在程序里，能用于建立更接近原版的界面规格。

仍需用户截图确定实际启用的主题、九宫格或全键盘、键盘高度、工具栏配置及个性化快捷键。安装包包含多个版本与状态，不能仅凭目录名判断当前画面。

## 能力与实现路线判断

| 目标 | 当前判断 |

| 还原键位、比例、颜色和常用入口 | 已找到参考配置，可按用户实际截图进一步确定 |

| 自定义长按、切换、工具栏与常用符号 | 可自行实现；原版功能动作码仍需行为验证，不能照搬数字就期待生效 |
| 拼音候选与中文纠错 | 是输入引擎工作，不由界面资源提供，需要选择或复用引擎 |
| 中文离线语音与标点 | 需要识别引擎、模型和实机评测，当前样本不能证明完整能力 |
| 直接裁剪原 APK 后重打包 | 尚未验证可行性；本地没有现成反编译工具，本次未做完整代码反编译 |
| 长期维护个人定制 APK | 更适合独立源码项目，参考原版布局与行为，再接入可维护的输入引擎 |

包内存在 `libspeechlib.so`、`libEVad.so`、`libcom_iflytek_inputmethod_aitalk.so` 等原生库，也声明录音及网络权限。这仅证明存在相关组件或权限，不能证明语音一定依赖联网、一定能离线运行，或可以独立复用。原生算法、模型完整性、认证和服务依赖仍未分析。

初步结论：界面规格提取有明确基础；精简且可持续调整的个人输入法可行。完整复用讯飞识别和预测能力、或直接大幅裁剪其 APK，目前没有足够证据承诺。

## 待确认需求

先确定以下四项即可开始界面方案：

1. **当前画面**：常用键盘、语音页面截图；切换操作可补充短录屏。
2. **必须保留的键**：直接写键名，或在截图上标出；哪些隐藏功能可以删除。
3. **语音交互**：按住说／点击开始；松手或点击结束；实时出字／结束后出字；是否先预览再提交；如何撤销。
4. **更小的含义**：降低键盘高度／减少按钮与页面／减小 APK 与模型占用，可多选。

后续再确认：

- 使用范围：所有应用的系统输入法，还是仅自己应用内的面板。
- 首版键盘：九宫格／全键盘；中文、英文、数字和符号哪些必须保留。
- 默认页面与切换方式：点击／长按／滑动。
- 语音约束：本地离线／允许联网；自动标点、纠错、英文混说、热词优先级。
- 自定义深度：由开发者持续调整，还是用户在设置页改颜色、大小、键位；是否需要拖动编辑。
- 应用功能：具体按钮、点击后的输入内容或操作、是否需要读取上下文。
- 验收环境：手机型号与系统版本，以及最常使用的应用。

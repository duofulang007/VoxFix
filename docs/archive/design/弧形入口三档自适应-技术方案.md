## 0. 先接受一个前提，否则方案会做偏

**拿不到弧下方真实背景的颜色。**

`ScreenTextHandle` 是 `TYPE_ACCESSIBILITY_OVERLAY` 窗口，Android 不允许它读取下方像素；
要真读得走 `MediaProjection`（弹授权、常驻录屏指示、耗电），本方案不采用。

所以「背景明暗」只能**间接推断**，两个可得信号：

| 信号 | 代表什么 | 局限 |
|---|---|---|
| 壁纸主色亮度 / 色彩提示（`WallpaperManager`） | 桌面和大多数 App 的底子 | 滑到深色 App（微信、B站）上时壁纸亮 ≠ 背景亮 |
| 系统深色模式（`uiMode`） | 当前 App 主题 | 有些 App 强制浅色/深色，与系统不同步 |

**这两项都只是近似。** 方案的价值是「比固定一档好」，不是「永远正确」。
若要真正确，只能用双色描边（见第 7 节 B 方案），那是形态改动，需用户单独确认。

写代码时不要为了追求准确率引入前台包名白名单——维护成本高且一个版本后就失效。

## 1. 判定算法

三档 = 亮 / 中 / 暗，与色值表一一对应。

```
若 系统处于深色模式            → 暗档
否则 取壁纸色彩提示：
     HINT_SUPPORTS_DARK_TEXT 置位 → 亮档        // 系统认定壁纸够亮、可用深色文字
     否则按 primaryColor 的 WCAG 相对亮度 L：
          L > 0.55 → 亮档
          L > 0.12 → 中档
          其余     → 暗档
取不到（null / 抛异常）        → 中档（当前已上线的值，最安全）
```

阈值标定（WCAG 相对亮度，白 = 1.0，黑 = 0）：

| 参考色 | L |
|---|---|
| `#f4f1ea` 浅色壁纸 | ≈ 0.88 |
| `#5a8c8d` 中间绿（本机实测壁纸） | ≈ 0.24 |
| `#1a1d22` 深色壁纸 | ≈ 0.01 |

0.55 / 0.12 就是按这张表切出来的，**必须在真机上复核一次**（见第 8 节）。

`HINT_SUPPORTS_DARK_TEXT` 优先于亮度计算：它由系统在生成壁纸配色时一并算好，
比 k-means 主色更贴近「整张壁纸的明暗」，成本也更低。

> **常量值已核实**：`WallpaperColors.HINT_SUPPORTS_DARK_TEXT = 1`、`HINT_SUPPORTS_DARK_THEME = 2`
> （用 `javap -constants` 从本机 `platforms/android-35/android.jar` 读出）。
> 早期网上流传「= 2」是错的，别手写数字，一律引用官方常量。

## 3. 完整代码骨架

### 3.1 `HandleTone.kt`（新建）

```kotlin
package local.voxfix.debug

import android.app.WallpaperColors
import android.app.WallpaperManager
import android.content.Context
import android.content.res.Configuration
import android.graphics.Color
import java.util.concurrent.Executors
import kotlin.math.pow

/**
 * 三档中性灰。取值见 docs/弧形入口状态色-2026-11-04.md，Android 为 #AARRGGBB。
 * 待机沉、激活亮/实，三档内部保持一致。
 */
internal enum class HandleTone(val idle: Int, val active: Int) {
    LIGHT(0x6b6b6b6b, 0xd16b6b6b.toInt()),                  // rgba(107,107,107,.42 / .82)
    MID(0xff979797.toInt(), 0xb3c7c7c7.toInt()),            // #ff979797 / #b3c7c7c7
    DARK(0x8cffffff.toInt(), 0xd1ffffff.toInt());           // rgba(255,255,255,.55 / .82)

    fun colorFor(pressed: Boolean) = if (pressed) active else idle
}

internal object HandleToneResolver {
    private const val KEY_TONE = "handle_tone"
    private val io = Executors.newSingleThreadExecutor { r -> Thread(r, "handle-tone") }

    @Volatile
    private var cached: HandleTone? = null

    /** 主线程可随时调用：永不 IPC，只读内存或 prefs。 */
    fun peek(context: Context): HandleTone =
        cached ?: restore(context) ?: HandleTone.MID

    /**
     * 后台刷新。入口 show() 时调用一次即可。
     * 官方文档明确 getWallpaperColors 走 IPC 且不建议在 UI 线程调用。
     */
    fun refresh(context: Context) {
        val app = context.applicationContext
        io.execute {
            val tone = runCatching { compute(app) }.getOrNull() ?: HandleTone.MID
            if (tone != cached) {
                cached = tone
                ScreenTextSettingsActivity.preferences(app).edit()
                    .putInt(KEY_TONE, tone.ordinal).apply()
            }
        }
    }

    private fun restore(context: Context): HandleTone? {
        val prefs = ScreenTextSettingsActivity.preferences(context)
        val ordinal = prefs.getInt(KEY_TONE, -1)
        return HandleTone.entries.firstOrNull { it.ordinal == ordinal }?.also { cached = it }
    }

    private fun compute(context: Context): HandleTone {
        if (isNightMode(context)) return HandleTone.DARK
        val colors = WallpaperManager.getInstance(context)
            .getWallpaperColors(WallpaperManager.FLAG_SYSTEM) ?: return HandleTone.MID
        if (colors.colorHints and WallpaperColors.HINT_SUPPORTS_DARK_TEXT != 0) return HandleTone.LIGHT
        return toneForLuminance(luminance(colors.primaryColor.toArgb()))
    }

    private fun isNightMode(context: Context): Boolean =
        context.resources.configuration.uiMode and Configuration.UI_MODE_NIGHT_MASK ==
            Configuration.UI_MODE_NIGHT_YES

    /** 纯函数，可单测。 */
    internal fun toneForLuminance(l: Double): HandleTone = when {
        l > 0.55 -> HandleTone.LIGHT
        l > 0.12 -> HandleTone.MID
        else -> HandleTone.DARK
    }

    /** WCAG 相对亮度，白 = 1.0。不用 android.graphics.Color，否则 JVM 单测会 "not mocked"。 */
    internal fun luminance(argb: Int): Double {
        fun channel(v: Int): Double {
            val s = v / 255.0
            return if (s <= 0.03928) s / 12.92 else ((s + 0.055) / 1.055).pow(2.4)
        }
        return 0.2126 * channel((argb shr 16) and 0xFF) +
            0.7152 * channel((argb shr 8) and 0xFF) +
            0.0722 * channel(argb and 0xFF)
    }
}
```

编译要点（照抄时别改）：

- `0xd16b6b6b`、`0x8cffffff`、`0xd1ffffff` 都超过 `Int.MAX_VALUE`，Kotlin 推断为 `Long`，
  **必须 `.toInt()`**，否则枚举构造参数类型不匹配，编译直接失败。
- `0x6b6b6b6b` = 1,801,074,539 在 Int 范围内，可省略 `.toInt()`；统一加上也不出错。
- `getPrimaryColor()` 返回 `android.graphics.Color`，要 `.toArgb()` 取 int。
- `colorHints` 是 `getColorHints()` 的 Kotlin 属性写法。
- **不要 `import android.graphics.Color`**：`luminance()` 用位移取通道，才能在 JVM 单测里跑。
  用 `Color.red/green/blue` 会抛 `RuntimeException: Method ... not mocked`（已实测踩过）。
- **`MID` 档的激活 alpha 反而更低**（179 < 255），它靠明度更亮取胜（199 > 151）。
  写任何「激活更醒目」的断言时必须分档，不能统一用 alpha 判断。

## 4. 线程与性能

| 事项 | 约束 |
|---|---|
| `getWallpaperColors` | 走 IPC，**禁止主线程**；官方明确可能阻塞 |
| 调用频率 | 只在 `show()` 触一次后台刷新；`onDraw` 绝不读 |
| 首帧 | `peek()` 读缓存（内存 → prefs → 默认 MID），零阻塞，不会闪 |
| 常态开销 | 单线程 executor，无定时器、无监听器 |
| 内存 | 一个 `@Volatile` 引用 + 一个 int |

**不要**注册 `addOnColorsChangedListener`：换壁纸是低频事件，监听器要配 Handler 和反注册，
在 overlay 生命周期里容易泄漏，收益不抵成本。「每次 show 刷新」已经足够。

## 5. 失败与降级

| 情况 | 行为 |
|---|---|
| `getWallpaperColors` 返回 null（动态壁纸未实现 onComputeColors / 自定义 launcher） | 中档 |
| 抛 `SecurityException` 或任何异常（个别 OEM） | `runCatching` 兜住 → 中档 |
| prefs 无历史值 | 中档 |
| 首次 `show()` 尚未刷新完 | 中档（与当前上线版本一致，无跳变） |

降级一律到中档，**不要**降级到亮档或暗档——中档是当前已验证上线的值。

- 不改 24×64dp 窗口、弧的贝塞尔控制点、2/2.5dp 线宽、9dp 离屏边、40% 垂直位置、220/180ms 动画。

- 不在 `onDraw` 里做任何 IO / IPC。
- 不加设置项 UI（若后续要手动覆盖，再单独立项）。

```kotlin
package local.voxfix.debug

import org.junit.Assert.assertEquals
import org.junit.Assert.assertTrue
import org.junit.Test

class HandleToneTest {

    @Test
    fun luminanceMatchesWcagEndpoints() {
        assertEquals(1.0, HandleToneResolver.luminance(0xFFFFFFFF.toInt()), 0.002)
        assertEquals(0.0, HandleToneResolver.luminance(0xFF000000.toInt()), 0.002)
    }

    @Test
    fun luminanceOfMidGreyIsAboutPointThreeOne() {
        // #979797 是中间档待机色，WCAG 亮度约 0.31
        val l = HandleToneResolver.luminance(0xFF979797.toInt())
        assertTrue("luminance(#979797)=$l", l in 0.28..0.34)
    }

    @Test
    fun toneFollowsLuminance() {
        assertEquals(HandleTone.LIGHT, HandleToneResolver.toneForLuminance(0.88))  // 浅壁纸 #f4f1ea
        assertEquals(HandleTone.MID, HandleToneResolver.toneForLuminance(0.24))    // 本机绿壁纸 #5a8c8d
        assertEquals(HandleTone.DARK, HandleToneResolver.toneForLuminance(0.01))  // 深色壁纸 #1a1d22
    }

    @Test
    fun toneBoundariesAreLowerExclusive() {
        assertEquals(HandleTone.LIGHT, HandleToneResolver.toneForLuminance(0.5501))
        assertEquals(HandleTone.MID, HandleToneResolver.toneForLuminance(0.55))
        assertEquals(HandleTone.MID, HandleToneResolver.toneForLuminance(0.1201))
        assertEquals(HandleTone.DARK, HandleToneResolver.toneForLuminance(0.12))
    }

    @Test
    fun toneColorsAreLockedToApprovedValues() {
        // 防止有人把色值改回旧的 #407f7f7f / #b3505660
        assertEquals(0xff979797.toInt(), HandleTone.MID.idle)
        assertEquals(0xb3c7c7c7.toInt(), HandleTone.MID.active)
        assertEquals(0x6b6b6b6b, HandleTone.LIGHT.idle)
        assertEquals(0xd16b6b6b.toInt(), HandleTone.LIGHT.active)
        assertEquals(0x8cffffff.toInt(), HandleTone.DARK.idle)
        assertEquals(0xd1ffffff.toInt(), HandleTone.DARK.active)
    }

    @Test
    fun lightAndDarkRaiseAlphaOnPress() {
        // 亮/暗档同色相，靠不透明度分状态
        for (tone in listOf(HandleTone.LIGHT, HandleTone.DARK)) {
            val idleAlpha = tone.idle ushr 24
            val activeAlpha = tone.active ushr 24
            assertTrue("${tone.name} idleAlpha=$idleAlpha activeAlpha=$activeAlpha",
                activeAlpha >= idleAlpha)
        }
    }

    @Test
    fun midGoesBrighterOnPress() {
        // 中档靠明度分状态：激活 #b3c7c7c7(199) 比待机 #ff979797(151) 更亮更跳。
        // 注意此时激活的 alpha 反而更低（179 < 255），所以不能用 alpha 判断"醒目"。
        fun gray(c: Int) = (c shr 16) and 0xFF
        assertTrue(gray(HandleTone.MID.active) > gray(HandleTone.MID.idle))
    }

    @Test
    fun colorForPicksStateColor() {
        assertEquals(HandleTone.MID.idle, HandleTone.MID.colorFor(pressed = false))
        assertEquals(HandleTone.MID.active, HandleTone.MID.colorFor(pressed = true))
    }
}
```

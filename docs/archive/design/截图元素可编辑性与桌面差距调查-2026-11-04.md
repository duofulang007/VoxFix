# 截图元素可编辑性与桌面差距调查

> 历史方案：已由后续实现覆盖，当前状态请看[开发入口](../../开发入口.md)，勿直接照旧计划执行。

日期：2026-11-04。用户要求先调查、统计和找技术；本轮不实现、不构建、不装机、不改图片数据。工作区有既有未提交修改，按当前文件调查，未回退或提交。

## 结论

可以实现“保存进图片剪贴板后，仍能移动、改字、改样式、删除每个标注”。应保存**底图＋可编辑对象＋合成图片**，而不是只换一种图片扩展名。

当前并非所有标注一画出就变成像素：`ScreenshotDrawingStroke` 已记录工具、坐标点、颜色、宽度、文字和样式，`ScreenshotDrawing` 已支持替换、删除和撤销。问题分别发生在工具状态、对象命中、不同文字系统和保存链路。保留现有原生 Canvas 最符合当前项目，不需要重写键盘或引入另一整套编辑器。

“保存后仍能编辑”按用户要求视作本项目新能力，不列为 Snow Shot 已有能力。电脑版基线仍为 Snow Shot 1.1.8 固定提交 `afdc340b14e7f92a294a95c374d13ada0d8c7a82`。

## 统计：12项问题与能力差距

编号是实施清单项，不等于12个已经真机复现的 bug。1–4 是现有交互限制及待复现风险；5–8 是源码确认的编辑/存储缺口；9–12 是对象编辑能力差距。

| 编号 | 发现 | 当前证据与影响 | 状态/优先级 |
| --- | --- | --- | --- |
| 1 | 绘制和移动分属两个工具状态 | `ScreenshotDrawingLayer.onTouchEvent` 只有 SELECT 分支平移/缩放；箭头/聚焦等完成后不自动选中，文字工具再次点旧文字也请求新建。`selectDrawing` 再点同工具才转 SELECT，或需主动点选择工具。用户直接拖旧对象可能继续画。 | 源码确认状态；是否解释这次全部操作待真机复现 / P1 |
| 2 | 选中后，框内空白也不能直接拖动 | SELECT 的 DOWN 在没碰到角点时总重新 `hit`，不优先保留当前选框。空心矩形内部故意不命中；无背景文字只命中字行。点已选框空白会丢选择，用户看到框却拖不动。不能简单扩大所有对象命中，否则会抢走底下对象。 | 源码确认交互限制 / P1 |
| 3 | 重叠对象难以重新选中 | `hit` 从末尾逆序取第一个对象；没有循环选择、对象列表或穿透选择。聚焦区域按区域矩形命中，容易与其内其他标注竞争。 | 源码确认选择机制；实际遮挡组合待验 / P1 |
| 4 | 超出选区两侧的对象可被移动边界锁住 | 平移 dx/dy 被裁剪边界夹取。对象外接框同时越过某轴两侧时，该轴许可位移成为 `[0,0]`；较宽文字/缩小选区后的对象尤其应测。文字初始框通常按240dp宽建立，不等于实际短文字宽。 | 源码可推导边界风险，未真机复现 / P1 |
| 5 | OCR文字与绘图文字不是同一类可移动对象 | `ScreenshotTextLayer` 的识别文字位置由原 blocks 固定，拖动交给 EditText 光标/选字；全文编辑与译文另走文档/重排模式，没有图形平移和缩放接口。绘图的 TEXT 则在 `ScreenshotDrawingLayer`。 | 源码确认能力缺口 / P1 |
| 6 | 保存进图片剪贴板只剩成品图 | `ScreenshotCaptureOverlay.beginSave` 合成 → `ScreenTextService.saveScreenshot` → `ScreenshotStore.save(Bitmap)`；磁盘只有 PNG、WEBP缩略图和尺寸/时间/字节索引，无底图与对象文档。IME桥接也没有重开编辑入口。 | 源码确认主要缺口 / P1 |
| 7 | 进入贴图及每次“完成”都会丢失旧对象身份 | `pinImage` 只把 `currentImage()` Bitmap 传给贴图；`ScreenshotPinEditor` 每次创建空 history，完成时 render 后替换 `ScreenshotPins.image`。再次进入只能在成品上新增，不能改上一轮箭头/文字。 | 源码确认主要缺口 / P1 |
| 8 | 图片剪贴板裁剪另存也只保留像素 | `ScreenshotKeyboard.crop` 解码 PNG → 裁剪 Bitmap → `store.save`，没有元素坐标、裁剪视窗或工程来源。只做持久化而不修此链路，裁剪后仍会断编辑。 | 源码确认后续必须覆盖的链路 / P1 |
| 9 | 没有多选和整体变换 | 只有一个 `selectedIndex: Int?`；无多对象选择集合与群组变换。桌面对照记录已有多选差距，桌面 palette 也有多元素对齐/分布入口。 | 手机源码确认缺口；桌面多选触摸适配待设计 / P2 |
| 10 | 没有对象旋转 | 只有平移和四角非等比缩放，stroke无旋转属性、无旋转柄。桌面既有对照记录将旋转列为差距，本轮未重新核验其引擎全部语义。 | 手机缺口确定；桌面具体细节待补核 / P2 |
| 11 | 箭头没有独立端点编辑 | SELECT 统一处理外接框，不能固定一个箭头端点只拖另一个，也没有折点编辑。桌面额外箭头形态仍属此前暂缓范围，不将其扩入本轮。 | 手机缺口确定；桌面端点交互需专门核验 / P2 |
| 12 | 没有对象层级、复制、对齐/分布操作 | 手机 history 只有 add/replace/remove，UI没有置顶/置底、上移/下移、复制、对齐/分布；桌面固定 palette 的选择面板明确创建相关按钮并连接请求信号。 | 双端源码入口差距确认 / P2 |

### 不误报为缺失的部分

- 会话内已有对象平移、四角缩放、样式修改、单对象删除和撤销/重做。不能宣称“完全没有移动代码”，也不能据此说“用户操作没问题”。
- 截图蓝色裁剪框已有内部移动、边角调整；绘图工具、OCR文字编辑和结果层会接管触摸。因此要分别验证“截图裁剪框”“绘图对象选择框”“聚焦区”“文字输入框”，不能统称一个框。
- 图像本来含有的文字、箭头或图案是底图像素；没有对应工程数据时，不会自动成为可编辑对象。
- 多个聚焦区域当前取并集，但统一使用最后一个对象的遮罩色和透明度。它不是多个彼此独立的遮罩层；是否改成独立样式需另定语义，不在未核对桌面渲染之前直接认定 bug。

## 推荐技术：本地可编辑工程＋普通图片导出

外部技术、固定版本、许可与官方链接见[技术调研](截图可编辑图层技术调研-2026-11-04.md)。

建议以现有 `ScreenshotDrawingStroke` 为起点，新增小型工程模型/编解码文件，不在大类里堆另一套引擎：

| 保存内容 | 用途 |
| --- | --- |
| 未合成的底图，限定为实际工程所需范围 | 删除/移动标注后恢复底下内容，不额外留存整屏私密区域 |
| 带格式版本的对象 JSON | 对象稳定ID、类型、坐标/变换、样式、文字、堆叠顺序；效果存区域和参数，按需重新渲染 |
| 当前裁剪视窗、画布尺寸及明确字体度量 | 重开、裁剪、横竖屏与贴图缩放后仍定位一致；不能让字号依赖当次窗口大小或字体缩放设置 |
| OCR/译文的文字、块几何和显示模式（如纳入可编辑范围） | 避免只保存手画对象而丢掉“编辑后的文字”；文本修改与对象变换须区分，保留原有全文编辑 |
| 合成 PNG 与缩略图 | 图片剪贴板预览、复制、插入聊天和普通分享继续使用常规图片 |

保存工程时应把底图、文档、成品图作为一份一致记录提交，成功后才更新索引；不能只让 JSON 原子写入而 PNG 已覆盖。修改失败、磁盘满、强杀应保留上一版。现有100张/128MiB限额必须按新增底图/文档实际占用重新计费，删除也清理关联文件。不要默认无限保存全部撤销快照；“能继续编辑”不要求无限历史。

旧记录作为“普通图片”兼容打开、允许加新标注；不能恢复以前已压进PNG的独立元素。裁剪建议保存视窗/坐标映射或生成带独立工程的新副本；不要直接丢掉图层。工程跨进程重开不依赖旧截图会话或仍活着的贴图窗口。

分享、系统复制和插入聊天默认仅输出合成图片。工程中含底图，被打码内容仍可恢复，因此工程文件不能跟普通图片一起悄悄分享；若以后提供工程导出，应单独明确选择。

### 为什么不直接“存SVG”

SVG能描述矢量形状、文字和图像，但它不自动提供选择命中、触控、撤销、文档迁移，也不会把底图变成矢量。当前模糊/马赛克与Android文字排版还需要一致的重建规则。JSON保存业务对象更贴合现有代码；SVG可以日后作为额外导出格式，不作为本轮继续编辑的前提。

## 后续实施建议与验收

1. 先补真实入口的失败回归：画箭头/聚焦/文字 → 完成编辑 → 重新选择并移动/删除。必须从 overlay 根视图分发触摸，不能只直接调用 `layer.onTouchEvent` 或直接替换 history。
2. 修当前会话编辑体验：选择入口与状态、选中框空白拖动、重叠对象可达、越界对象恢复；不破坏连续绘制和文字光标选区。
3. 接工程保存与剪贴板“编辑”，同时覆盖截图→贴图→完成→再编辑、剪贴板裁剪另存→再编辑。保存后杀进程重开仍可逐对象改字、移动、改样式、删除，成品图与编辑结果一致。
4. OCR文字几何、统一历史及对象编辑边界单独接线；不能为了统一图层删掉现有全文编辑功能。
5. 多选、旋转、箭头端点、层级等按本表继续补；这些操作都写入同一工程模型，避免第二次推翻存储格式。

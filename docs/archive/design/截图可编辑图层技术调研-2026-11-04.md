# 截图可编辑图层技术调研

> 历史方案：已由后续实现覆盖，当前状态请看[开发入口](../../开发入口.md)，勿直接照旧计划执行。

日期：2026-11-04。范围：技术与现有数据结构调查；没有接入新依赖、修改运行代码或做真机验证。本文是候选方案，不是实现完成记录。

## 结论

可以实现用户要求的“保存到图片剪贴板以后，仍可单独移动、修改、删除文字、箭头、聚焦框等元素”。准确的技术是**非破坏性编辑文档：原图＋对象图层＋编辑参数**。截图底图本来就是位图，不必把整张图转换成矢量；把新增标注以结构化对象保存即可。

建议继续使用现有 Kotlin 原生 Canvas 与 `ScreenshotDrawingStroke`，补文档持久化与重新打开链路。现有代码已经保留工具类型、点列、文字、样式，并有替换、删除、撤销及平移/缩放方法；不需要为此整体替换编辑器。这里的建议是根据本仓库现状作出的工程判断。

## 本仓库已有基础与缺口

- [ScreenshotDrawing.kt](../../../android/app/src/main/java/local/voxfix/debug/ScreenshotDrawing.kt)：`ScreenshotDrawingStroke` 包含工具、点列、样式、文字和尺寸；`ScreenshotDrawing` 用对象列表快照记录编辑历史；`transformed()` 可平移/缩放。
- [ScreenshotDrawingLayer.kt](../../../android/app/src/main/java/local/voxfix/debug/ScreenshotDrawingLayer.kt)：`SELECT` 分支已编写命中、拖动及四角缩放，说明“完全没有移动能力”不能仅根据模型成立；是否能正常触达、是否被别的 View 抢触摸，需另查真实操作链路。`render()` 会把对象画入合成位图。
- [ScreenshotStore.kt](../../../android/app/src/main/java/local/voxfix/debug/ScreenshotStore.kt)：`save(Bitmap)` 保存 PNG、WEBP 缩略图及尺寸/时间/字节索引，没有保存对象和独立原图的接口。图片文件本身因此不能恢复已合成的独立标注。现有总量上限为 100 张/128MiB，新增源图和编辑文档后必须把这些文件一起计入限额。

“当前会话不能拖动”与“保存后不能重开编辑”是两个问题：前者要查输入、命中与选中状态；后者缺的是持久文档。只换保存格式不会自动解决前者。

## 技术对照

| 路线 | 能满足什么 | 仍要实现/限制 | 对本项目判断 |
|---|---|---|---|
| 原生 Canvas＋版本化 JSON | 用点列、坐标、文字、样式重新绘制；对象可移动、删除、修改 | Canvas 是绘制 API，不是自动提供对象选择和项目文件的完整编辑器；继续复用当前对象模型，补保存/加载与交互 | **优先**，改动范围最小。平台 Canvas 能绘制路径、文字与位图，见 [Android Canvas](https://developer.android.com/reference/android/graphics/Canvas) |
| SVG | 保存形状、路径、文字、分组和变换；可嵌入底图 | 是图形文档格式，不会自动提供手机命中、手柄、撤销、图库恢复；截图底图仍是位图，滤镜/遮罩和原生文字排版还需验证 | 可考虑以后作为交换/导出格式，不建议把它当本轮唯一工程格式。见 [W3C 文档结构](https://www.w3.org/TR/SVG2/struct.html)、[嵌入图像](https://www.w3.org/TR/SVG2/embedded.html) |
| Fabric.js | 对象交互、文字、路径、JSON/SVG 导出；可自定义对象属性 | 自定义控制与事件处理不随状态自动保存；箭头、聚焦、滤镜等业务语义仍需定义；迁入 WebView 还要重做现有原生叠层和输入衔接 | 能做，但本项目没有必须换引擎的证据。见 [核心概念](https://www.fabricjs.com/docs/core-concepts/)、[自定义属性](https://www.fabricjs.com/docs/using-custom-properties/) |
| Konva | 场景节点、拖动、Transformer 缩放旋转、JSON 序列化 | 图片和事件不能直接序列化；官方建议复杂应用保存业务状态。文字内容编辑需 DOM input/textarea；聚焦效果仍需组合遮罩或自定义节点 | 适合网页编辑器备选，但不是接入即完成。见 [变形](https://konvajs.org/docs/select_and_transform/Basic_demo.html)、[序列化](https://konvajs.org/docs/data_and_serialization/Serialize_a_Stage.html)、[文字编辑限制](https://konvajs.org/docs/sandbox/Editable_Text.html) |
| Android PhotoEditor | 原生文字/贴纸编辑、手势缩放旋转、画笔及撤销 | 官方公开保存接口是文件或 Bitmap；本次未找到可直接承诺“全部对象持久项目保存/重开”的接口。不能据此断言内部完全无法扩展；聚焦工具和当前工具语义仍需适配 | 可借鉴原生对象手势；不能仅换库就交付持久图层。见 [项目功能](https://github.com/burhanrashid52/PhotoEditor)、[保存接口](https://burhanrashid52.github.io/PhotoEditor/features/saving/) |

## 建议的最小完整文档

一个剪贴板项目至少同时保留：

1. 未合成标注的原图；截图裁剪的坐标基准和输出区域。
2. 版本化 JSON：稳定对象 ID、工具、顺序、几何、文本/序号、样式；OCR/译文如属于可编辑内容，也要保留结构和编辑结果。
3. 合成 PNG 与缩略图：继续供图片剪贴板展示、复制、分享和插入聊天使用。

重新编辑时读取原图和对象；保存时先写完整的新版本，再切换索引，避免图片更新了而对象文件只写一半。平台 [AtomicFile](https://developer.android.com/reference/android/util/AtomicFile) 只负责单文件原子替换，不能把几个独立文件自动变成一个事务，因此需以文档版本/索引作为整体提交点。撤销历史是否跨重启保存可另定；“对象能再次编辑”不要求把所有历史步骤永久保留。

内部工程文件只留应用私有目录；复制/分享仍发合成图。**可编辑文档保留原图，因此马赛克/模糊可以被移除，原始敏感内容仍在内部工程里；不能把内部工程文件当成已脱敏图片分享。**这是此需求本身带来的存储语义，落地时必须落实分享边界。

## 迁移与验收边界

- 旧 PNG 保留为普通底图，继续查看、复制和新增标注；已经合成进去的旧箭头、文字不能可靠自动拆回原对象，不承诺无损恢复。
- 裁剪应先保留原图并记录裁剪窗口，避免裁掉后无法恢复；移动标注时须明确采用原图坐标，不能混用屏幕 dp 与像素。
- 文件加载需校验版本、尺寸、对象/点数、有限数值和资源引用范围；损坏工程应保留原文件，至少仍能显示既有合成预览。
- 验收必须覆盖：各工具创建→选择→移动/缩放→改样式/文字→删除→撤销/重做→保存→关闭/强杀→图片剪贴板重开→继续编辑→分享结果一致；增加裁剪、重叠对象、多指取消、旋转与大图压力。

尚未验证：任何候选库的 K60 性能、真实手指交互、工程格式往返效果、实际对象移动故障复现。本文不能作为这些项目通过的证据。

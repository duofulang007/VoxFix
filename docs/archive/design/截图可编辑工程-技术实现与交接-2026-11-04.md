## 2. 完成标准与范围

### 必须完成的主链路

1. 当前截图会话内：箭头、矩形、画笔、高亮、聚焦、滤镜区域、绘图文字、序号可重新选择、移动、调整支持的几何/样式、删除，并可撤销/重做。
2. 截图→贴图→编辑→完成→再次编辑，旧对象仍独立存在；取消不改原对象或贴图内容。
3. 保存→图片剪贴板→编辑→保存→退出/进程重启→再次编辑，旧对象仍可移动、修改、删除；预览、复制、插入聊天与编辑后结果一致。
4. OCR/译文用户修改、位置与显示模式不能在工程往返中丢失；OCR文本块需有明确的移动/尺寸编辑入口，不能拿新增绘图文字冒充已支持原OCR文本框。
5. 图片剪贴板裁剪另存保留工程对象与坐标映射，原记录不变；普通旧图片也能添加新标注。
6. 写盘失败、取消、损坏工程、旧记录不导致用户现有图片/词库/剪贴板丢失；普通分享只发送合成图片。

### 能力补齐项（主链路完成后，不混算为存储修复）

多选整体变换、任意旋转、箭头端点编辑、对象复制、置顶/置底和前后移动、对齐/分布。模型要留出正常字段表达这些操作，但首阶段不为其写空实现、额外配置或完整群组框架。若用户要求完整实施12项，接手者在主链路稳定后继续这些项；否则保留为明确待办，不悄悄扩范围。

不新增录屏、长截图、其他箭头形态、云同步、训练记录、独立截图管理页或SVG编辑器。保留输入法编辑框、八方向盘、滑轨锁定和宿主选区，勿与本次截图选择框混淆。

## 4. 技术方案：原生对象文档，不替换引擎

保留 Kotlin Canvas、`ScreenshotDrawingStroke`、既有滤镜/文字排版与工具样式，新增小型文档模型与编解码。SVG仅可作为未来导出格式；当前无需新图形依赖。

### 4.1 文档模型

建议新增 `ScreenshotDocument.kt` 与 `ScreenshotDocumentCodec.kt`，下列为逻辑协议，不要求照抄类名或制造接口层：

```text
ScreenshotDocument
  version: 1
  canvas: { widthPx, heightPx }
  viewport: { leftPx, topPx, rightPx, bottomPx }
  objects: [ { id, kind, geometry, style, content } ] // 数组顺序为绘制顺序
  textState: OCR/译文块、修改值、几何、背景恢复信息、布局模式、当前显示模式
```

- 对象稳定ID只生成一次，移动、样式、文字变化保持ID；复制生成新ID。不要用可变列表下标充当持久身份。
- v1 geometry直接复用已有点列、textWidth/textHeight等；字体、笔宽与尺寸在创建时换算为画布像素并保存。绘制到窗口时用同一映射缩放，不能在重开时再次按density乘一遍。
- 旋转扩展需要明确局部原点与变换顺序；若当轮不实现旋转，就先不写虚假角度控件。坐标烘焙和矩阵方式选一种统一，不能平移时改points、旋转时又无规则叠加。
- 原图本身不是矢量，新增对象才是可编辑标注。滤镜保存区域/点列、效果类型与强度，按底图重新取样；不能把滤镜结果当底图覆盖掉。
- 工程快照深拷贝所有点列/列表和文本，异步写盘不得引用触摸仍会改变的数据；历史只在内存保存必要快照，暂不持久化全部撤销栈。
- JSON显式白名单字段，不序列化View、Bitmap、回调、系统字体对象或缓存；未知版本保留文件并回退成品预览，不能擅自按空工程覆盖。
- 加载校验：ID、版本、画布/视窗范围、数值有限性、对象/点列/文本总量上限；资源路径只由程序生成，拒绝任意路径和外部资源。限额结合K60现有内存测量确定并写成测试，不凭“能解析”就接收无界输入。

### 4.2 坐标与裁剪

初次保存只保留当次截图选区所需底图，不额外存未选择的整屏区域。设当前选区左上角为 `(L,T)`，导出工程时将对象/文字块坐标统一减去 `(L,T)`，底图与画布原点变成 `(0,0)`；不能只移动箭头而漏掉OCR背景、路径和滤镜区域。

剪贴板后续裁剪是同一工程内部的 viewport，仍用底图画布坐标，导出时 clip 后平移；重开需能定位裁剪视窗，隐藏区中的对象保留。另存副本使用新记录ID，不破坏原项目。未完成裁剪按现有交互取消。贴图的屏幕Rect与文档坐标严格分开，屏幕缩放不会修改对象内容尺寸。

超出视窗的对象允许重新拖回；不要用“对象必须完整位于当前裁剪范围”把整轴位移夹为零。最小可达边界与可见选择柄需明确处理，整体移动/缩放可撤销。

### 4.3 存储与一致性

继续使用应用私有 `files/screenshot-clipboard/`，建议通过索引版本2支持新旧混合记录：

```text
旧记录：<id>.png + <id>.webp             // 不批量迁移/删除
新记录：projects/<id>/source.png         // 底图，本项目内复用
        projects/<id>/<revision>/document.json
        projects/<id>/<revision>/composite.png
        projects/<id>/<revision>/thumbnail.webp
index.json：旧记录字段兼容；新记录增加kind/revision/实际总bytes
```

revision由程序生成，文件名不接受UI传入。具体磁盘布局可按现有Store简化，但必须做到：

1. 在Store工作线程串行写入，先校验再写完整候选修订；编码失败、磁盘满、取消均不发布索引。
2. 源图和全部修订文件完成并关闭后，用现有AtomicFile发布新索引；索引是提交点。单文件AtomicFile不等于多文件事务。
3. 索引成功前旧修订始终可读；成功后才清理无引用旧修订/临时文件。不扫描删除未知路径，不删除旧普通图片；失败残留限定在自身生成的修订目录并在安全时回收。
4. 更新同一项目检查预期revision，防止旧编辑覆盖新保存，尤其用户删除后异步保存完成不能把记录“复活”。原子索引更新和删除在同一Store锁内协调。
5. 继续执行100张/128MiB现有限额，但bytes包含底图、对象、成品、缩略图；更新不重复计旧修订，写入前还需检查临时空间。不能通过裁剪/编辑绕过限额，也不能未经用户决定提高上限或自动删旧图。
6. `file(id)`/`thumbnail(id)`统一解析已提交索引中的修订，旧调用者不自己拼路径。外部ContentProvider继续只提供合成PNG只读URI，不提供source或document路径。
7. 同一ID编辑后系统已授予的URI可能读到新成品，需保持现有语义；分享临时文件仍由`ScreenshotShare`输出固定快照。WebView继续no-store，保存完成触发刷新，避免预览缓存旧内容。
8. 删除先原子移除索引，再清理该记录关联文件；失败清理不恢复到列表，保留可重试的垃圾回收边界。读写在主线程外，Bitmap生命周期不能与仍在绘制的View冲突。

不覆盖老PNG去“补底图”，也不对旧图自动逆向恢复箭头。旧图编辑时以旧成品作底图，仅新加标注可单独改；首次保存生成新工程副本并保留原记录。新工程日常“保存”更新当前记录；“裁剪另存”始终新记录。

## 5. 交互实现约定

以下为推荐默认行为，接手者需与现有连续绘制、文字选区和触摸结构核对，不能为修拖动破坏输入。

### 5.1 选择与移动

- 保留显式“选择对象”工具及当前工具再次点击返回选择的入口；当前选择状态必须可见。不要让同一DOWN既新建标注又拖旧对象。
- 绘制工具保持连续绘制，不能每画一笔强制退出；文字完成后选中本对象并进入对象选择，方便改位置。其他工具如增加画后直接拖动能力，须先给出不干扰连续绘制的手势规则。
- SELECT命中顺序：当前对象控制柄→其他对象真实轮廓命中→当前已选框内部空白用于拖动→空白取消选择。若命中当前轮廓则保持当前；聚焦大区域与细小对象重叠时须可选到底层。
- 重叠选择先实现紧凑“切换重叠对象”动作：仅多个候选时出现，按固定绘制顺序循环，复用当前第二栏，不新增常驻调试面板或完整图层侧栏。
- 空心矩形内部不作为首次选中目标，已选中后框内空白可拖；无背景短文字的空白框规则同上。不要通过扩大所有命中框解决单个问题。
- 触摸拖动达到系统slop才开始；ACTION_CANCEL/多指中断恢复手势前状态，松手提交一次历史。角点、箭头端点（后续）、框体平移明确分开。
- 聚焦、文字、序号、画笔、滤镜均走同一选择/删除路径；聚焦渲染仍保持目前多个洞取并集的语义，未经核实不私改成多个遮罩叠乘。

### 5.2 文本内容编辑与对象变换

- 文本“编辑内容”使用现有输入组件，负责光标、选字和组合输入；对象选择负责移动/尺寸。不在EditText输入过程中把手指选字解释为移动整块。
- `ScreenshotTextLayer` 不再只把几何当构造时常量：块数据成为可替换文档状态，位置/尺寸和文字都进入同一文档历史；保留OCR段落来源关系，避免改一块导致全文顺序乱掉。
- 保留识别结果、译文和原图对照模式；工程保存当前模式及两份修改值。OCR块移动后原位置的遮盖和新位置的文字背景要有独立数据，不能让文字移动时原字又露出，或把底图永久涂改。
- 全文编辑继续作为独立编辑视图；合并/拆段后用明确规则重建对应文本对象，取消恢复原块。译文重排模式的段落是文档布局，不把段落滚动误做对象拖动；选择/变换时提供可编辑的块布局视图，保存此模式，显示/导出一致。
- 绘图TEXT与OCR文字可共用几何/样式/历史操作，但不要求为了抽象统一重写整个文字渲染器。OCR原文、用户修改值与译文不得互相覆盖。

### 5.3 工程重开入口

- 图片预览增加“编辑”动作，保留复制/裁剪/插入聊天；使用现有同级操作布局，不恢复独立截图管理页。
- 建议桥接 `screenshotEdit(id)`：校验存在与revision后投递主线程，通过已绑定`ScreenTextService`打开原生编辑器；不得在JavascriptInterface线程创建窗口。服务不可用时清晰反馈并保留图片预览，不自动改无障碍配置。
- 编辑器加载、渲染/保存走后台线程，UI只应用有效generation结果；一个活动编辑会话，重复点击不叠窗口。复用截图/贴图的工具层和样式，不另起第二套功能。
- 原生完成回调通知仍活着的IME WebView刷新列表/预览；IME切换、WebView销毁后丢弃回调，下次打开从Store读取，不持有旧View。保存失败停留编辑可重试；取消不写盘。
- 贴图保留文档与预览：进入编辑给文档副本，完成替换两者，返回仍在原位置与比例；编辑前的底图不销毁，渲染器也不能过早recycle仍供硬件帧使用的Bitmap。

## 7. 验收矩阵

### 自动回归

| 用例 | 必须断言 |

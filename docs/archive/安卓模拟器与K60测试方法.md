## 已安装环境

- Google 官方 Android Emulator 37.2.12，Android 15/API 35 Google APIs x86_64 镜像，platform-tools 37.0.1。
- 全部安装在 `.android/`；下载缓存位于 `.model-downloads/`。没有安装完整 Android Studio 或 Java，也未修改全局 PATH、Windows 功能或系统启动项。
- 已由 `emulator -accel-check` 确认现有 WHPX 可用，实际启动日志确认加速正常。
- 主 AVD 名称：`VoxFix_K60_API35`。配置 1440×3200、密度 560、4 个虚拟 CPU 核、4GB RAM、16GB 虚拟数据分区。实际参数见 `android-emulator-profile.json`。
- 电脑可见物理内存约 13.6GiB，D 盘安装前可用约 150GiB。模拟器不照搬手机 16GB/512GB，因为这些设置会占用电脑资源，并不能复制手机芯片性能。
- 屏幕密度 560 是测试配置，不是从 K60 读取的实际值。真机连电脑后可以读取真实 `wm size`、`wm density` 再精确对齐；物理屏幕分辨率也不一定等于用户当前开启的渲染分辨率。

## 日常打开

双击项目根目录 **打开安卓试用.cmd**。它会：

1. 启动或复用本项目模拟器，保存浏览器和 AVD 数据。
2. 必要时启动本机 VoxFix 服务。
3. 用 adb reverse 将模拟器里的 127.0.0.1:18743 映射到电脑本机服务。
4. 打开模拟器 Chrome 中的试用页。首次浏览器初始化已选择不登录账号、不启用通知。

重复打开会先恢复 Chrome；已在试用页时不重新导航，保留未发送的试用输入。连续打开两次的标签数量保持 1，并用临时输入验证了文字保留，见 `android-launcher-validation.json`。为识别页面临时生成的可访问性 XML 会立即删除，不留作用户文字日志。

关闭模拟器窗口可结束日常试用；下次一键入口可以重新启动。模拟器未配置为开机自动运行。若 5554 端口正在运行其他模拟器，启动脚本会停止操作，不复用或修改无关虚拟机。

## 测试层次

| 层次 | 适合验证 | 验证不了的内容 |
|---|---|---|
| 电脑自动测试 | 拼音、数据处理、文本保护、失败恢复、快速回归 | Android 与手机系统行为 |
| 安卓模拟器 | Android 浏览器、触摸、候选滑动、不同屏幕布局、连接生命周期；原生 APK 接入后可测试权限、输入法与跨应用交互 | 骁龙真实性能、K60 麦克风、HyperOS 后台规则、发热耗电 |
| K60 真机 | ARM64 原生库、系统输入法、真实录音、性能、内存、后台、锁屏、发热耗电 | 一台设备不能代表全部厂商 |

一般开发者以 Android API、屏幕/密度、字体、处理器 ABI、权限与生命周期形成测试矩阵，常规回归放在模拟器和自动测试中，再选少量厂商真机做关键验证。当前目标是个人 K60，不需要一开始覆盖所有品牌；优先确保 Android 15 与 K60 关键路径，其他配置作为防止布局退步的补充。

## 本轮自动验收

`preview/android.test.mjs` 使用 Playwright 官方安卓接口连接专用模拟器并启动受控 Chrome，发送网页触摸事件，运行真实 Android 浏览器与音频接口。它不是桌面浏览器设置一个手机尺寸。计划覆盖：

- 1440×3200、密度 560：K60 屏幕比例。
- 1080×2400、密度 420：相同比例的较低渲染分辨率。
- 1440×3200、密度 700：更窄逻辑宽度，检查较大界面缩放。
- 屏幕按键输入 `wzdl`，候选“我知道了”，触摸选择。
- 网页触摸向左滑动候选，验证滚动并且不会误选。
- 官方模型 WAV 经 Android Web Audio / AudioWorklet 送到本机服务，验证真实流式出字；不会录制当前用户麦克风。
- 真实离线润色服务在安卓页面上的预览、替换与撤销。

切换显示参数会重建 Chrome，脚本为每种配置启动受控测试浏览器，避免旧标签页误判。测试结束后恢复主显示配置。结果和截图见 `android-emulator-validation.json`、`android-*.png`；只有结果文件记录通过的项目才算本轮已验收。测试应在本项目专用模拟器运行，不用于日常浏览器里未保存的内容。

### 本轮已通过的结果

- 三种显示配置全部通过：完整简拼 `wzdl` 选“我知道了”，候选滑动正常且不会误选，页面没有横向溢出。
- 10 秒官方 WAV 经安卓浏览器的真实采样链路到电脑识别服务，最终一次验收观察到 15 次流式更新。文件识别输出仍有英文误识别，不能宣称提高准确率。
- 含 10／15、公里、否定词和 Obsidian 的人工文本在真实电脑离线模型整理后，安卓页面预览、替换与撤销通过，没有页面脚本错误。
- 这些结果是安卓网页与电脑后端的测试，没有安装 VoxFix 原生 APK，也没有声称手机内部离线识别已经通过。
- 模拟器发现并复现了真实按键缺陷：部分 Android 点击事件 detail=0，但 pointerType=touch；旧代码误当作键盘激活，重复输入字母。现在按 pointerType 与 detail 共同区分物理点击，已验证各配置只输入一次；电脑鼠标、候选和键盘激活回归通过。独立 HTML 同步重新打包。
- 前期测试脚本对原生键盘、未完成拼音及标签页连接的处理不正确，已改用官方安卓接口和粘贴语义准备文本；这些脚本失败没有标记为应用通过。最终完整证据为 `android-emulator-validation.json`。

## 第八阶段的准确状态

本轮建立了安卓模拟器及安卓网页测试环境。VoxFix 当前仍没有原生 Android IME APK。模拟器 Chrome 使用的是电脑 Python 服务，语音和 Q4_K_M 都在电脑执行。因此本轮结果不能证明模型已在安卓设备内部离线运行，也不能证明原生输入法跨应用、ARM64 或 HyperOS 兼容。

下一步原生接入要复用现有界面和输入行为，并接入 Android InputMethodService、sherpa-onnx Android 运行库与 llama.cpp Android 运行库；模拟器使用 x86_64 构建，K60 使用 arm64-v8a 构建。原生 APK 的开发与手机验收是独立工作，不用一个 WebView 包装 APK 冒充完成。

K60 真机阶段可使用 USB 或无线调试，在电脑安装、查看日志和执行测试，减少拿起手机的次数；性能和真实麦克风仍需设备本身参与。

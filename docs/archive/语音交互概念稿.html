语音识别 · 呼出与取消动效概念稿v1 草图

目标：让语音从「啪一下弹出一块白板」变成「从手指下长出来的一团会呼吸的光」。文字减到 1 行，其余全部交给图形。

1先看现状：为什么觉得「卡」

下面是刚才在真机尺寸（393×312 @2x、原生 IME 分支）下截的现状图。三个状态的共同问题是：没有「过程」，只有「结果」。

  • 没有进场 / 退场面板靠 render() 整块替换，出现就是 0→1 的瞬变，没有生长、没有收敛。这是「卡」的第一来源。
  • 动效是「等长柱 × 同周期」58 个节点各自跑 0.8s alternate，只有 --delay 差 0.1s。节奏整齐 = 机械感；且每帧改 height 触发布局。
  • 取消靠换文字「上滑取消输入」→「松开手指，取消输入」，是文案在告诉人，不是图形在告诉人。且状态切换无过渡。

2三个概念方向

核心变化：把「一排柱状波形」换成一个会流动的球体。圆形天然带「活着」的感觉，也是 Siri / ChatGPT 语音界面共用的语汇。下面是三个方向的动态草图（是真动，不是静态图）。

C · 流云光球 推荐 · ChatGPT Live 风

四层蓝白流云叠成一团没有硬边的球，各自以不同周期缓慢形变，叠加起来就是持续流动的流体感。说话时整团随声幅呼吸胀缩。

  • 最沉浸，一眼看出「它在听」
  • 纯 transform / opacity + blur，全程合成层
  • 取消时整体转红、向内收束，语义统一
  • 与「圆形图标钮」形状语言同源

A · 呼吸光环

中心一颗实心光点，外面三层同心光环。静默时缓慢呼吸，说话时内环先响应、外环追赶，形成一圈圈溢出的涟漪。

  • 层次最清晰，轻量、好调参
  • 纯 transform/opacity，零布局
  • 偏几何、偏「仪器」，沉浸感弱于 C

B · 环形律动

中心圆点，32 根短柱呈放射状排布，长度随声音起伏，整体以 26s 缓慢自转。保留一点「讯飞波形」的血缘。

  • 最接近原版讯飞观感，改动最小
  • 环形 + 自转，比直排灵动
  • 节点多，需 transform 写长度
建议取 C 为主、把 A 的「不显示波形也看得出在听」补进来。C 的流体球与 ChatGPT Live 同源，最符合「丝滑沉浸」；形态上仍是圆，与现在键盘已经收敛的「圆形图标钮 / 胶囊 / 圆角卡片」三形状语言同源。取消时不给它换组件，而是让同一团云整体转红并向内收束，动作连贯不断裂。代价是 blur 有一层额外开销，需在中低端机上实测帧率。

3完整状态机（可交互）

按住下面键盘区的话筒（空格键）：会看到光球从按键处「生长」出来；按住不放向上拖，光球跟着手指走、变红、收成一圈红环；此时松手即取消（整体向内炸掉）。不上滑直接松手，则进入识别中。

倾听中
按住不放 · 向上拖试取消
  • 1召唤（0 → 300ms）
    按键先响应：自身 scale(.94) + 一圈涟漪从按键扩散。80ms 后语音面板从按键上沿「张开」—— transform-origin:50% 100%，scaleY(.18)→1 配合 blur(6px)→0，光球再过冲 (1.06) 回弹到 1。
  • 2倾听（循环）
    脚本只往根节点写一个 --mic 变量（0~1），整团云的胀缩由 calc() 派生。云本身由 4 层不同周期的 border-radius + translate/scale 形变叠加而成（11s / 8.5s / 13s / 6.5s），互不同步才像流体。声幅包络做在 JS 侧：60ms attack、320ms release —— 快起慢落，才是「跟得上话」。
  • 3上滑取消（跟手）
    translateY 1:1 跟手（阻尼 0.55），整团云向上被「推」走，同时缩小到 .82、透明度降到 .42，色相沿 accent→danger 插值，背景卡片渐变到极浅红。中心浮出一颗红色靶心，外面一圈弧线随位移从「一小段」合拢成闭环——闭环 = 已选中取消。越过 56px 阈值时给一次轻微触感。
  • 4松手 → 取消
    整块从光球中心向内「炸」掉：190ms scaleY(.14) scaleX(.86) + 淡出 + 轻微模糊，原点回到话筒键，方向与召唤相反。红环闪一下收尾。
  • 5松手 → 识别中
    云整团收掉（缩到 .5 并淡出），只留一颗小核心 + 一圈 .9s 匀速旋转的进度弧。文案用一个 220ms 的「旧字上移淡出 / 新字下方上移淡入」替换。
  • 6结果落地
    进度弧向下塌陷成候选条（morph），或整体淡出让文字逐字打出。收尾同样从中心向内收成话筒键，260ms。

6落地要点

概念稿要能落到这台手机上，几个硬约束先钉住。

性能（这是「卡」的真正来源）：现在的 .waveform 是 58 个 DOM × 每帧改 height，会持续触发 style/layout。新方案把它换成一团光云（1 组 4 层 blob + 1 halo + 1 core），并且只动 transform / opacity，加 will-change 提到合成层。声幅不改任何几何属性，只写一个 --mic CSS 变量，其余全由 calc() 派生。
那层 blur 怎么办：光云的柔边靠 filter:blur(15px)，它比纯 transform 贵。两条降本路子：① 每层 blur 只作用于静态尺寸的图层，形变走 transform（blur 结果可缓存，不逐帧重算）；② 若真机掉帧，把 4 层降成 2 层 + 一张预渲染的柔和底图。要不要保留 4 层，以真机实测为准。
真机尺寸：原生 IME 视口 393 × 351 @2x，语音面占据键盘区主体（约 248px 高）。
· 光云整体 190px（=380 物理像素，几乎占满语音面），核心 46px，外晕 236px
· 「上滑取消」的微提示（一枚淡色上箭头）贴在语音面底部、话筒键正上方，而不是挤在标题旁
· 阈值：上滑 56px 进入取消区
· 文案字号沿用现有 12px 一档，不再新增 10px
要接的真机信号：现在已经有 voxfixVoiceLevel(level) 这个桥（app.mjs 里写 --mic-level）。新方案直接复用它，改成写 --mic；attack/release 用 JS 侧做包络（快起慢落），而不是交给 CSS 动画——这是「跟得上话」的关键。
不改的东西：语音触发方式（长按空格 / 长语音按钮）、手势判定阈值、取消语义、识别引擎链路，全部不动。只换「呈现层」。

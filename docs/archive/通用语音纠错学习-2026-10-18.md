# 通用语音纠错学习（2026-10-18）

本轮取代此前“中文等长同音词、英文必须先手动添加”的限制。不为张玥、Excel或Word写特例；只保存局部词条与纠正证据，不保存日常录音，不训练模型权重。早期安装、测试及限制见[历史实现记录](个人语音词典与纠正学习-实现-2026-10-18.md)，最新行为以本页为准。

## 正常使用

在App正文中听写后，删除错词，打拼音并点正确候选，便是一次学习；中英文无需事先添加。组合中的拼音与未确认的英文字母不算纠正。候选确认即安排读取，发送、收键盘或开始下一段语音前再处理一次待完成编辑；用户不必逐词联系开发者。

第一次可靠纠正提供较弱词语偏好；独立重复纠正增强权重，并允许在匹配上下文中恢复正确词。近音通常需要2次证据，读音差异较大的中文确认替换需要3次。相同目标、相同上下文下已确认的不同错法共享证据；中文错法可按读音匹配变体，例如沃/卧，而不是每个字都要单独登记。中文词达到3次证据、至少2种已确认上下文且有同音证据后，才允许按分词边界迁移到新上下文。手动词仍从下一次语音立即优先。

这里提高的是个人词条和文本纠正的优先级。新读音、噪声或没有证据的新错法仍可能识别错，不承诺单次改字后所有发音均正确。

## 通用实现与边界

- `VoiceEditExtractor.kt`：标准Levenshtein对齐，复用Android ICU词边界，提取局部替换；支持不同长度、同一句多个改词、中文改英文、英文大小写、带数字或连字符的术语，以及错误片段末尾多出的句号。不依赖具体词名或预先登记。
- `VoiceCorrectionTracker.kt`：只观察最后一次语音插入，最多512字、2分钟、两侧各12字锚点，临时正文仅驻留内存；同一次插入内相同纠正不重复计数。删除后等待候选完成，每次最多8个改词，每词最多32字和各4字上下文。相邻改词同时保留原识别/正确文本的左右锚点组合，至多32条规则；同批同词仅计1次，规则共享证据不超过词条计数，避免上下文变体虚增权重。跨字段、越界、无法确认锚点时跳过。
- `VoiceEditorSnapshot.kt`：优先读取`getSurroundingText`，不支持时用有绝对偏移的完整`getExtractedText`回退。长正文只截取光标附近窗口；拒绝未知偏移和补丁式更新，不猜坐标。
- 原生服务：拼音候选、通用候选、英文补全、确认边界和宿主文本/选区回调接入统一学习；同编辑框restart保留观察，密码/禁止个性化字段、键盘本地编辑器和剪贴板搜索不学。纠正保存与下一段识别复用同一语音工作队列，确保先保存再读取；不让语音等待拼音引擎初始化。销毁时先排空相关工作再关闭词库。
- `PersonalLexicon.kt`：同一schema2数据库，批量纠正原子写入，词条合并而不重置；反向改字仅撤销相同上下文的反向证据。多目标冲突取独占较强证据，同分跳过。文本始终匹配原识别位置，已确认且无歧义的相邻纠正可支持上下文，最多8轮收敛；不从改写后的词中再找新替换，避免串联改写。
- 数字变化、否定含义变化、纯删除、大范围重写及不可靠修改不当作词语学习。未确认中文只接收近似读音；明确候选确认的非近音局部替换可留证，但需更多重复证据才按上下文生效。局部语义改写与纯听写纠正无法仅凭文本完美区分，因此不将一次证据直接用于全局替换。
- schema2和完整备份version2继续兼容旧文件；安卓与网页校验同步扩展，通用TSV仍仅承载拼音词。手动词最多96个活动热词、纠正最多256条活动规则；长期数据库不按这个上限删词。

## 复用依据

识别仍用固定版本sherpa-onnx 1.13.8的[官方热词机制](https://k2-fsa.github.io/sherpa/onnx/hotwords/index.html)，没有重写识别器。宿主取文复用[Android InputConnection](https://developer.android.com/reference/android/view/inputmethod/InputConnection)；平台可能不提供可靠正文，此时应跳过而非误学。纠正监控思路参考[OpenWhispr一手修复记录](https://github.com/OpenWhispr/openwhispr/pull/665)，未移植其Windows UI Automation代码。本轮无新增第三方库或模型。

K60最终隔离平台流程通过19组、38次：使用实际`BaseInputConnection`、`Editable`和Android ICU执行选择、删除、拼音组合、正确候选提交；所有词未手动登记，学习两次后均为自动词、计数恰为2。第二次使用1800余字正文和旧读取接口回退，检查绝对偏移；重开SQLite、完整备份合并、失败批量不写入和普通词负例通过。这是平台编辑流程测试，不冒充真实聊天App里的人手选词。

K60英文/混合固定音频5条：从零自动词条开始，经纠正保存、关闭重开后，3条目标完全匹配、2条普通中文负例不变；包括“艾克塞尔→Excel”与中文首字“货用→我用”。测试已明确断言不存在手动词，未向最终文本直接注入整句正确答案；仍只代表这些合成音频。

K60中文固定音频10条：零自动词条开始，两个独立纠正周期后，5条专名均完全匹配，5条普通负例不变。除姓名外，也覆盖近音的卷解/玄界→玄戒与多音字欧博→欧泊；实现中无这些词的专门替换。该组及英文组测试完成后又收敛了保存队列与冲突裁决；单目标样本走相同分支，最终包重验平台编辑及Word音频。

Word固定音频7条发现并修复通用相邻错误问题：只记正确上下文，会让“沃→Word”受同时错误的“文的→文档”阻挡。现保留原始与确认后的上下文组合，两个中文近音样本从“我的沃文的”恢复“我的Word文档”，四条普通负例（含卧室/沃土）不变。中英拼接样本仍可能漏“的”，静态三次喂同一基线未解决，不能将仅含Word算作整句通过；因此新增每轮重新解码实际输出的连续学习回归，不复用过时错误训练。

连续回归又复现了反馈链路问题：用户看到的Word已被修正，后续“文的→文档”便在Word上下文中积累，但原始解码仍可能是沃。修复为让可靠相邻纠正支持上下文，并增加有歧义邻词不可作支持的回归。K60重新跑三轮真实解码，每轮只学习本轮实际输出；最终三条Word样本均完整输出“我的Word文档”，四条普通负例不变，返回`VOICE_CYCLE_PASS rounds=3 targets=3/3 negative=4`。没有手动词条，也没有把整句正确答案直接作为识别结果返回；每轮trace保留在本机忽略目录`.android/voice-personal-20261018/word-fixtures/cycle.json`，此前失败trace单独保留。

补齐单说一个词却识别成一个汉字时的观察入口（原识别允许1字，目标仍须是合法词语），平台回归包含该情形。真实自然发音、跨App宿主行为和长期误学习率没有因此视为通过。

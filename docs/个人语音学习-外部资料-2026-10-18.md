# 个人语音学习：外部一手资料

核查日期：2026-10-18。本文只记录外部官方文档、仓库与源码证据；不代表已完成 VoxFix 接入或 K60 验收。用户已确认参考产品是 **Typeless**。

## Typeless 到底学了什么

- 官方《History & Dictionary》明确说明：听写后纠正单词时，会识别偏好拼写并加入 **Auto-added**；可手动添加词或短语、CSV 批量导入、搜索、修改和删除。这与“说完改几个字，下次偏向自己常用词”的需求直接对应。[官方使用说明](https://www.typeless.com/help/quickstart/history-and-dictionary)
- 官方另有 **Personalization**，描述的是语气、表达和写作习惯的适配；官方说它观察抽象风格模式，不保存实际消息内容。这与词典自动加词是两种产品能力，不应混为“每天训练声学模型”。公开说明没有披露自动加词阈值、上下文窗口、中文歧义处理或是否对用户做模型权重微调。[官方个性化说明](https://www.typeless.com/help/quickstart/personalization)
- 本次没有找到 Typeless 官方发布的应用源代码或允许复用其实现的开源许可证；只能说**未核实到官方开源**，不能据此证明网上绝无仿制项目。其功能说明也不是实测准确率证明。

## 真正相关的开源实现

| 项目 | 已核实的机制 | 对中文和安卓的限制 | 许可证 |
| --- | --- | --- | --- |
| OpenWhispr | 官方 CHANGELOG 的 1.5.4 已加入粘贴后纠正监控、自动更新词典和撤销；后续明确修复 CJK 等非拉丁文字学习。已合并 PR #665 解释 Windows 用 UI Automation 读取编辑框，获得修改文本 | 桌面监控代码不能直接当安卓 IME 使用；字段不提供可访问文本时会跳过。未实测其中文词边界、误学习率及手机表现 | MIT；模型等独立资源另查 |
| Handy | 自定义词参与转写适配；源码另有转写后 Levenshtein + Soundex + 最多三词片段的匹配 | 当前源码明确把 fuzzy fallback 限制为 ASCII；其按空格切分和 Soundex 不适合中文。不能直接移植为中文个人成长学习；此次未核实到自动观察外部纠正并学习的等价实现 | MIT；品牌资源有独立限制 |
| sherpa-onnx | transducer 模型可在 modified_beam_search 中使用 hotwords/contextual biasing，支持全局和逐词分值；另有 SenseVoice + HomophoneReplacer 官方 Java 示例 | 热词文档限定 transducer + modified_beam_search，不能据此宣称普通 SenseVoice greedy 解码支持同一热词接口。HomophoneReplacer 是基于发音词典及 FST 的文本后处理，不是自己发现纠正或训练模型 | Apache-2.0；模型等独立资源另查 |

Handy 一手证据：[仓库](https://github.com/cjpais/Handy)、[text.rs 当前源码](https://github.com/cjpais/Handy/blob/main/src-tauri/src/audio_toolkit/text.rs)、[MIT LICENSE](https://github.com/cjpais/Handy/blob/main/LICENSE)。源码中的 build_custom_word_match_keys 明确注释 CJK 不适用于此 fallback，is_supported_fuzzy_key 只接受 ASCII 字母数字。

sherpa-onnx 一手证据：[官方热词文档](https://k2-fsa.github.io/sherpa/onnx/hotwords/index.html)、[SenseVoice + HomophoneReplacer Java 示例](https://github.com/k2-fsa/sherpa-onnx/blob/master/java-api-examples/NonStreamingDecodeFileSenseVoiceWithHr.java)、[HomophoneReplacer 实现](https://github.com/k2-fsa/sherpa-onnx/blob/master/sherpa-onnx/csrc/homophone-replacer.cc)、[Apache-2.0 LICENSE](https://github.com/k2-fsa/sherpa-onnx/blob/master/LICENSE)。当前实现读取 lexicon 与 rule_fsts，将词转换为发音后交给规则 FST；多个 rule_fsts 当前仅支持一个，不能照配置字段误判成多规则文件已经支持。

## SenseVoice 微调与热词的边界

SenseVoice 上游提供 finetune.sh 和带音频、文字的训练数据准备流程，说明**离线监督微调在技术上可做**。这不等于在安卓手机上每纠正一次即可训练，也不证明只保存文本纠正就能改善声学模型。上游 README 所列第三方 SenseVoice Hotword / streaming-sensevoice 是另外的增强实现，不能自动归为现有 sherpa-onnx SenseVoice 权重和接口的能力。[SenseVoice 官方仓库](https://github.com/QwenAudio/SenseVoice)

许可也需要分层：当前 SenseVoice 仓库说明代码为 MIT，模型权重按各模型卡独立条款；原始权重、转换权重和微调产物不能仅因代码 MIT 就一概判定为 MIT。[SenseVoice License 章节](https://github.com/QwenAudio/SenseVoice#license)

## 从资料得到的可行方向（设计推断）

1. 将“成长”先落实成**个人词条 + 纠正事件 + 受控加权**，无需保存日常录音或训练模型权重。词条可以共享给拼音和语音，使用次数、语音误识别映射、拼音候选选择证据应各自记录。
2. 语音采用双入口：支持的流式 transducer 在解码时热词加权；SenseVoice 最终文本通过受控纠正层处理，避免二遍覆盖已学偏好。是否能直接使用 HomophoneReplacer 取决于项目所用库版本与绑定，必须单独查验。
3. 纠正监控只在能确认属于本次语音输入的范围内学习。大幅改写、换意思、删除整段、仅改标点不应自动形成词语替换；多义或同音常用词需要上下文和重复证据。不能把一次“我现在要上学 → 我现在要上班”的主动改意，永久学成“上学永远替换上班”。
4. 真正声学微调留到热词和纠正记忆仍无法解决、且用户另行授权采集标注录音后再评估；当前不建议作为第一阶段。

# 个人输入法拼音引擎技术调研

日期：2026-10-12。范围：只读检查现有拼音逻辑、检索上游一手资料；未改应用源码、未构建或安装。

## 推荐

适合本项目的长期组合是：本地拼音解码与个人词库常驻，语音另行按需运行。拼音部分优先评估原生 librime，先使用基础词库、用户词频与组词学习，再根据真实长句错误决定是否加入小型语法模型。用户所需的“常打的词越来越靠前”无需生成式大模型，也无需把日常文字发往服务器。

保留已有 26 键布局、候选横滑、常用语与 Android 输入连接；替换拼音解码部分即可。暂不为了迁移引擎同时重写键盘界面。原生引擎仍配 WebView 时不会自动消除 WebView 渲染进程；降低整机占用必须把两部分单独测量。

## 四种需求应分别实现

| 用户需求 | 合适的技术 | 与大模型的关系 |
|---|---|---|
| 已选过的同音词靠前 | 本地用户词典、频次与近期使用权重 | 不需要大模型 |
| 从逐字/分词选择中记住新词 | 拼音编码与确认词组写入用户词典 | 不需要训练神经网络 |
| 长串拼音自动组成更合理的句子 | 音节图、词图、句子解码，可加统计搭配模型 | 与生成式 LLM 不同 |
| 输入一个词后推荐下一个词 | 独立的下一词预测组件与预测数据库 | 不等同于词频学习，也不等同于整句解码 |

## 当前实现的边界

源码检查：`preview/core.mjs:101-117` 中用户记忆最多 2,000 条；累计选择 2 次才提前；`rankLearned()` 仅重排本次已有候选，不向解码词库注入新词。`preview/app.mjs:505` 写入 `voxfix-learning-v1` 本地存储，并对密码等私密字段作限制。因此已经有“常选词提前”，但不等同于成熟输入引擎的新词学习。

`preview/pinyin.mjs` 将 JSON 词库建立为多个 JS 索引；整句兜底按词频与长度选路径，没有语义模型。联想查找以已输入文字作为词条前缀、返回后缀，尚非根据个人上下文统计出的下一词概率。自定义词组的读音从单字映射推导，多音字读音需要更可靠的编码/编辑路径。这些是后续升级质量的明确入口，不能只换更大的词表解决。

## 上游证据

- librime 为跨平台 C++ 核心，官方列出 Trime 等 Android 前端；运行依赖含 LevelDB、marisa、OpenCC、yaml-cpp。集成成本应计算 JNI、词典部署和数据迁移，不能假设引入一个库即可完成。[librime 官方仓库](https://github.com/rime/librime)
- Rime 的提交事件进入 Memory，已选词组按编码组合后交给用户词典；ScriptTranslator 支持组合词组的记忆和句子候选生成。[Memory 实现](https://github.com/rime/librime/blob/master/src/rime/gear/memory.cc)、[ScriptTranslator 实现](https://github.com/rime/librime/blob/master/src/rime/gear/script_translator.cc)
- 用户词典记录提交次数与时间刻度，更新动态权重并按权重查询；不是每次选择就一定无条件排第一，实际效果受方案和系统词频影响。[用户词典实现](https://github.com/rime/librime/blob/master/src/rime/dict/user_dictionary.cc)
- librime-octagram 使用 `.gram` 搭配数据库，为前文与候选的组合提供分数；数据库以只读映射、双数组前缀树检索。映射避免把文件展开成大量 JS 对象，但被访问的页仍会占实际内存，不能说“模型无需内存”。[搭配评分实现](https://github.com/lotem/librime-octagram/blob/master/src/octagram.cc)、[数据库实现](https://github.com/lotem/librime-octagram/blob/master/src/gram_db.cc)
- librime-predict 是独立下一词插件，使用预测数据库与 schema 配置；可先不引入，待基本拼音与个人词库验证后再决定。[官方插件说明](https://github.com/rime/librime-predict)
- Trime 的 Kotlin Rime 包装通过 `rime_jni` 提供按键处理、提交、上下文、候选选择与删除等接口，证明 Android 集成有成熟参考，但不能证明 VoxFix/K60 的内存与速度。[Trime Rime.kt](https://github.com/osfans/trime/blob/develop/app/src/main/java/com/osfans/trime/core/Rime.kt)
- 万象 RIME-LMDG 提供词库与语法数据，作者将数据搭配和解码权重视为配套参数。作者自己的评测不能直接外推至本项目或 K60，最大词表/模型不是本项目的默认选择。[RIME-LMDG 上游说明](https://github.com/amzxyz/RIME-LMDG)

## 最小实施顺序

1. 先把现有个人词库与选择记忆可迁移地导出，保留密码字段禁学；仅学习用户明确确认的词组，不默认将语音误识别或自动润色内容写入词库。
2. 在现有 Android 输入法接入单一 librime 拼音方案，替换 JS 候选解码；现有 UI、手势与输入连接保留。先验收全拼、简拼、中英混输、拆选、多音词、连续组词与重启后学习保留。
3. 同 K60、同文本测试首候选命中、平均选词次数、按键至候选延迟和全部相关进程内存。达标后才决定是否移除旧 JS 词库；保留可回退数据。
4. 长句仍明显出错再试小型 octagram 数据，与不加载模型基线比较；不先加载整套最大万象数据。下一词预测单独比较，避免组件堆叠。

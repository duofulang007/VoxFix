# 候选区：官方小米版对照

普通26键候选栏已采用[2026-10-17自然宽度20px与悬浮入口](候选自适应与剪贴板悬浮-2026-10-17.md)；本页继续作为展开候选页、词/字切换与官方取证依据。

## 2026-10-13 续做结果

拼音错位补正：用户真机 `ning` 展开后，`bing/jing/ming/ning` 因固定 25px 左 padding 向右偏移，`ming` 被分隔线裁切。回读真实元素与几何回归复现（中心偏差 8.37–13.73px，`ming` 超出按钮）。仅将 `.pinyin-item` 改为 `text-align:center;padding:0`，按原版各拼音共同中心对齐；保留列宽、字号及竖向均分。新增 `ning`、`niang` 实际候选按钮文字范围检查。下方「左列左距25px」是此前误判，已被此修正替代。

后续用户提供原版 `jv'h` 展开面板并指出白卡片/右侧灰按钮「贴得太紧」。同一 K60 真实屏幕复核：原版白卡片白色区域止于物理 x≈1184，灰按钮填色从 x≈1203 起，约 5px CSS 留白；当前安装版白卡片右缘与按钮左缘同为 338.93px，实际间隔 0。原版灰按钮约 62–63px 宽，当前为 67.5px。最小修正为 `.panel-actions` 加左 padding 5px，保留其 67.5px 整列占位，按钮宽变 62.5px；不挤压候选网格。下方旧测量中的「紧邻无间隙」结论不成立。

以下原记录含按 APK ini 推导的旧尺寸；最新依据是 [实测交接](候选区官方对照-实测交接.md) 的 o2/o3/o5 截图，并作两项修正：

- o2 所谓「↑ 控件」是候选「你」被裁掉的左半边，右侧只保留一个 `>` 展开钮。
- 当前键盘高 351、footer 49；面板上下 padding 改为 2/15，保持卡片约 285px 高。交接建议的 2/1 会把卡片撑成 299px，与截图不符。右边不加 padding，按钮贴齐原键盘边距。

本轮候选栏/网格都用 22px，左列用 16px、左 padding 25px，首候选左 padding 17px；左列宽 62.9px、右列宽 67.5px、按钮 gap 6.4px，去掉网格竖线。候选文字按实际宽度占 1–4 列；只有超过整行宽的极长内容才换行，不省略文字。

「词/字」已实现：词模式保留引擎原列表，字模式只显示其中真实的中文单字候选，选择继续走原生 Rime 拆选/学习/提交接口。没有单字或处于联想列表时禁用切换。翻页按钮按首尾禁用，操作键复用现有按下/松手反馈。

相近拼音单音节 `ni` 保持 `bi/ji/mi/ni`；多音节 `nihao` 为 `nin/niu/bi/ji`。其它音节仍是有限的尾音/邻键近似，不宣称复刻官方易混表。替换首音节不会吞掉 `xi'an` 这类明确分隔符。

网页候选专项、fixed-layout、key-press、native-ime 及 37 项 ime-regressions 通过。APK 构建、安装与用户实际操作结果分别见 [USB真机验收](USB真机验收.md) 本轮记录。

## 四、左列内容是什么

真机实测（输入 → 左列）：

| 输入 | 左列 |
|---|---|
| `ni` | bi / ji / mi / ni |
| `hao` | bao / gao / hai / hao |
| `women` | ao / wo / a / e |

规律：取**首个音节**，把声母换成 QWERTY 键盘**相邻键**，保留韵母，筛出合法音节，末尾补自身（`ni` 的 n 邻键 = b/j/m ⇒ bi/ji/mi；`hao` 的 h 邻键含 g/b ⇒ gao/bao）。点击左列即把组合串的首音节替换掉。

VoxFix 按此规则实现 `nearbyPinyin()`（`preview/app.mjs`），音节判定由 `pinyin.mjs` 的 `isSyllable` 提供。真机验证 `ni` → 左列 `bi/ji/mi/ni`，与官方一致。

> 右列第一个键：官方是「词/字」（候选以词/字为主切换）。VoxFix 引擎没有该能力，该位置保留为**分词**（插入 `'` 分隔符），位置与尺寸与官方一致，标签用 VoxFix 的实际功能名。

## 2. 更新清单与源

```json
{
  "versionCode": 5, "versionName": "0.4.1", "date": "2026-11-20",
  "changelog": "简短文案", "apkSizeBytes": 456608620,
  "apkSha256": "64 位小写 hex",
  "apkUrls": ["https://github.com/<owner>/<repo>/releases/download/<tag>/<APK名>", "<实际可控镜像>"]
}
```

- **主清单源**：`https://github.com/<owner>/<repo>/releases/latest/download/manifest.json`（`UpdateChecker.RELEASE_MANIFEST`，owner/repo 确定后填入；不走 GitHub API，避免限流与 assets 二次请求）。
- `manifestUrls` 与 `apkUrls` 都是按序完整 URL 列表；每源独立超时（清单 6s/10s），失败静默换下一源。
- **镜像**：发布前必须配置并实测一个实际可控镜像（prefs `voxfix-update.manifestUrls` 可覆盖内置列表）；「支持镜像字段」不等于「国内可更新」——发布 checklist 里是阻塞项。
- 清单 URL 校验：正式源强制 https；debug 构建（`allowInsecureHttp=true`）放行局域网 http 联调源（`UpdateCore.isDownloadUrl` 与 `DownloadEngine` 门禁一致）。
- **联调源优先级（2026-11-14 真机实证后的最终设计）**：debug 构建源列表 = RELEASE_MANIFEST（GitHub）→ loopback（`adb reverse`，走 USB）→ **companion 推送过的 PC 局域网地址**（`AdbWireless.pcAddresses`，走 Wi-Fi，无 USB 依赖）。GitHub 直连在国内被墙是真机实证的常态（ping 通但 443 被掐断，报 `unexpected end of stream`）——多源串行回退后落到局域网源即成功。
- **三个联调坑（都踩过）**：
  1. **Windows 防火墙按程序路径放行**：`.venv/Scripts/python.exe` 不在放行规则里，入站被拦（PC 服务日志零请求即此因）；改用已放行路径的解释器（如 workbuddy runtime python）跑 `http.server` 即可，零权限改动。
  2. **cleartext 必须放行局域网 IP**：`networkSecurityConfig` 的 domain-config 不支持网段且 PC IP 动态——debug 构建直接 `<base-config cleartextTrafficPermitted="true" />` 全放行（release 不受影响，正式源仍由调用方强制 https）。
  3. `adb reverse` 规则在 PC 服务被杀后仍残留在手机侧，连接快速失败回退下一源，无碍。
- 正式源强制 HTTPS；自动检查失败静默，手动「检查更新」必须显示「已是最新/发现新版/检查失败及原因」。

## 3. 下载与安装（复用 DownloadEngine）

- `DownloadEngine.kt`：从 `TranslateDownloader` 抽取的传输核心——多源回退 + Range/206 续传 + 416 重下 + 重定向 + 大小/SHA-256 校验 + 取消（`disconnectCurrent` 打断阻塞读）+ `.part` 断点续传。`TranslateDownloader` 公共 API 不变，内部委托（461.9MB 翻译模型与更新 APK 共用同一套校验）。
- 更新 APK：用户点击横幅才下载（不自动）；下载前空间检查（apkSizeBytes + 128MB 余量）；完成即 SHA-256 强制校验，不符删 `.part` 且**绝不调安装器**。
- 状态机：HIDDEN → AVAILABLE → DOWNLOADING（进度 + 取消）→ READY；FAILED 可重试。横幅只在首页与关于页；「忽略这个版本」写 `voxfix-update.dismissedVersionCode`，About 手动检查不受节流（24h 自动检查节流）。
- 安装：`UpdateApkProvider`（authorities `${applicationId}.updateapk`，openFile/query/getType，文件名白名单防穿越）+ 只读 URI grant；`canRequestPackageInstalls()` false → 跳本 App 的「安装未知应用」页，返回后横幅仍在 READY。
- 权限：Manifest 新增 `REQUEST_INSTALL_PACKAGES`（普通权限 + appops）。
- 版本比较只比 versionCode 整数（`UpdateCore.isNewer`），versionName 仅展示。

## 4. 测试与验证

- **JVM 新增**（全量 521 项 0 失败）：
  - `ImeSwitcherLogicTest`：归一化/合并（保留讯飞条目原样）/移除；
  - `UpdateCoreTest`：清单解析（坏 JSON/缺字段/非法 sha/非 https）、versionCode 比较、sha 格式门禁；
  - `DownloadEngineTest`：本机回环 socket 手写 HTTP——多源回退、Range 续传（206 校验）、SHA 不符删 `.part`、loopback 门禁、完整 `.part` 跳网络直接校验；
  - `ModuleStructureTest` 见精简文档。
  - 注意：`com.sun.net.httpserver` 不在 Android 单测类路径；`java.time`/`java.util` 在本机 Kotlin DSL 脚本编译不可解析（AGP 8.7.3 实测）——APK 命名改用 git 命令取日期 + Copy 任务（零 AGP impl API）。
- **真机链路验证（0.4.0-4 装机，模拟源 versionCode=5）**：
  - 检查更新 → toast「正在检查更新…」→「发现新版本 0.5.0-test，回首页点横幅即可更新」；
  - 首页横幅：版本/约 435MB·建议 Wi-Fi/changelog/忽略行全齐；
  - 下载：进度横幅（24% · 106MB）+ 取消入口；454MB 经 USB reverse 下载完成；
  - **SHA-256 校验通过** → 「0.5.0-test 已就绪 · 校验通过」READY；
  - 点「安装更新」→ 正确跳 HyperOS「安装未知应用」授权页（开关当前关，属预期）。
- **诚实边界**：模拟源 versionCode=5、安装包实为 0.4.0-4——验证到 READY + 授权跳转，**不宣称真实闭环**；真实闭环 = 发布首个 v5+ 构建后，装 v4 的设备走 检查→下载→安装→v5 生效→横幅消失 全程（发版 checklist 见下）。

## 5. APK 命名与发版 checklist

- 输出：`android/app/build/outputs/apk/named/VoxFix-<versionName>-<versionCode>-<yyyyMMdd>-<git短sha7>.apk`（本次 `VoxFix-0.4.0-4-20261114-873f7a4.apk`，454MB）；`assembleDebug` 自动 finalize `renameDebugApk`（Copy 任务，源 app-debug.apk 保留）。
- 发版步骤：
  1. `android/app/build.gradle.kts` 顶部 `appVersionName/appVersionCode` 递增（单一来源，defaultConfig 与命名共用）；
  2. `AboutActivity.changelog` 补一行（首行最新）；
  3. 构建 → 记录 named/ APK 的 SHA-256；
  4. GitHub Release 上传 APK + manifest.json（apkUrls[0] = GitHub asset 直链，apkUrls[1] = 实测镜像直链）；
  5. 镜像同步并**用未挂代理的网络实测** manifest 与 APK 均可拉取；
  6. 装上一版本的设备走一遍真实更新闭环。

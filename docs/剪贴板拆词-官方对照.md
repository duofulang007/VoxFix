## 一句话结论

官方「拆词」是**剪贴板条目长按菜单里的第二层页面**：把一条剪贴板文本切成**词块**，
点一个词块就把该词**以 composing（带下划线）追加进输入框**，再点一次撤回；
面板离开即整段回滚，只有宿主回车/继续输入才落定。面板可纵滚，词块自然宽度流式换行。

## 入口

- 剪贴板面板里**长按任意一条** → 弹出白色浮层菜单，三项：**拆词 / 添加到常用语 / 删除**。
- 菜单紧贴被长按的行（不是固定位置），行高 50dp，文字纯黑 #000，约 16sp。
- 面板本身有两个入口：工具栏剪刀图标 → 「剪贴板（N/300）」列表页（标题 + 齿轮设置 + 返回）；
  键盘底部右下的双卡图标 → 「⌄ / 剪贴板|常用语 / 🗑」粘贴面板。两处都能长按出同一菜单。

## 词块（chip）几何与配色

| 项 | 实测 | 换算 |
|---|---|---|
| 高度 | 107 px | 30.6 dp |
| 最小宽度 | 225 px | 64.3 dp |
| 宽度公式 | `max(225, 文字宽度 + 114)` | `max(64.3, 文字 + 32.6)` dp |
| 圆角 | ≈ 41.5 px | ≈ 11.9 dp |
| 文字左右内边距 | 57 px | 16.3 dp |
| 块间距（横 / 纵） | 38–39 px | 11 dp |
| 行距（顶到顶） | 146 px | 41.7 dp |
| 文字 | 48 px | ≈ 13.7 dp ≈ 14 sp |
| 网格内容左内边距 | 53 px（首块左边 72 px 距面板） | 15.1 dp（距面板 20.6 dp） |
| 首行距卡片顶 | 62 px | 17.7 dp |

- **未选中**：边框 #60646B（2 物理 px ≈ 0.57 dp）+ 文字 #60646B，**无底色**。
- **选中**：边框 #3482FF + 文字 #3482FF，**无底色**（不是浅蓝填充）。
- 面板底 #EDEFF2，卡片纯白 #FFFFFF，标题/返回/全选/右侧图标均为 #60646B。

**宽度是自然宽度 + 流式换行**，不是固定 5 列网格：中文 1–2 字词的"文字 + 114"都小于 225，
所以看起来像等宽格子；换成 URL 立刻暴露真实规则 ——
`https://`(284) `s.`(225) `click.`(225) `Taobao.com`(405) 换行到 `/`(225) `jWXJyci`(298)。

## 卡片底行

- **全选**：圆直径 78 px（22.3 dp），圆心距卡片左边约 103 px；未选中底色 #F0F0F0，
  选中为 #3482FF 实心 + 白勾。「全选」文字 14 sp、#60646B，紧随圆右侧。
- 全选圆是**派生状态**：单独点选一个词块不会勾上它；点满最后一个词块才自动变勾。
- 右侧一枚 58×58 px（16.6 dp）图标（色 #60646B），实测**等同返回剪贴板列表**，
  无选中时点它无反应，有选中时会**放弃**已上屏内容。

## 交互行为（全部真机复现）

1. **点词块 = 把该词追加到输入框光标处**，以 composing 呈现（正文里能看到**下划线**），
   同时该词块变蓝（选中态）。
2. **再点同一个词块 = 取消**，该词从输入框中消失，词块回到灰色。
3. **全选 = 逐词全量追加**（等价于把整条文本上屏），圆变实心蓝勾。
4. **词块区可纵向拖动滚动**（长文本第 5 行开始被截断，上滑后看到后续词）。
5. **离开面板（↶ 返回 / 卡片右侧图标）= 整段回滚**，输入框恢复成进入拆词前的样子。
   composing 未提交，所以"先试着点几个词"不会污染正文。
6. **提交**：与普通候选一样由宿主回车/后续输入落定（官方靠 composing 语义，不是面板里再放"完成"）。
7. 面板打开期间宿主输入框仍可见（`adjustResize` 上移），上屏效果即时可见。

## 中文分词粒度（实测片段）

> 将 / 被 / 注销 / ， / 与 / 之 / 关联 / 的 / 相关 / 资产 / 将 / 被 / 清空 …

- 词典式切分（不是逐字）：能出「尊敬 / 用户 / 您好 / 中国 / 移动 / 服务 / 感谢 / 选择 / 号码 /
  邮箱 / 账号 / 注销 / 关联 / 资产 / 清空」。

## 复刻方案（含用户要的"编辑后自动拆词"）

复刻范围（第一批，1:1）：

1. **入口**：在 `preview/app.mjs` 现有长按菜单 `clipContextMenu()` 里**新增一行「拆词」**（原有项保留，
   不动用户习惯），点它进入 `state.page='split'` 新页面，记录来源条目与进入前正文快照。
2. **分词引擎**（新增，纯前端、离线）：用 APK 已打包的词库（`pinyin-lite.json` 26,501 词条 +
   `pinyin-data.json` 全量 + `characters`）做**最大概率（unigram DP）切分**，未知字回退单字，
   标点/数字/ASCII 走同一套符号规则 —— 等价 jieba 关闭 HMM 的行为，与官方粒度同源
   （`tools/build_pinyin.py` 本来就以 jieba `dict.txt` 为源）。纯函数放 `preview/core.mjs`，
   配 `preview/split.test.mjs`（中文长句 / URL / 中英混排 / 纯标点 / 超长）。
3. **面板**（`preview/app.mjs` + `style.css`）：按上表实测值实现 —— 45dp 标题栏、圆角 8.3dp 白卡、
   自然宽度流式词块（最小 64.3dp、圆角 12dp、间距 11dp、14sp 文字、#60646B / #3482FF）、
   可滚动可视区（198dp）、底行「全选 + 右侧图标」、分隔线 #E7E7E8。
4. **行为**：点块=追加该词（用现有 `InputConnection` 提交链路，正文带 composing 态），
   再点=撤回；全选=全量；离开=整段回滚（原生侧保留进入前快照，退出时还原）；
   宿主回车/继续输入=落定。
5. **验证**：网页回归（`split.test.mjs` + 受影响的 `ime-regressions` / `fixed-layout` / `key-press`）
   → APK 构建 → 真机安装 + 真机截图自检（`.android/design-shots.mjs` 同类脚本）→ 与官方同条件截图并排比对。

第二批（用户新增需求，官方没有）：

- **面板内编辑**：点「编辑」进入本次拆词的文本编辑（复用现有大文本框 `sheet` 布局），
  改完**立即重新分词**并刷新词块（只重排、不丢已选中的词：以"已选词的相对位置"重新对齐，
  无法对齐的按整段重排）。
- **词级微调**：长按词块可「合并左右 / 在此拆开 / 删除该词」，改完同样自动重排。
- 编辑结果**只作用于本次上屏**，不改写原剪贴板条目（与现有"引用/编辑不学习"一致）。

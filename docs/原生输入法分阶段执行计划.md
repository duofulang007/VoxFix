# 原生输入法分阶段执行计划

日期：2026-10-10。状态：独立输入法、26 键常用输入和实时语音链路已实施并安装；自检/构建、K60 真实文字连接、用户流式语音/取消/跨 App/断网指定场景通过。最新优先级：26 键常用功能优先，手写仅基本维护。手写固定笔画原生推理通过，不将其视为真人准确率通过。具体证据见《USB真机验收》。

## 已确定的目标和交互

在现有 Android 项目中实现安装后可独立选择的 VoxFix 输入法，按现有网页原型逐步复刻讯飞小米版界面与交互，接入已有手机本地语音能力。保留手机上的两个讯飞包。

本轮用户确认的主流程：长按空格开始说话，停止后自动写入当前 App 输入框，不增加确认提交或暂存面板。网页原型已实现短按空格、长按录音、上滑取消、松手结束，直接作为迁移依据，不再重新询问或设计一套手势。

最新用户纠正取代此前一次性上屏决定：说话时 ASR 文字持续进入上方 App 输入框；松手后补整段标点并保留既有数字格式处理。使用 Android composing text 更新本次语音范围，最终替换该范围而非重复追加。原生输入法暂不让 Qwen 整理阻塞实时输入；独立验证页仍保留原有本地整理能力。无文字不提交，识别失败保留已收到文字；不保存录音或转写。润色规则和速度专项优化仍暂缓。

## 当前起点

- 以下为执行前起点：原生 APK 当时是独立验证应用，Manifest 中没有输入法服务；现已加入服务。
- 已有 SpeechEngine、NativePolisher、TextNormalizer 及本地 JNI 推理接口，优先复用。
- 录音、离线识别、整段标点及整理已有指定场景证据；数字和量词有固定文本通过记录，去重复仍有失败记录。
- 网页端键盘和手势已有实现；网页与电脑服务的测试不能作为手机原生输入法通过证明。
- 具体历史证据以《USB真机验收》《手机端大模型框架》最新决定为准，本计划不改变既有验收结论。

## 阶段一：独立输入法入口与最小跨 App 输入

**内容**：在现有包内加入 InputMethodService、系统注册及必要配置。现有 Activity 承担启用、选择输入法及麦克风授权引导，保留验证能力。提供最小输入视图，先接通文字、空格、删除和按输入框类型执行的回车动作。

**涉及范围**：AndroidManifest.xml、新增输入法服务与必要资源、MainActivity.kt 中必要引导；修改前检查相关调用及生命周期。不移动整套语音代码、不换包名、不新建项目。

**验收效果**：

- 系统输入法列表能看到并选择 VoxFix；可切回原讯飞输入法。
- 在 K60 的聊天、笔记、搜索三类实际输入框中可呼出键盘并输入、删除，已有文字不被清空。
- 在文本中间输入落在当前光标位置；有选区时符合正常替换选区行为。
- 回车按输入框要求换行或执行搜索等编辑动作，不把普通文字输入等同于发送消息。

**完成条件**：相关源码自检和 APK 构建通过，安装回执明确，用户完成以上真机操作后才记录本阶段真机通过。最小键盘不算讯飞界面复刻完成。

## 阶段二：长按空格语音与自动上屏

**内容**：迁移 preview/app.mjs 的现有空格手势；复用手机语音链路和原文保护。输入法内仅提供必要录音、取消和处理中反馈，不加入识别对照或调试面板。

**涉及范围**：输入法服务和输入视图、SpeechEngine.kt、NativePolisher.kt、TextNormalizer.kt 的调用与资源管理。只在现有接口无法安全复用时做必要小改动；模型、提示词、数字规则默认不变。

**验收效果**：

- 短按空格正常工作；长按开始录音，按住说话，松手结束；上滑取消后不写入本次文字。
- 说话时识别文字持续出现在上方真实输入框；松手后将同一语音范围补全为整段标点/数字格式结果。不需要点确认，不重复追加，不把未校验的 LLM 草稿上屏。
- 停顿仍用于 ASR 分段，实时更新文字；停止后使用整段标点结果。
- IME 暂不调用阻塞式 Qwen 整理；补全失败保留已收到识别文字，没有识别文字时不破坏输入框内容。
- 连续两次录音各写入一次，保留原有文字；在光标和选区位置行为正确。
- 拒绝麦克风权限、模型加载失败时提供简短可理解的提示，键盘仍可操作，不假装已识别成功。

**内部边界**：原输入会话结束、输入目标变化或键盘收起时停止录音并取消本次后续提交资格；迟到回调不能写入新输入框。目标变化时保留旧框已显示的文字，不跨框删除；明确上滑取消且原输入会话有效时撤去本次 composing 文字并恢复原选区内容。自身实时更新带来的光标回调不能误取消录音。新录音不能与旧任务争用麦克风。该策略尚未核实为讯飞当前版本的内部行为。

**原文保护与撤销**：保留当前语音会话的原文保护能力。现有验证页的“撤销整理”不能直接照搬成跨 App 任意删字；只有能确认刚提交文字仍未被编辑、光标和输入会话未变时，才可替换为原文，否则不覆盖用户后续输入。若尚不能安全实现，明确记录此项待办，不宣称跨 App 撤销已完成。

**完成条件**：增加最小自检覆盖取消、旧任务回调失效、一次提交及失败回退；相关现有保护测试、构建通过；用户真机完成正常录音、取消、连续输入、处理中收起及切换输入目标。仅完成自动上屏，不等于整理质量全面通过。

## 阶段三：正常功能与离线真机验收

**内容**：对阶段一、二形成的链路集中验收，只修复实际问题，不扩展润色和性能研究。

| 场景 | 预期效果 |
|---|---|
| 聊天、笔记、搜索框 | 正确呼出、输入、语音自动上屏，符合各输入框编辑动作 |
| 手机 Wi-Fi 和移动网络均关闭 | 手机本地录音、识别、标点及整理链路可用 |
| 上滑取消、空录音 | 不插入本次文字，不清空已有内容 |
| 连续录音、光标中间、选区 | 每次只提交一次，位置正确，无无关文字损失 |
| 录音中或整理中收起键盘、切换 App/输入框 | 麦克风停止，旧结果不进入新位置，再次呼出可正常输入 |
| 原文保护回归 | 既有数字、否定词、英文和引号保护自检通过；真人语义仍按实际结果判断 |

不通过的场景保留操作步骤和故障现象，先查现有日志再做最小修复。不得为补齐报告盲目重复长模型测试。真人语音只使用用户当场反馈，不保存日常录音或转写。

**完成条件**：每项记录通过、失败或未测及证据类型。源码自检、APK 构建、安装回执、真人结果分别记录。缺少真人反馈时保留“待验收”，不从启动成功推断功能通过。整理去重复、同音词及单位准确性保持独立质量待办，不混入输入法链路通过结论。

## 阶段四：逐步迁移讯飞小米版键盘界面与交互

**内容**：以现有 preview 为行为依据、用户既有截图和录屏为外观依据，每次迁移一个可独立验收的模块。开始各模块前只读涉及的原型、测试和原生实现。

建议顺序：主键盘布局与空格语音状态 → 拼音组合和候选提交 → 候选栏完整显示、展开与拖动 → 数字/符号及中英文切换 → 其余已存在的工具栏、剪贴板和手写模块。

中文拼音、词库及手写等原生能力先检查现有代码和成熟实现；不将浏览器可用等同于原生可用，不为短小功能新增依赖。需要引入上游时先固定版本、确认许可和模型/词库许可，再在 K60 验证。

**验收效果**：已迁移模块的布局、按键反馈、手势和状态与现有参考一致；候选文字完整，保留触摸拖动浏览；中文组合、选词与删除正确。迁移键盘后，长按空格语音与自动上屏仍通过受影响回归。未迁移模块逐项标明，不能把主键盘外观相似记为全部复刻完成。

**完成条件**：每个模块单独检查外观、交互与真机行为，通过后再迁移下一个；不在一轮重写全部键盘。

## 全程约束

1. 保留现有未提交工作、用户数据、模型和两个讯飞包；项目没有 Git 仓库，不报告虚构 Git 差异。
2. android/app/src/main/ 是原生实现；preview/ 是原型，voice/ 是电脑服务，不将其作为手机离线能力。
3. 不新增确认提交、暂存面板、识别对照、调试面板、日常录音/转写训练、云端识别或个人记忆。
4. 优先现有模块、平台能力和成熟开源实现；不新建项目，不一次重写全部键盘。
5. 润色规则、速度、逐字显示和模型更换暂缓；当前质量与耗时限制如实记录。
6. 普通文件发现用 rg --files，遵循 .ignore；不递归读取 SDK、模型下载、虚拟环境、模型和构建目录。必要日志按明确路径读取。
7. 只回归受影响功能。构建不自动代表安装，安装不代表真机通过；手机选择输入法、授权和实际操作由用户完成，不改系统安全设置。

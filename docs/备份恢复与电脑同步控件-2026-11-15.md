# 备份恢复落位与电脑同步控件（2026-11-15）

## 1. 用户现象

卸载重装 → 按首页三步向导把「启用 / 默认 / 试用」全部走成就绪 → 再从本地备份恢复。
结果：词库、剪贴板回来了，但**截图编辑工具栏的横向排布（主栏与绘图栏的自定义顺序）仍是默认值**；
另外手机侧一直找不到「电脑剪贴板同步」的设置控件。

## 2. 取证（K60，串号 6959dba1）

恢复发生在 17:25，检查时 17:46：

| 位置 | 内容 | 说明 |
|---|---|---|
| `files/prefs-restore/` | `screen-text.xml`、`screenshot-tool-memory.xml`、`voxfix-modules.xml`、`voxfix-update.xml` 仍在（17:25） | **从未落位**：`VoxFixApp` 只在进程启动时复制它们 |
| `shared_prefs/screen-text.xml`（在线） | 只有 `pc.*`、`y`、`right`、`handle_tone` | 没有 `screenshot.toolbar.actions` / `drawing` |
| 备份 `VoxFix-20261115-172331.zip` | `screenshot.toolbar.actions=SAVE/MOVE/PIN/…`、`screenshot.toolbar.drawing=SELECT/PEN,LINE,…` | 自定义顺序确实在备份里 |
| 备份 `VoxFix-20261115-172556.zip` | 没有上述两个键 | 恢复后、落位前又生成的一份**降级备份**，不要再拿它恢复 |
| `files/web-mirror/layout.json` | 默认工具栏顺序 | 键盘顶栏本来就没改过顺序，与本次问题无关 |

结论：不是三步向导与恢复冲突。向导写的是系统输入法启用/默认状态（Secure settings），
恢复写的是应用偏好与 WebView 镜像，两者不共享存储。问题是**恢复后的设置没有落位**。

## 3. 根因（两个）

1. **“从文件恢复”不触发冷启动。**
   卸载重装后 MediaStore 收回了旧备份的所有权，备份列表必然为空，用户只能走文件选择器。
   列表路径的 `restore(archive)` 会判断 `LocalBackup.needsRestart()` 并 1.5 秒后退出进程；
   `onActivityResult` 的文件选择器路径只调了 `LocalBackup.restore`，没有重启。
   `prefs-restore/` 于是永远躺在私有目录里，截图工具栏顺序、工具样式（`screenshot-tool-memory`）
   全部停在默认值。

2. **运行中的镜像推送只合并 snippets。**
   前端 `voxfixApplyPendingMirror`（原生 `updateClipboard` 每次键盘弹出时调用）此前只处理
   `parsed.snippets`，`layout`（工具栏顺序、键盘几何、外观）与 `keyboard`（9/26 键、语言、夜间）
   被整段忽略。即使恢复发生在键盘已加载之后，这两类设置也不会生效。

## 4. 修复

- `BackupActivity`：抽出 `restore(uri, label)`，列表与文件选择器共用同一收尾。
- **偏好改为运行中即时写回**：`LocalBackup.restorePrefs` 用 `PrefsXml` 解析备份里的 8 个 XML，
  在主线程用 `PrefsStore.replaceAll` 整份覆盖运行中的 SharedPreferences（clear + put + commit），
  不再落 `prefs-restore/`、不再杀进程重启。
  旧做法会让 HyperOS 把被杀的无障碍服务记为 Crashed，用户恢复一次就得重新授权一次「屏幕取字」；
  现在弧线位置、模块开关由监听器当场更新，无障碍与授权都保持。`files/prefs-restore/` 只作为
  旧版本遗留兜底，恢复时会清掉，避免下次冷启动把新值覆盖回去。
- `preview/app.mjs`：新增 `applyPendingKeyboard` / `applyPendingLayout`，
  `voxfixApplyPendingMirror` 现在一起应用 snippets、keyboard、layout；
  布局走 `settingsFrom` 校验，坏备份保留当前设置，不会把键盘打空。
- 回归：`preview/pending-mirror.test.mjs` 覆盖启动时取镜像、运行中推送、坏布局三种情况。
- 提示文案：弧柄无线调试的「缺少授权 / 见设置页」改为「缺少授权 / 用电脑 adb 授权」——
  这个权限不在系统设置里，只能由电脑 `pm grant`。

恢复语义保持不变：偏好文件是整份覆盖（备份为准），词库与词典仍是合并。

## 5. 电脑同步控件（原版无此功能，手机侧扩展）

链路本体早已存在：电脑端 `tools/copyq_phone_sync.py` 推送 → `ClipboardImportReceiver` 写剪贴板 /
图片页；心跳 `PC_STATE` 存在 `screen-text` 的 `pc.beat`、`pc.transport`、`pc.clip`、`pc.addrs`。
2026-11-14 精简时删掉的「电脑同步」状态行是死 UI（接收器从不读取），所以这次补页面时
同时给接收器加了**真正生效**的开关，避免再做一次「看得见、点不动」。

新增 `PcSyncActivity`（设置页 → 设备 → 电脑同步）：

- 连接状态：电脑端是否在线（15 秒无心跳即断开）、USB / Wi-Fi、电脑地址、CopyQ 监听是否就绪、最近心跳。
- 手机侧控制：`接收电脑剪贴板`（总开关）、`接收电脑图片`（子开关，总开关关闭时置灰）。
- 电脑端说明：运行 `tools/copyq_phone_sync.bat`；只有 CopyQ「手机文本 / 手机图片」标签会推送；
  手机 → 电脑由 scrcpy 负责，不受这里开关影响。
- 状态每秒刷新，离开页面停止。

实现约束：

- `PcSyncPrefs`（`screen-text`，默认全开，保持升级前行为）是唯一读写入口；
  `ClipboardImportReceiver` 在导入前读取开关，关闭时把电脑已推进来的临时文件删除并记
  `CLIPBOARD_IMPORT_SKIPPED`，不接收也不占空间。
- 心跳与地址不受开关影响：关掉接收仍能看到电脑在不在。
- `PcSyncStatus` 是纯数据换算（心跳时间戳 → 连接状态/连接方式/耗时文案），JVM 单测覆盖边界。
- 原版（Snow Shot 1.1.8）没有电脑同步，本页是 VoxFix 手机侧扩展，不计入 1:1 复刻。

# 屏幕取字离线模型对比（2026-11-03）

## 结论

在本轮生成样本上，**ML Kit定位文字行＋PP-OCRv6 small识别**显著减少错字，优于现用ML Kit单独识别；
medium体积更大、速度更慢，在本组的准确率还低于small，因此优先建议small。
这是候选评测，未替换、构建或安装主程序，未升级主程序的语音运行库。

## 实测结果

Redmi K60 / Android 15，ONNX Runtime Android 1.20.0 CPU两线程；候选复用同一份ML Kit 16.0.1的文字行位置。
12组三行文字、16/24/36/64px、深浅底，96张不同图；每张重复两轮，加每轮两张空白图。
共196次图片处理、三种引擎588条结果，完整运行387.610秒，无识别异常或超时。
准确率只统计首轮96张、共5352个去空白参考字符，重复轮次不当成新语料。

| 指标 | 现用ML Kit | ML Kit定位＋v6 small | ML Kit定位＋v6 medium |
| --- | ---: | ---: | ---: |
| 去空白字符编辑错误 | 356/5352 | 15/5352 | 22/5352 |
| 去空白字符错误率（保留标点） | 6.65% | 0.28% | 0.41% |
| 再忽略Unicode标点的正文错误 | 192/4656 | 5/4656 | 15/4656 |
| 正文字符错误率 | 4.12% | 0.11% | 0.32% |
| 整张三行完全一致（去空白、保留标点） | 6/96 | 82/96 | 77/96 |
| 数字串（含逗号、小数点）逐项一致 | 87/96 | 96/96 | 96/96 |
| 请求耗时P50 | 83ms | 522ms | 1581ms |
| 请求耗时P95 | 113ms | 626ms | 1876ms |
| 请求耗时最大值 | 184ms | 662ms | 1945ms |
| 第二轮文字发生变化的图片 | 0/96 | 0/96 | 0/96 |
| 空白图误输出 | 0/4 | 0/4 | 0/4 |

时间包含ML Kit处理；候选再加逐行裁剪预处理、识别、CTC解码。
不含系统截图、测试图绘制、面板展示，以及首次模型复制和会话构造。
首次复制＋会话构造：small145ms、medium293ms；两候选同时驻留，轮末总PSS301787/315924 KiB，
该总量不能用于声称单独small的内存用量，也不足以排除长期泄漏。

与ML Kit相比，以正文编辑错误数量判断：small改善82张、持平14张、变差0张；
medium改善81张、持平14张、变差1张。持平只表示错误数相等，不一定错在同一位置。

前六组沿用[上轮48图](屏幕取字准确率与稳定性测试-2026-11-03.md)，ML Kit仍为184/2488（7.40%），
small为6/2488（0.24%），medium为10/2488（0.40%），说明对照基线可重复。

## 修好的错误与残留

36px浅底的“离线屏幕取字”“请检查屏幕亮度”在ML Kit中两次将“幕”写成“募”，
small和medium均恢复正确。small在本组也改善了财务词汇和近形字。
不使用词典替换、语言模型改写或参考答案引导解码。

small仍有五处正文编辑错误：四张16/24px近形样本将“嬴”识成“赢”；
64px深底英文样本将“OpenAI”识成“DpenAI”。
medium还在若干字号把“OpenAI”识成“OpenAl”，并有“羸”误识。
不能把这组结果写成“日常准确率99.9%”或“金额永远正确”。

## 体积与兼容性

- small ONNX模型：21,234,383字节；medium：76,629,984字节。SHA256已与固定上游清单核对。
- 保留现用ML Kit用于定位时，只需加入胜出的识别模型，不必同时加入两套或新检测模型。
- 候选IR10模型被主程序现用ONNX Runtime 1.17.3拒绝（最大IR9）；独立测试包使用1.20.0后成功。
- ARM64运行库加JNI：旧版16,797,888字节，新版18,487,128字节，差1,689,240字节。
  若主程序采用同样配置，small模型＋运行库替换的原始文件增量约22.92MB；medium约78.32MB。
  这是估算，尚未包含主包DEX、签名、对齐等变化，不是实测主APK增量。
- 主程序的1.17.3还用于语音CTC救援。采用候选前必须回归语音及JNI兼容性，不能据独立测试直接宣称可安全升级。
- 同时包含两模型、ML Kit、运行库的独立测试包，清理后重新构建为139,094,314字节；
  增量打包曾保留旧条目空洞，故不使用其154,968,919字节作为正式包体积依据。

## 复跑

使用本项目可用Python运行：

```text
python tools/prepare_screen_ocr_eval.py
```

按开发入口用仓库JDK/Gradle串行构建`:screenTextUiTest:assembleDebug`，安装独立测试APK后：

```text
adb shell am instrument -w -e offlineCompare true local.voxfix.screentest/.ScreenTextUiInstrumentation
adb exec-out run-as local.voxfix.screentest cat files/offline-compare.json
python tools/score_screen_ocr_eval.py <本地保存的offline-compare.json>
```

结果含每行参考、原始识别、字号、底色、耗时和轮次，不依赖云端服务；先完整结束再启动另一instrumentation。
取回结果时保持UTF-8字节，避免Windows控制台编码改变中文。

# 并行开发约定（2026-10-17）

目的：让多条开发线同时推进而不互相覆盖。本文只讲“怎么切、怎么说、怎么收”，不讲具体功能实现。

---

## 一、怎么跟我说：任务书四行

每次派活给我这四行就够，多了会乱，少了我会追问——但追问比猜错便宜。

```
目标：要什么行为，怎么算做完
范围：只动 X；不要碰 Y
验收：跑哪个 test / 要不要真机
参考：官方对照在哪份文档
```

示例：

```
目标：剪贴板引用入口在匹配时右端悬浮，点击展开连体浮层
范围：只动 app.mjs 的 paintClipboardReference 一族 + style.css 的 .ref-* 段
验收：clipboard-search.test.mjs，不需要真机
参考：docs/候选自适应与剪贴板悬浮-2026-10-17.md
```

一次派多条时，并列写并在每条前标 `A/B/C`，我按文件边界判断哪些能同时开、哪些必须排队。

## 三、“按功能拆文件”：方向对，切法要改

你的提法对了一半。

**对的部分**：不要在 `app.mjs` 里继续叠新功能。现在它 196 KB，再加两个功能就彻底改不动了。

**要改的部分**：不能按“候选 / 剪贴板 / 语音”去切 `app.mjs`。原因很实在——这三块共用同一个 `state`、同一个 `render()`、同一套事件委托。剪贴板要读候选状态，语音要写选区状态，选区又驱动候选区刷新。按功能切目录，第一次 import 就会形成循环依赖，最后被迫加一层中间层，比不拆更复杂。

功能度均匀（123~172）恰恰是“交织”的证据，不是“可分块”的证据。

**正确的切法是按层次**，从无状态往有状态推进：

| 层 | 内容 | 风险 | 收益 |
|---|---|---|---|
| L1 无状态渲染 | 返回 HTML 字符串的模板函数，不读 `state` | 极低 | 立刻可并行，改动零冲突 |
| L2 单功能闭环 | 自带局部状态、只通过约定接口与主流程通信的完整小功能 | 中 | 该功能独占文件，长期可并行 |
| L3 全局 state 拆分 | 把 `state` 按域切开、`render()` 拆成多段 | 高 | 只有连续加大型功能才值得 |

现在只该做 L1，并按需做 L2。**L3 在近期没有并行需求时是负收益：拆文件本身不产生功能价值，它的唯一作用就是让并行不打架。**

### 抽一个模块的准入判断（三条都满足才抽）

1. 有独立 test 文件守行为
2. 有独立 CSS 前缀（`.ref-*`、`.clip-*` 这类）
3. 原生侧或算法侧已有对应独立文件

只满足一两条就抽，等于给自己造一个没有测试保护的模块。

## 四、并行时的固定动作

开工前（每次都做）：

1. `git status` 必须干净。有未提交改动先提交成基线（2026-10-29 已提交到 `main`），否则并行合并会覆盖在做的活。
2. 每个并行线一个 worktree + 一个分支：`git worktree add ../VoxFix-<线名> -b feat/<线名>`。
3. 每条线自己跑自己的 `preview/*.test.mjs`，不跑全量（省时间）。

收尾时（必须串行）：

4. 按顺序逐个 merge 回 `main`，每合一个跑一次全量网页回归。
5. **只有最终 `main` 才构建 APK 并装机**。中间分支不装机。
6. 真机验证永远只有一条队列：一台手机，`adb install` 是全局操作。

### 并行的真实上限

- 能并行：写代码 + 网页回归测试。
- 不能并行：`adb install` / `am instrument`（单机全局）、Gradle 构建（单 cache 单锁）。
- 所以并行加速的是“前半段”，后半段必然串行收口。三条线并行大约省一半时间，不是省三分之二。

## 六、多出来的目录怎么管

worktree 会在磁盘上真的多出目录，所以必须有固定规矩，否则比不并行更乱。

### 为什么 worktree 不会变成垃圾

- **git 认识它们**。`git worktree list` 一查就知道有哪些线、在哪、什么分支。相比之下，“复制一份文件夹改完再手动对比合并”那种才是真乱：没有主、没有追踪、合并靠人眼。
- **集中放一个地方**：`D:\Projects\VoxFix-wt\<线名>`，不散落在 Projects 里。主目录 `D:\Projects\VoxFix` 永远只有 `main`。
- **本体很轻**：`.git` 仅 6.7 MB，裸 worktree 只占几十 MB。
- **收线即删**：最后一条线收完，`VoxFix-wt` 整个目录自动消失。

### 一个必须知道的坑

`.gitignore` 排除了 `models/`（351 MB）、`.android/`（4.4 GB）、`preview/pinyin-data.json`（13 MB）等生成物。**新建的 worktree 是“裸”的，缺这些文件时 8 个以上的测试会直接失败。**

所以不要手动 `git worktree add`，用脚本，它会自动补齐。

### 三条命令

```bash
python tools/wt.py new clip-ref      # 建线：建 worktree + 分支 + 补齐生成数据
python tools/wt.py list              # 看线：分支、未提交数、已提交数、状态
python tools/wt.py done clip-ref     # 收线：确认已合并且无未提交改动，再删目录和分支
```

已经实测整条链路：建线 → 在 worktree 内跑 `split.test.mjs` 5 项 PASS → 收线 → 目录与分支都清理干净。

### 大目录怎么办

默认**不挂** `.android`（4.4 GB 工具链）和 `models`。因为分支只做“写代码 + 网页回归”，不需要构建：

- 分支线：跑 `preview/*.test.mjs`，用主目录同一套 node/playwright。
- 构建与装机：只在 `main` 上做。合并完成再构建，物理上也只有一台手机。
- 确实要在某条线构建：`python tools/wt.py new <线名> --native`，会给该目录建 junction 指向主目录的 `.android` / `models`（不复制、不占额外空间）。

### 日常节奏

同时最多开 2–3 条线。一条线该收就收，不要留着当“以后可能要用”。`list` 里出现“已合并，可 done”就立刻收。

## 七、建议的第一步

不要一上来大拆。先做一次试点，验证“抽出去之后测试还守得住”：

挑**剪贴板引用浮层**做试点——它是唯一三条准入全满足的候选（有 `clipboard-search.test.mjs`、有 `.ref-*` 前缀、算法在 `split.mjs`/`pinyin.mjs`）。抽成独立模块，跑全量回归，确认零行为变化。

试点通过，再按 L1 → L2 推进其他块。试点不通过，说明测试覆盖不足，该先补测试而不是先拆文件。

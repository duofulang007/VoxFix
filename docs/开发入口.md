## 目标与当前实现

VoxFix 是可独立选择的自有 Android 输入法，复刻讯飞小米版的界面与交互，接入本机离线语音。
保留手机上的讯飞小米版 `com.iflytek.inputmethod.miui`。`preview/` 同时是浏览器原型与 APK 内键盘前端，
语音只在原生 `SpeechEngine.kt` 侧真实运行；桌面语音服务已于 2026-10-18 删除，不能再拿电脑端结果当手机能力。

- 原生 ARM64 Debug IME：`local.voxfix.debug`，Android 15 / API 35，已在 Redmi K60 安装使用。
- 中文26键使用 librime 1.17.0；个人词库与英文词表由 `stagePinyin` 打包，`preparePersonalData()` 部署。
  全拼、首字母简拼与混拼共用同一词库召回，数字页符号栏可滚动但不显示滚动条，见[简拼与隐藏滚动条](简拼与隐藏滚动条.md)。
  个性化选词统一由长期个人词库提供，默认开启，无学习开关或清空控件；支持完整备份/通用文本与合并导入，见[长期词库约定](长期个人词库与迁移-2026-10-17.md)。
  现已加入个人语音词典：手动词立即优先、中文同音改字渐进学习，与拼音共享用词先验；完整备份version2兼容旧版导入。源码/安装/隔离成长闭环已验，真人改字与跨App待验，见[实现与边界](个人语音词典与纠正学习-实现-2026-10-18.md)。
  已升级为[通用语音纠错学习](通用语音纠错学习-2026-10-18.md)：删错词→拼音组合→候选确认后自动学习，中文、英文无需逐词登记；支持不等长、多处改词、同音错法共享，发送/收起/下一段前处理，保存与识别按同一队列执行。旧“英文须先加词”限制已取代；平台编辑闭环与固定语音已验，真人日常表现仍待验。
- 26键普通候选自然宽度、20px完整文字、横向滑动；匹配剪贴板时右端悬浮入口，整入口点击展开210px连体列表，
  点条目引用、长按编辑。已取消五/六固定格与拖动调位，见[最新候选约定](候选自适应与剪贴板悬浮-2026-10-17.md)。
- 剪贴板支持拆词、连续拖选、最多300条全历史检索和原位搜索；引用与编辑共用「取消 / 拆词 / 保存」编辑框。
- 滑轨只输出左右，短按精调一个字，长按切换锁定/自由；跨行选择用右侧八方向盘。面板保持既定尺寸，支持图标操作与删除。
  到文本首尾再继续推不会把焦点送出输入框（根因与宿主方向键处理见[滑轨越界](滑轨光标越界-宿主方向键.md)）。
- 工具栏长按 380ms 图标直接抬起，拖到别的图标上松手即落位并持久化；没有排序模式、提示行或「完成」按钮，
  见[工具栏长按拖动](工具栏长按拖动排序-2026-10-18.md)。
- 删除键与面板删除钮按住走独立连删曲线（90ms 起步到 30ms 封底），滑轨仍走摇杆分档速度，
  两条曲线互不影响，见[删除连删速度](删除连删速度-2026-10-18.md)。
- 语音使用 sherpa-onnx 1.13.8：Zipformer 流式 + SenseVoice 二遍整理 + silero VAD + CT-Transformer 标点。
  长按空格 300ms 进入，上滑取消、松手停麦；普通打字不加载语音，使用后空闲 30 秒释放，二遍后台加载。

  **模型与调度**

  - 二遍权重是**通用版** `…2024-07-17`（`use_itn=true` 自带标点，LID 能分辨 zh/yue；此前那条 2025-09-09
    粤语微调既不产标点、LID 又恒报 `yue`，已弃用）。
  - 冷启动二遍改为用户启动语音时与流式模型并行加载，不再等首次非空文字，见[冷启动二遍加载](语音冷启动二遍加载-2026-10-19.md)。
  - 20ms 采集，构建时预优化流式计算图，见[跟手与冷启动](语音跟手与冷启动优化-2026-10-17.md)。
  - 二遍按停顿切段：0.5s 静音才切，提交前先把解码器里最后一块补渲完再重置（否则会丢尾字）；
    英文二遍只在词序列可自证时才采用，见[中英混合与英文评测](语音中英混合与英文评测-2026-10-17.md)。
  - 实时文字（边说边出）只有第一遍流式，中英混说的准确率上限由它决定；K60 实测 beam 加路数不划算，
    能用的是热词（术语进个人语音词典即生效，混说 18.2%→16.5%），见[中英混说实时文字](语音中英混说实时文字-2026-10-18.md)。
  - 换更大基座/离线模型的可选路线与评测口径见[准确率方案调研](语音准确率方案调研-2026-10-18.md)（均未在 K60 验证）。

  **松手交接与改写**

  - 普通输入松手先定稿上屏，420ms 内只允许在原输入框、原位置、原文字未变时替换；不再占用拼音组合区，
    下一次编辑/换框即关闭窗口，空首结果也可补词。共享编辑框复用最后一句 ≤350ms 的二遍收尾预算，
    模型未就绪不等。见[交接修复与验收](语音准确率速度与交互审计-2026-10-18.md#后续最小修复已构建并保留数据安装)。
  - 二遍队列在 `SpeechSecondQueue.kt`：已有英文术语受数量保护，队列取消会向下传递，迟到的单句结果复用其标点，
    维持原模型/调度/时限，见[本轮修复与试验](语音数量保护与迟到标点复用-2026-10-19.md)。
  - 二遍术语修正先检查中文否定，防止修正英文时删掉“不/没/别”；补否定仍须原有双裁剪证据，
    见[术语否定保护](语音术语修正否定保护-2026-10-19.md)。
  - `SpeechEnglishRecovery.kt` 做[混说局部术语恢复](语音混说局部术语恢复-2026-10-19.md)：整句二遍无法采用时，
    仅在词位及中文上下文一致时恢复有词表依据的单个英文词。129 项源码测试通过，后随启动闪现修复保留数据安装
    （`df7a6f…66920`），并完成 46 条固定回放；JSON 局部恢复生效，API 漏字及其他英文/粤语模型错词仍在。

  **VAD 边界与采用证据**

  - silero 阈值用 **0.4**（不是上游默认 0.5）：0.5 会把句首轻声判成静音，二遍因此丢掉「这个bug」的前半句，
    见[VAD 句首丢失](语音VAD句首丢失-2026-10-18.md)。
  - VAD 报出的每段前后各补 160ms 原音频（`SpeechAudioWindow.kt` 环形 32 秒，"补边界"与"原裁剪"两份音频都送二遍）；
    短词、否定句首的补全必须两份识别一致才采用，金额单位结构不一致直接拒绝覆盖，粤语沿用原裁剪结果，
    见[边界与二遍采用修复](普通话边界与二遍采用修复-2026-10-19.md)。
  - 已修[粤语跨文字长度误拒绝](粤语跨文字长度误拒绝-2026-10-19.md)：双裁剪正文及粤语标签一致时，允许用英文词数
    核对被误识为长串英文的流式结果。目标长句编辑差异 40→28，配对 46 条无新增正文退化，133 项 JVM、
    80 条跨语种及 24 条普通话保护回放完成；已保留数据安装（`4c4e57…1fbcd`），仍有其它英文/粤语错词，真人未验。

  **标点与数字**

  - 标点由独立的 CT-Transformer 离线模型补位：它只吃文本、不需要音频，**松手预算超时退回实时文字**时
    同样生效，加载等待上限 150 ms（随二遍一起回收），见[标点恢复](语音标点恢复-2026-10-17.md)。
  - 数字格式转换在统一输出处默认执行，无设置开关；标点必须发生在数字转换之前，否则阿拉伯数字会被模型拆坏。
    明确时间、金额、计量单位复用已有数值解析，流式和最终结果均生效，不等待二遍。模糊口语数值保留原文，
    见[专项](语音数字转换专项-2026-10-17.md)。
- WebView固定550dp画布，外层按可见键盘高度裁切，减少编辑区展开时旧画面搬动；主键盘351px。
- 手写与安卓Qwen润色已移除；停用手写源码与测试已删除，历史版本可从Git追溯。
  桌面语音服务 `voice/`、`preview/voice.mjs` 与 `tools/validation_server.py` 于2026-10-18整簇删除，
  语音只在原生侧真实运行。网页试用页已与手机功能面对齐：电脑语音服务、离线整理、语音热词、长句词库与
  录屏对照均从页面移除，语音在网页侧只做交互演示。不恢复模拟器，不另起输入法项目。

## 验证链路

网页交互检查 → APK 构建 → USB 真机。**网页通过 ≠ 原生通过；构建 ≠ 安装；安装 ≠ 真机通过。**

- 网页交互检查：`preview/*.test.mjs`，Playwright + Edge，纯逻辑与几何可无头验证。
- 构建与 JVM 自检：`tools/build_android.ps1`，内部执行 `testDebugUnitTest assembleDebug`；**不自动安装**。
- 真机：先用 `adb forward` 把 IME WebView 的 devtools 端口转到本机，再跑 `preview/*-device.test.mjs`；
  Android 侧改动必须重新 `adb install -r -t` 才算真的上机（构建日志成功不能证明手机上是新代码）。
- 只回归受影响功能；手机操作需要用户实际完成，不能假设通过。破坏性操作先预演再确认。

## 运行与大文件边界

Git 仓库为 `duofulang007/VoxFix`，远端 `https://github.com/duofulang007/VoxFix.git`，私有，主分支 `main`。
只提交源码、脚本、必要文档/许可及浏览器参考图；模型、SDK/NDK、缓存、APK、签名密钥、录屏和生成词库
都不提交（见 `.gitignore`）。提交及同步状态以实际 Git 检查为准。

- `android/app/build/` 是生成产物；APK 在 `android/app/build/outputs/apk/debug/app-debug.apk`。
- `preview/pinyin-data.json`、`preview/pinyin-lite.json` 和根目录 `键盘试用页.html` 是生成数据，
  修改时应追溯生成器（`tools/build_pinyin.py`、`tools/build_preview.py`）。
- `.android/` 保留本机 SDK、NDK、拼音 JNI 与依赖工具，**不含模拟器**；`.model-downloads/` 是下载元数据
  与词库源；`.venv/` 是电脑依赖；`models/` 是运行模型。常规搜索已由 `.ignore` 排除，不要递归阅读。
- 首次克隆后需要另行准备：`.venv`、`models/`（`tools/setup_voice.py`）、`.android/pinyin-rime/`
  （`tools/setup_pinyin_rime.py`）、Gradle/JDK/SDK（`tools/build_android.ps1` 会按固定摘要自动准备）。
  语音计算图预优化使用构建机 `.venv` 中的 `onnxruntime==1.31.0`，依赖固定在
  `tools/streaming-optimization-requirements.txt`；Gradle自动生成并校验 `.android/streaming-optimized/`，不提交模型或缓存。
- 模拟器及其系统镜像、AVD 已按要求移除（合计约 16 GiB），**不要为网页/USB 工作流重新安装模拟器**。

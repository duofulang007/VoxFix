# 开源复用与项目管理

更新时间：2026-10-10。

## 本轮替换范围

此前中文整数解析是项目自行实现的，不能称为直接使用成熟开源方案。本轮已移除该解析算法，复用 [WeTextProcessing](https://github.com/wenet-e2e/WeTextProcessing) v1.2.0 的 C++ 处理器及官方 wetext 0.1.8 数字转换图；Android OpenFst 固定为 1.0.2。源码版权、Apache-2.0 许可和上游说明位于 `android/app/src/main/cpp/vendor/wetext/`，下载与图文件摘要固定于 `tools/setup_text_normalization.py`。

只做 JNI、旧版 Android OpenFst BYTE 接口及静态库兼容；不重新实现中文数值计算。项目保留数量上下文选择、原文保护和 Qwen 提示词，这些属于本应用的接入逻辑。数字格式交给 WeText；去赘词、去重复及上下文整理仍由已有本地 Qwen 完成。

不直接套用整句 WeText ITN：电脑评估中整句转换会把“十三香”变为“13香”，并改变部分单位拼写。当前只将明确数量片段送入数字图，避免姓名与普通词语被整句转换。“另一双”等小数量表达保留自然写法。这不是所有中文数字、日期或语义场景的完整验收，也不宣称上游是普遍最优方案。

本轮已核验并删除三个已安装工具对应的下载压缩包，释放 2,942,276,736 字节（2.74 GiB）。没有删除模型、模拟器用户数据/快照、源码或验收证据。

| 目录 | 约 GiB | 内容 |
|---|---:|---|
| `.android` | 16.33 | SDK、NDK、模拟器及其数据、第三方与构建缓存 |
| `android` | 1.68 | 原生源码和生成的 APK/构建文件，主要体积来自后者 |

因此当前占用对“工具、模拟器和离线模型都放在项目内”的开发方式可以解释，但不是源码本身需要 20 多 GiB。后续若专做真机且不再需要模拟器，可以另行处理 AVD 数据；本轮保留，避免丢失状态。

根目录 `AGENTS.md` 和 `docs/开发入口.md` 是新聊天入口；`.ignore` 已排除工具、模型、缓存及生成产物，常规 `rg --files` 当前只列出 122 个相关文件。源码、浏览器原型与电脑服务的边界明确，历史网页结果不作为手机原生能力验收。

新聊天不会仅因为目录占用 20 多 GiB 就自动把全部文件内容送入上下文。目录指令与后续选定读取的文件才形成实际输入；大文件未排除时，宽泛搜索仍会制造噪声。入口指令按 [Codex 官方 AGENTS.md 文档](https://learn.chatgpt.com/docs/agent-configuration/agents-md)保持简短，详细状态与证据按任务读取。

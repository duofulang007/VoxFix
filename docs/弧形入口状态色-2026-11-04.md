# 弧形入口状态色改版（2026-11-04 · v2 已对调）

配套效果图：[弧形入口取色效果图.html](弧形入口取色效果图.html)。几何一律不动，只换状态色。
取色依据见[侧边栏柱状把手-原生规格](侧边栏柱状把手-原生规格.md)。

## 现状问题

`ScreenTextHandle.kt` 的 `Icon.onDraw()`（`kind == 0` 分支），第 214 行原始值：

| | 值 | 问题 |
|---|---|---|
| 待机 | `#407f7f7f` | 不透明度只有 25%，2dp 细线在亮壁纸上等于不可见；在暗壁纸上是一层灰雾 |
| 激活 | `#b3505660` | RGB `(80,86,96)` 蓝通道比红高 16，是冷调灰，叠在暖色或绿色壁纸上被读成「脏」 |

## v2 对调（用户 2026-11-04 09:09 确认）

v1 把原生「常态 `#b3c7c7c7`」当待机、「拖动 `#ff979797`」当激活，用户看效果图后指出反了。
原因成立：中亮度彩色壁纸上，`#b3c7c7c7`（199）比背景亮、更跳眼；`#ff979797`（151）比背景暗、更沉。
**沉的应该当待机，跳的应该当激活。** 对调后三档方案也统一成同一规律：激活一律比待机更亮或更实。

## 最终色值

| 背景 | 待机 idle | 激活 active |
|---|---|---|
| 亮（浅壁纸 / 白底 App） | `rgba(107,107,107,.42)` | `rgba(107,107,107,.82)` |
| 中（彩色 / 灰壁纸） | `#ff979797` | `#b3c7c7c7` |
| 暗（深壁纸 / 深色 App） | `rgba(255,255,255,.55)` | `#ccffffff` |

线宽不变：待机 2dp、激活 2.5dp。状态差异由 **明度 + 线宽** 共同表达，不再靠色相。

## 已落地（v2）

采用中间档，最小改动，只改一行：

```kotlin
// ScreenTextHandle.kt:214  Icon.onDraw() / kind == 0
// 旧
paint.color = if (isPressed) 0xb3505660.toInt() else 0x407f7f7f
// 新
paint.color = if (isPressed) 0xb3c7c7c7.toInt() else 0xff979797.toInt()
```

## 后续可选

### 完整三档自适应

要跟随壁纸明暗切换，三条路成本递增：

1. **系统深色模式**：读 `resources.configuration.uiMode`，只分两档。成本最低，但亮色壁纸 + 深色模式时会判错。
2. **壁纸主色亮度**：`WallpaperManager.getWallpaperColors(DRAWABLE)`（API 27+）取主色算相对亮度，
   建议只在入口首次显示时算一次并缓存。
3. **实时采样**：成本过高，不可行。

若暂不引权限和缓存逻辑，当前中间档已解决「待机看不见」和「激活发脏」两个具体问题。

## 字节序提醒

Android 用 `#AARRGGBB`，CSS 用 `#RRGGBBAA`，两者相反。
Kotlin 用本文件左列原值；HTML/CSS 必须换算 `rgba()`，直接抄 `#b3c7c7c7` 会渲染成半透明青、抄 `#ff979797` 会渲染成粉红。

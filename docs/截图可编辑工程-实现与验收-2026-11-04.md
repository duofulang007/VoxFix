# 截图可编辑工程：实现与验收

更新时间：2026-11-04。交接编号沿用 `SCREENSHOT-EDITABLE-20261104`。
本轮把[技术实现与交接](archive/design/截图可编辑工程-技术实现与交接-2026-11-04.md)的 A–G 主链路落地：
已画元素可反复选中/移动/改样式/删除，保存后工程可重开，OCR 文本块可摆放，贴图可二次编辑。

## 1. 一句话结论

截图不再只存一张合成 PNG：保存时同时写入底图、对象文档和当前修订，图片剪贴板里再打开就回到
同一批可编辑对象。旧 PNG 仍按普通图片读取，编辑它只会新增一条工程记录，原图不动。

## 2. 用户看到的改变

1. **再次选中不再靠猜**：点选框中空区域即可抓住对象并拖动；重叠时下方对象可通过「切换重叠」取到。
2. **框外也能画**：所有标注工具可以从选框外起笔，画好的内容先在框外预编辑，再拖进框里；
   导出永远只裁选框内的像素（`ScreenshotDrawingSmoke` 逐像素验证框外笔画不进入导出）。
3. **文字标注画完即选中**：新建文字后自动回到选择工具并选中该文字，可直接摆位置。
4. **选择工具下有操作面板**：选中对象后能看到它的样式（颜色/线宽/字号/描边/填充等）与「删除标注」。
5. **图片预览多一个「编辑」**：复制 / 裁剪 / 插入聊天旁边，点开进入原生编辑器，保存后列表与预览刷新。
6. **识别文字可摆放**：结果栏新增「调整文字位置」，拖动文字块移动、右下角改大小；
   原位置的像素会被同色补丁盖住，新位置重新取背景色，撤销可一起回退。
7. **贴图能改很多次**：贴图编辑携带源图与文档，第二次编辑不会把第一轮的箭头再叠一遍。
8. **裁剪另存保留工程**：工程记录的裁剪只改视窗并另存新记录，原记录与其对象不动。

## 3. 根因（真机先失败后修复）

新回归 `ScreenshotObjectEditingSmoke`（走 `ScreenshotDrawingLayer.onTouchEvent`，与真机触屏同一路径）
在修复前于 K60 报 `点击选中框内部后丢了选择`，对应三处真实缺陷：

| 现象 | 根因 | 处理 |
| --- | --- | --- |
| 选中后拖不动 | `ACTION_DOWN` 只做轮廓命中，`hit()` 对空心矩形内部返回 false，选择被清空 | 命中顺序改为「当前框角柄 → 真实轮廓 → 对象本体 → 空白取消」；框内按下保留选择 |
| 缩小选框后旧标注选不中/移不动 | 点选要求点在轮廓上；移动钳制 `minOf(0, 左)…maxOf(0, 右)` 在对象两侧越界时变成空区间 | 越界对象按本体可选中；移动边界改为整张截图，钳制不再产生空区间 |
| 小对象被大聚焦框挡住 | 倒序命中只返回最上层 | 记录重叠候选，第二栏「切换重叠」按绘制顺序循环 |
| 文字画完还要再点工具 | `addText` 不改变工具与选择 | 文字落定后切到选择工具并选中新对象 |
| 选择工具下无删除入口 | 样式面板对 `SELECT` 直接 return | 选中时面板按对象的工具渲染，并追加「删除标注」 |

另外取消/多指中断现在丢弃半次变换（`dragging` 只在超过系统 slop 后置位）。

## 4. 数据协议

新增 `ScreenshotDocument.kt` / `ScreenshotDocumentCodec.kt`（纯数据，无 View/Bitmap）：

```text
ScreenshotDocument
  canvasWidth / canvasHeight        截图原始画布
  viewport (l,t,r,b)                本记录显示的选框（画布坐标）
  objects[]                         ScreenshotDrawingStroke（含稳定 id、点列、样式、文字、序号）
  text?                             blocks[] / translation[] / mode / translated
    block: (l,t,r,b,text,origin?)    origin 为被移动前的矩形，用于遮盖原位置
```

约束（`ScreenshotDocumentSmoke` 覆盖）：
- 版本号必须为 1，未知版本直接拒绝，绝不按空工程覆盖；
- 画布 1–20000，视窗必须落在画布内且至少 1px；
- 对象 ≤4000、总点数 ≤400000、文字 ≤400000 字符、文字块 ≤2000；
- 对象 id 必须为正且唯一，解码后推进全局计数器，重开后再加对象不会撞号；
- 只白名单字段，未知字段丢弃。

对象 id 在 `ScreenshotDrawing` 入历史时一次性分配；`equals` 不比较 id，
因此样式/几何派生对象不会因为 id 不同而“变成另一个对象”。

## 5. 存储（index v2）

```text
index.json  version 2: { id, createdAt, width, height, bytes, kind, revision }
旧记录（v1）  <id>.png + <id>.webp                       kind=IMAGE，永久兼容
新记录（工程）projects/<id>/source.png                   未改动的底图
             projects/<id>/<revision>/composite.png       成品
             projects/<id>/<revision>/thumbnail.webp      列表缩略图
             projects/<id>/<revision>/document.json       对象文档
```

- **索引是提交点**：先写完一个完整修订目录，再原子写索引；失败只留自己的临时目录并回收。
- **旧修订**只有在新索引提交后才删除；删除记录先移除索引再清文件。
- **并发保护**：编辑会话记住打开时的 revision，保存时比对当前 revision，不一致报
  「这张图片已被修改，请重新打开后再保存」，不会用旧编辑覆盖新保存。
- **限额**沿用 100 条 / 128 MiB，bytes 计入底图+当前修订；更新不重复计旧修订。
- `file(id)`/`thumbnail(id)` 统一按已提交索引解析修订；`ContentProvider` 仍只导出合成 PNG，
  分享临时文件仍是固定快照，底图与 document.json 不可从外部取得。
- 裁剪另存：同一画布、对象不变、视窗平移后作为**新记录**写入，原记录与其修订不受影响。

## 6. 编辑器重开入口

```text
preview/app.mjs  「编辑」→ nativeIme.screenshotEdit(id)
VoxFixImeService 校验 id/存在/服务可用 → 主线程 post
ScreenshotEditorHost   由 ScreenTextService 注册的唯一出口
ScreenTextService      worker 解码底图与文档 → 主线程建 ScreenshotCaptureOverlay
                       视窗固定、对象与文字已装回；保存走同一 revision 链
完成后                  回写 globalThis.voxfixImageSaved(saved) → 列表刷新 + URL 加 epoch
```

- 服务不可用（无障碍未启用）时不打开窗口，返回错误并**保留图片预览**。
- 已有工程：`replaceId` = 原 id、`expectedRevision` = 打开时的修订；
  旧 PNG：`copySourceFromId` = 原 id，首次保存生成**新**工程记录，原图保留。
- 编辑会话空闲超时不会像普通截图那样被转成纯文字面板。

## 8. 未验 / 边界

- **真人手指**：所有触摸结论来自 `dispatchTouchEvent` 注入与控件 `performClick`，不是真手指；
  手感（拖动跟手、角柄命中率、文字块拖动精度）仍需用户实测。
- **跨应用与强杀恢复**：保存后退出输入法、杀进程再重开图片列表这一路径未实机走查。
- **插入聊天**：仍取决于宿主是否接受 `image/png`，未在真实聊天应用验证。
- **框外绘制**在选框外的部分会被选择遮罩压暗但依然可见，未按官方截图工具做逐项对照。
- 译文层按段落重排，不支持块拖动（会提示「改回原文后可拖动」）。
- `screenshot-toolbar`（工具条设置编辑器的拖放注入）在本轮之前即失败于
  `DragEvent.obtain` 反射断言，与截图编辑链路无交集，未改动。
- `app.mjs` 2332 行 / 205 KB，已过 2200 行预警线（红线 3000 行未触）。本轮新增约 40 行，
  若继续增长需按 `docs/模块边界与拆分策略-2026-10-26.md` 处理。

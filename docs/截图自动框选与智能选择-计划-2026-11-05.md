## 一、机制 A：自动筛选（AutoFilter）——纯像素，零模型

### 上游证据（已全部取到本地 `.android/snow-auto-region/reference/`，24 份 + SOURCES.txt）

| 文件 | 内容 |
|---|---|
| `visual-region-detector` crate（lib/pipeline/selection/geometry/grid/mask/model/color + `backend/pure_rust/{mod,canny,contours,median,morph,align}`） | 检测算法本体，纯 Rust 手写，OpenCV 只是可选后端 |

| `screenshotintelligentselectionmodel.{h,cpp}` | 机制 B 用（见下） |

### 已核实的上游语义
- 算法链：BGR888 → 背景/表面估计 → 前景掩码 → 媒体检测（图/头像/logo/纹理/徽章）→ 文字行（抑制媒体区）→ 合并 → NMS(0.8) → 排序；输出 7 类：`text / text_in_box / image / avatar / icon / message_box / text_block`。
- 交互：滤镜工具的三变体之一（矩形/画笔/**自动筛选**，`filterToolFromSetting`）；选中即检测，扫描光带 1400ms 循环渐变（64,150,255 系）；完成后红框 #FF4D4F + 红底 51α 闪烁；**点区域 = 把当前马赛克/模糊样式涂到该区域**（与矩形/画笔滤镜共用 FilterEditor）；`fillCategory` 按类别一键全涂（隐私打码主场景）；识别绑定来源画布 bounds，变化即失效重测。
- 结果可复用：canvas 缓存 `autoFilterRegions`（`record->sourceBounds` 比对）。

### 手机四块计划（按「做完一个再动下一个」推进）
1. **图像原语移植**：`grid/geometry/color/mask` + `pure_rust` 六文件 → Kotlin 纯函数；用上游 `opencv_fixtures.json` 契约数据建 JVM 逐值对拍单测。
2. **pipeline 移植**：`surfaces/media/text/icons/selection` + `pipeline.rs` finalize；用构造图像对拍 `tests/contracts.rs` 语义。
3. **UI 接线**：滤镜工具加「自动筛选」变体（工具面板取原图标）→ 扫描动画 → 红框闪烁 → 点区域应用滤镜 → 按类别填充；识别结果缓存与 bounds 失效语义照搬。
4. **性能与真机**：大图降采样策略（先测再定，不牺牲关闭释放）；全套件 + 数据摘要不变 + 真人走查。

## 六、手机触屏交互设计（无滚轮、纯手指）——2026-11-05 补

设计原则：原版所有「悬停/滚轮」语义一律改为「点按 / 长按 / 拖动」，改动处逐条写明差异（沿用 T11 面板「悬停→点按」的先例）。

### 机制 A（自动筛选）触屏方案
- 工具条：滤镜槽位长按弹出三变体（矩形/画笔/自动筛选），点选切换（原版是设置里切换+悬停预览）。
- 选中「自动筛选」即自动检测（无需额外触发键），扫描动画/红框闪烁照搬。
- **点区域 = 涂当前马赛克/模糊样式**（与原版一致，无滚轮影响）。
- 按类别填充：原版在滤镜编辑器里有类别按钮；手机在工具参数栏加一行类别 chips（文字/图片/头像/图标/气泡），点一下全涂。差异：入口从编辑器移到参数栏。

### 机制 B（智能选择）触屏方案（候选，取证后定稿）
- 上游是鼠标悬停逐层高亮 + 点按选中。触屏没有悬停，候选映射：
  1. **按住即高亮**：手指按下显示最深层命中框，**原地停顿或向内点按 = 深入一层，向外拖出 = 回退一层**，松手选中当前层；
  2. 拖动超过阈值 = 转手动框选（沿用上游 shouldStartManualDrag 阈值语义）；
  3. Window / WindowSubElement 两档用长按切换（原版是键/菜单切换）。
- 与现有手势冲突的处理：作为「选择」工具的独立模式（原版 Move/Select 工具族的一员），不与 MARQUEE 框选混用。
- ⚠️ 以上为候选设计，**必须先取证桌面 selector 层 hit path 组装再定稿**，且交互定稿前给多弗朗确认一次。

### 无滚轮波及的其他点
- T11 比例按钮原版滚轮±5 已改点按（已做）；吸附距离等数值调节一律点按步进或滑杆，不引入滚轮语义。

## 七、已知隐患与待验证问题（2026-11-05，移交下个 agent 逐条核销）

1. **MOVE 吸附修正可能把元素推出画布**：ScreenshotSelection.moveX/moveY 先做画布夹取，吸附 delta 是之后加上的，没有二次夹取；上游引擎层是否有边界再约束未取证。真机验证时重点看拖到画布边缘。
2. **RESIZE 两遍法在翻转/最小尺寸下可能错位**：第二遍用修正后指针重算 geometry，若 alt 翻转或触到最小尺寸使 scale 符号翻转，第一遍算的 signX/signY 与第二遍不符。设备套件 selection-resize 需覆盖。
3. **导线绘制层级未取证**：手机把 snap 导线画在选择框之下（draw() 先画导线）；上游 Qt 渲染层级未取证，marker 样式也未取证未画。
4. **吸附配置只在 layer lazy 时读一次**：改 SharedPreferences 后不重读；开关 UI 落地时需加失效机制（重建 layer 或通知刷新）。
5. **设备套件未跑**：吸附默认关，理论行为与基线一致，但 selection-resize/selected-tools 套件有按子视图下标取按钮的前科（§选择动作族踩过），装机后必须全套件复跑。
6. **机制 B 的 hit path 组装完全未取证**：桌面 selector 工作流（screenshotselectorworkflow / screenshotselectorserviceclient）没拉，层级顺序、去重、窗口枚举方式都不知道，不能凭 model 文件就开始写。
7. **上游 bindables 进集规则未取证**（§43 遗留）：snow-draw-engine-model 决定哪些元素可被绑定，当前默认排除箭头/直线，已标注待核对。

## 八、手机方案、实现和验收顺序（2026-11-05）

录像约 26.7 秒。5.6 秒高亮内容区，10.0 秒高亮整个窗口，18.9 秒高亮一段文字，21.1 秒确认文字行后工具条出现在选区附近。悬停时周围变暗、选区保持原亮度，光标旁可见放大镜。取样证据在 `.android/snow-auto-region/contact.png`。录像用于智能选择的对照。

### 1. 智能选择

- 固定提交核对 `snow_shot/src/presentation/selector/screenshotselectorworkflow.cpp`、`screenshotselectorserviceclient.cpp`、`snow-crates/crates/snow-ui-selector/src/windows/uia/cache.rs` 和 `cache_tests.rs`。原版命中最上层窗口，返回最深元素至最外层窗口的路径。候选与画布求交，连续相同的框去重。
- 原版无触屏长按分流，以下是手机侧实现。矩形截图初始默认选元素，轻点预览并松手确认。已有选区也能继续轻点换目标，点框内则沿命中路径取完全包含在当前框内的最深子元素，即使大框来自窗口模式。从窗口收进元素后切回元素档，便于继续点按切换相邻元素。框内没有更小的候选时保留原框。按住到 Android 长按阈值后滑动，蓝框和避开指尖的放大镜跟随命中。未达到长按阈值就拖过触摸阈值时，按起点进入拉边、移框或手动新建。多指取消智能预览。模式和可用层级操作以 48dp 图标触区集中在底部，空间冲突时避开选区和主工具栏。智能命中时主栏默认靠底，留出选区附近的内容供连续点按。
- 截图请求前只提取 Android 无障碍窗口和可见节点的矩形。成功回调核对窗口 ID、顺序、边界与窗口状态事件，再把几何交给冻结图。当前 App 没有暴露细粒度节点时，仍能选可用的窗口或直接手动框选。树与像素为两次系统请求，同一窗口内容在两次请求之间变化时仍可能错位。窗口快照和截图会话同生命周期，不记录节点文字、节点对象或界面历史。
- K60 复现了一个无障碍文字控件覆盖多段、短行后方留白的情况。原版 Windows selector 以更深的 UIA 元素补全命中路径。Android 增加手机侧像素定位，复用已打包的 ML Kit 中文检测器，从冻结截图后台提取行框，并在检测块内按实际行距拆出段落候选。命中路径可按文字行、段落、控件、窗口逐级选取。只保留当前截图的几何，未命中文字时仍可命中控件。首次点按早于定位时，只重算当前会话最近一次有效的智能点按。[ML Kit 文字定位](https://developers.google.com/ml-kit/vision/text-recognition/v2/android)

### 2. 自动筛选

- 使用原版纯 Rust 检测器与 C ABI，锁定 Git 提交、归档 SHA-256 和 Cargo 依赖。按原始像素裁出当前选区，在后台检测并以选区范围缓存。当前打包目标是 ARM64，首次构建需要 Rust/Cargo、`aarch64-linux-android` 目标与仓库原有 NDK。
- 原版无手机工具参数栏，以下是手机侧实现。在马赛克／模糊参数栏直接切换「矩形／画笔／自动筛选」，不用另开设置。扫描光带周期 1400 ms，结果红框闪现 300 ms。点按取面积最小的命中框，拖过多个框则处理相交结果，七类按存在的检测结果显示。点同一滤镜已处理区域会切换为取消填充，按类别填充为一次撤销。打码对象写入工程并进入常规导出。
- 原版换选区时重置自动填充。手机只重测候选，保留之前的打码，避免扩大或移动选区时露出已处理区域。检测结果在会话内复用，工程仅保存已填充的对象。超过 1600 万像素的选区提示检测失败，可缩小选区重试。手机速度和大图内存占用需实测。

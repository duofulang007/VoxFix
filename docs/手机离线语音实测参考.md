# K60 手机离线语音识别选型与实测参考

日期：2026-10-11。用户要语音转文字（ASR），不是文字转声音（TTS）；目标为中文准确、轻声响应、边说边出字、松手快完成、全离线。本轮只查资料、核对指定本地文件和源码，不安装、不换模型、不录音。

## 用户手机与当前项目

- 用户提供的参数截图：Redmi K60，第一代骁龙8+移动平台，最高3.0GHz，16.0+16.0GB，Android 15，OS 3.0.8.0.VMNCNXM。选型按16GB物理内存计算；扩展内存使用存储，不能当成32GB物理内存或双倍推理算力。[小米内存扩展说明](https://www.mi.com/global/support/faq/details/KA-541717/)
- 已核对本地文件 `models/polish/Qwen3.5-2B-Q4_K_M.gguf` 存在、GGUF 文件头、大小1,280,835,840字节；下载脚本固定来源与SHA-256，本轮未重新计算全文件摘要。
- 当前 Qwen3.5 是文字整理模型。`NativePolisher.kt` 只接转写文字；`polish.cpp` 为CPU、4线程、每次加载和释放。`MainActivity.kt` 调用它，`VoxFixImeService.kt` 未调用它。不能通过换提示词让这条文字接口直接听懂录音。
- 既有真机记录：20字的一次整理11.639秒，changed=false；另一次固定文本27.266秒仍有“然后然后”。这些是历史指定场景，不是平均性能，也不证明每次回退都由保护规则造成。见《USB真机验收》129行、《手机端大模型框架》77行。
- 当前ASR固定来源见 `tools/setup_voice.py`：中英流式 Zipformer mobile 2023-02-20、Paraformer small INT8 2024-03-09、CT-Transformer 标点 INT8 2024-04-12。已有实时输入和指定跨App/断网验收应保留作基准。

## 已核实的可部署候选

以下为可行性与试验顺序，尚未在本机比较。权重文件大小不等于运行内存；上游桌面RTF不等于K60首字或松手延迟。

| 候选 | 已核实版本或形式 | 对本项目的意义 | 边界与建议 |
|---|---|---|---|
| 中文流式 Zipformer INT8 | `sherpa-onnx-streaming-zipformer-zh-int8-2025-06-30`，普通版三文件154M+4.9M+1.0M | 原生 OnlineRecognizer，最直接比较新的中文流式模型，同时保持边说边出字 | 官方标注Chinese；不能假设保留现有中英能力。先对比普通版，xlarge的726M encoder不优先。接入须核对模型类型、分块、词表，不能只改文件名 |
| SenseVoiceSmall INT8 | 原始2024-07-17版本，model约228MiB（约239MB） | 同一sherpa-onnx框架已有Android示例，适合比较短句或结束后二遍，支持中英日韩粤 | 核心为非流式；Android实时示例使用分段/模拟流式。优先作为替换二遍的候选，不立即替换整个流式入口 |
| Qwen3-ASR 0.6B INT8 | 2026-01-29公开模型；sherpa ONNX包2026-03-25，三ONNX共约1GB | 真正接收音频的语音模型，可评测方言、口音和中英混说；已有Android ARM64测试包 | 与现有Qwen3.5整理模型不同；sherpa路径为OfflineRecognizer/模拟流式。官方Python原生流式入口依赖vLLM，不能直接等同Android能力。16GB容量具备试验条件，但没有本机速度结论 |
| Fun-ASR-Nano | 2512 / 800M，sherpa提供INT8 Android包 | 新一代语音大模型候选，官方覆盖中英日及中文方言口音 | 不因“Nano”推断比SenseVoice更快；安卓示例仍归在非流式/模拟流式页。本轮后置，避免一次比较太多模型 |
| FireRedASR2 | Android列表有 `fire_red_asr2_ctc_int8_2026_02_25` | 可用于离线中文识别对照 | 应区分CTC移动部署形式、1B+ AED及8B+ LLM；论文8B版精度不能当成CTC手机版结果。本轮不推荐把大版本直接用于实时键盘 |

### 为什么普通话不直接追SenseVoice最新日期

2025-09-09版本来自ASLP-lab的粤语微调，使用21.8k小时粤语数据，并不支持标点。sherpa维护者在2026-04-12明确建议：不专注粤语不要切换，普通话使用旧模型。模型日期与手机框架版本要分开看。[版本说明](https://k2-fsa.github.io/sherpa/onnx/sense-voice/pretrained.html)、[维护者原始回复](https://github.com/cjpais/Handy/discussions/1274)

## 适合当前目标的决定

1. 保留已验收的流式链路作基准。若主要普通话，第一项比较2025-06-30普通版中文流式Zipformer；英文名和中英混说必须纳入检查。
2. 第二项比较SenseVoiceSmall INT8替换现有二遍是否更准确、更快；避免增加成第三遍、把等待叠加。
3. Qwen3-ASR 0.6B INT8作为质量候选，只有实际减少错字且结束时间、发热可接受才接入，不因名称“千问”或榜单自动替换。
4. 现有Qwen3.5对“准确、快速的语音输入”不是必需项。已经下载可保留作主动文字整理，不默认每句执行；本轮不删除或更换任何模型。若未来做精简、改写或翻译，再单独衡量其价值。

先用同一批固定短句对照首字、文字更新间隔、松手到提交、中文字符错误、数字/否定/专名及中英混说，再看连续使用的内存和发热。只记录性能与固定测试结果，不收集日常录音或转写。由用户实际完成手机说话和手感验收；没有此结果不能称新模型已满足全部需求。

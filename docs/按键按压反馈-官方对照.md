# 按键按压反馈：与讯飞小米版逐像素对照

日期：2026-10-13。对照对象是手机上已安装的 `com.iflytek.inputmethod.miui` 8.1.8322（K60，1440×3200，560dpi）。
本文件只记录"按下瞬间长什么样、怎么实现的"，不改动任何已确认的交互结论。
可交互自查页：[按键按压对照.html](按键按压对照.html)（浏览器直接打开，可按住对比官方 / 改前 / 改后三条）。

## 一、三条结论

1. **官方按下态不是"变蓝"，是往键盘底上盖一层 45% 的中性冷灰。**
   我们原来的 `#c1d5e5`（rgb 193,213,229）比官方蓝得多、也深得多（ΔR −28、ΔG −12、ΔB −3），
   所以观感像"这一格被选中了"，而不是"这一格被我按下去了"。这是"不像真的按下去"的主因。

2. **官方按压是原生 state drawable 直接换图：没有过渡、没有缩放、没有位移。**
   按下 0 延迟、松手 0 延迟。"跟手感"来自三点叠加：瞬时变色 + 颜色对比够明显 + 按键振动/音效。
   所以我们不需要给按键加动画；要做的是把颜色对准、把延迟和残留清掉。

3. **"颜色迟迟退不走"不是动画慢，是 `:active` 粘连。**
   原规则把两个状态写在一条里：`.key-row .key:active,.key-row .key.pressed{background:#c1d5e5}`。
   `.pressed` 是我们自己加的、松手一定删；而 `:active` 在 Android WebView 上清除不可靠
   （首次触摸还会被当成 hover 起点，且不保证什么时候退），于是视觉上"松手了颜色还在"。

## 二、官方证据（可直接复现）

手机上的官方包：`pm path com.iflytek.inputmethod.miui` →
`/data/app/~~RllROgWQW88ArvGz8B-dmA==/com.iflytek.inputmethod.miui-iqYZErSapJ8cksLLfGZMIw==/base.apk`（65,003,596 B）。

主题由 ini 驱动，K60 上生效的是**白皮**：`assets/theme/white/config-1080/image.ini` 里
`Image6 → btn_keyboard_key_normal.png`、`Image7 → btn_keyboard_key_pressed.png`，两者都是 `Scale=33,33,33,33`
（66×66 的 9-patch，四边各 33px 不拉伸，即只有圆角参与缩放）。

抽出来的 5 张关键图，逐像素统计主色：

| 资源 | 尺寸 | 主色 | alpha |
| --- | --- | --- | --- |
| `btn_keyboard_key_normal.png` | 66×66 | `#FFFFFF` | 255（不透明） |
| `btn_keyboard_key_pressed.png` | 66×66 | `rgb(202,208,220)` | 115 |
| `btn_keyboard_func_key_normal.png` | 66×66 | `rgb(202,208,220)` | 115 |
| `btn_keyboard_func_key_pressed.png` | 66×66 | `rgb(197,203,212)` | 203 |
| `btn_symbol_key_pressed.png` | 66×66 | `rgb(212,220,230)` | 204 |

**关键推论**：功能键*常态*和字母键*按下*是同一个 45% 冷灰。
⇒ 这些图是**直接叠在键盘底色上**，不是叠在白色键帽上。官方键盘底是 `#EDEFF2` = rgb(237,239,242)。

于是官方按下态在屏幕上真正显示的颜色是：

```
0.451 × (202,208,220) + 0.549 × (237,239,242) = rgb(221,225,232)   ← 字母键按下
0.796 × (197,203,212) + 0.204 × (237,239,242) = rgb(205,211,218)   ← 功能键按下
```

三处独立交叉验证（都在 `docs/recording-frames/`、`preview/reference/` 的原始截图上量）：
官方截图的**功能键常态** = rgb(221,225,234)、**键盘选择页选中底色** = rgb(221,226,232)、
**深色态功能键按下** = rgb(201,208,216)。与上面算出的值一致（截图是 JPEG，有 ±2 漂移）。

## 三、官方 vs 我们

| 项目 | 官方（白皮） | 改前 | 改后 |
| --- | --- | --- | --- |
| 字母键常态 | `#FFFFFF` | `#FFFFFF` | 不变 |
| 字母键按下 | `rgba(202,208,220,.451)` → 屏幕 **rgb(221,225,232)** | `#c1d5e5` → rgb(193,213,229) | 同官方 |
| 功能键常态 | 等效 rgb(221,225,232) | `#dce0e7` → rgb(220,224,231) | 不变（本来就已对齐） |
| 功能键按下 | `rgba(197,203,212,.796)` → 屏幕 **rgb(205,211,218)** | `#c7dbea` → rgb(199,219,234) | 同官方 |
| 过渡动画 | 无 | 无 | 无（回归里断言 `transition-duration: 0s`） |
| 缩放 / 位移 / 气泡 | 无 | 无 | 无 |

网页与原生皮肤原来各写了一份按下色（`#c1d5e5` / `#c7dbea`），互相还不一致。现在两处共用同一组令牌。

## 四、改了什么

- `preview/style.css`：新增 `--key-press: rgba(202,208,220,.451)` 与 `--func-press: rgba(197,203,212,.796)`；
  按下态只由 `.pressed` 驱动，`.key` 上的 `:active` 全部删除（九宫格同理）。
  用半透明覆层而不是算好的实色，是为了**在结构上就等价于官方**——叠在 `--kb-bg` 上自动得到正确等效色。
- `preview/native-ime.css`：删掉原来单独覆盖的 `.keyboard .key.pressed{background:#c7dbea}`，与网页共用令牌。
- `preview/app.mjs`：新增 `clearKeyPress()`。
  - `pointerdown` 时先清残留（上一次按压若没退干净，这一次按下会先自愈）；
  - `endGesture` 收尾统一清（不再只清 `g.target` 那一个节点，节点在重绘后可能已经不是同一个）；
  - 丢事件兜底：`lostpointercapture` / `window.blur` / `visibilitychange`。
    失焦只清视觉，不动正在进行的语音与光标手势。

## 五、验证

- 新增 `preview/key-press.test.mjs`，网页态与原生态各跑一遍：按下覆层的 RGB/alpha、按下等效色、
  松手立刻回白、同帧只有一个按下态、连点 12 次不残留、残留会被下次按下清掉、失焦后能自愈、
  按下与松手都在同一次事件派发内完成（即 0 延迟）、按键 `transition-duration` 必须是 `0s`。
- 真实渲染取证：在真实键盘上按住一个 Q，截图取像素，实测命中 **rgb(221,225,232) 共 6218 px**
  （键面 70×100 设备 px，与 Q 键尺寸吻合）；功能键按下实测 **rgb(205,211,218)**。
  改前的对照图命中 `rgb(193,213,229)` / `rgb(199,219,234)`，与旧值一致。
- 既有套件：`core` / `fixed-layout` / `pinyin` / `english` / `candidates` / `workflow` / `voice` /
  `voice-orb` / `native-ime` / `ime-regressions` 全绿。
  （`live.test.mjs` 需要 127.0.0.1:18743 上的桌面润色服务，与本次改动无关。）

## 六、官方还有、本次没动的部分（等你定）

- **按键振动**：官方默认开，桥里现成有 `VoxFixIme.haptic()`（`KEYBOARD_TAP`，不需要 VIBRATE 权限，
  自动跟随系统触感总开关）。目前只在滑轨切框选时调用。若也要 1:1，就在按键按下时一并调用。
- **按键音效**：官方有键盘音效与音量设置，我们没有。
- **长按放大气泡**（`btn_keyboard_key_pop.png`，170×180）：之前已明确去掉，本次不恢复。

## 七、边界

- 本次改的是网页与打包进 APK 的前端资源；真机手感属于物理确认，装机后仍需你自己按一下才算通过。
- 上面的"官方值"来自已安装 APK 的资源与真实截图，不是官方源码；主题不同（深色皮、其他品牌皮）取色会不同。

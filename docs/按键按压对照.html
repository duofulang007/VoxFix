26 键按压反馈：官方 / 改前 / 改后

按住下面的键试试。官方那一条与「改后」是同一个颜色模型，改前那一条是原来的高饱和蓝。

官方取值来自手机上已安装的 com.iflytek.inputmethod.miui 8.1.8322：assets/theme/white/res/image/btn_keyboard_key_pressed.png = rgb(202,208,220) / alpha 115，官方键盘底 #EDEFF2。

1:1 目标

官方 讯飞小米版（白皮）

按下 = 往键盘底上盖一层 45% 中性冷灰。
无过渡、无缩放、无位移。

覆层rgba(202,208,220,.451) 屏幕等效rgb(221,225,232) 按下耗时—

功能键常态就长这样，按下再深一档 rgb(205,211,218)。

改前

VoxFix 原实现

按下色写在 :active 与 .pressed 的同一条规则里。

字母键按下#c1d5e5 → rgb(193,213,229) 功能键按下#c7dbea → rgb(199,219,234) 残留0 个键

比官方更蓝更深（ΔR −28），读起来像「被选中」而不是「被按下」。

改后

VoxFix 现在

按下只由 JS 的 .pressed 驱动；:active 已从按键上删除。

覆层rgba(202,208,220,.451) 屏幕等效rgb(221,225,232) 松手后残留0 个键

自愈：下一次按下会先清掉上一次的残留；失焦、指针捕获丢失也会清。

—

为什么原来会「颜色迟迟退不走」

  • 原规则：.key-row .key:active, .key-row .key.pressed { background:#c1d5e5 } —— 两个状态挤在一条里。
  • .pressed 是我们自己加的，松手一定删得掉；:active 是浏览器管的。
  • Android WebView 对 :active 的清除不可靠：第一次触摸还会被当成 hover 的起点，且没有确定的退出事件，于是松手了颜色还挂着。
  • 点上面的「演示」按钮可以看这个残留长什么样 —— 这是把 WebView 的行为搬到桌面复现，不是桌面浏览器本身的行为。

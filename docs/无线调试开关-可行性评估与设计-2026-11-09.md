# 无线调试开关：可行性评估与弧柄方案设计（2026-11-09）

配套动效稿：[无线调试开关-弧柄动效稿-2026-11-09.html](无线调试开关-弧柄动效稿-2026-11-09.html)（浏览器打开，可直接点按体验开/关与失败态）。

结论先行：**能做成「右侧弧柄一键开关 + 图标动效表达状态」，但不能做成「零授权的纯第三方开关」，也不能做成「桌面小组件动效」。** 三条硬约束分别是权限、Wi-Fi 前置条件、RemoteViews 能力。本机已实测，证据在第 2 节。

---

## 1. 需求拆解与载体选型

需求实质是三件事：**(a) 不进入 App 页面就能切换**、**(b) 常驻在任意界面之上**、**(c) 状态用动效直接表达**。四个候选载体只有弧柄同时满足：

| 载体 | 一键切换 | 状态动效 | 新增权限 | 常驻任意界面 | 判定 |
|---|---|---|---|---|---|
| 桌面 AppWidget | 是 | **不可行**：RemoteViews 无 Animator / 无自定义 View，只能 ViewFlipper 2–3 帧硬切，刷新还受 launcher 调度（HyperOS 实测量级 1–3s） | 无 | 否（只在桌面） | 排除 |
| 桌面快捷方式图标 | 是 | **不可行**：图标是静态资源，只能整体换图并等桌面刷新 | 无 | 否 | 排除 |
| 快捷设置磁贴 TileService | 是 | 受限：仅 `Tile.icon` 的 AnimatableVectorDrawable，系统/ROM 决定是否播；API 34 才有 `subtitle` | 无 | 是（下拉） | 可作可选第二入口 |
| **无障碍悬浮弧柄（现有 `ScreenTextHandle`）** | 是 | **完全可控**：自绘 Canvas + ValueAnimator，逐帧控制 | **0**（无障碍已绑定，`TYPE_ACCESSIBILITY_OVERLAY` 免 SYSTEM_ALERT_WINDOW） | 是 | **采用** |

补充：`preview/` 里的键盘前端也能放入口，但那是"进 App"路径，与需求 (a) 冲突，不做主入口。

## 2. 真机实测（2026-11-09 09:52–09:58，K60 / Android 15 / HyperOS V816）

测试只读 + 可逆写入，结束后已恢复原状（`adb_wifi_enabled=0`、Wi-Fi 关闭）。

| 序号 | 操作 | 结果 | 结论 |
|---|---|---|---|
| E1 | 读初始态 | `adb_enabled=1`、`adb_wifi_enabled=0`、`development_settings_enabled=1`、`wifi_on=0` | 目标键就是 `Settings.Global.adb_wifi_enabled` |
| E2 | Wi-Fi 关闭时 `settings put global adb_wifi_enabled 1` | 命令 `rc=0`，但值仍是 `0`；logcat：`AdbDebuggingManager: Not connected to any wireless network. Not enabling adbwifi.` | **写入被框架静默回滚**，必须先连 Wi-Fi |
| E3 | 连上 `HRW-新2楼-5G`（192.168.2.40）后同一条写入 | 值稳定为 `1`，`ss -ltn` 出现 adbd 监听 `*:41607` | 写入链路成立，可编程开关 |
| E4 | 读端口：`getprop service.adb.tcp.port`、`settings get global adb_wifi_port` | 均为空 / `null` | **端口无法从属性或设置读到** |
| E5 | PC 侧 `adb mdns services` | 发现 `_adb-tls-connect._tcp 192.168.2.40:41607` | 端口交给 PC 侧 mDNS 发现，手机端不必暴露 |
| E6 | 权限定义 | `WRITE_SECURE_SETTINGS: prot=signature|privileged|development|installer|role` | 含 `development` 位，`adb shell pm grant` 可授予 debuggable 包 |
| E7 | `adb connect` 验证 | 超时（PC 在 192.168.1.4、手机在 192.168.2.40 跨网段） | 配对链路**本次未验证**，实施前需同网段补测 |

> E2 是本方案最重要的实测：**任何"乐观置位"的 UI 都会撒谎**。写入必须回读确认（见 4.3）。

## 3. 权限与授权模型

### 3.1 必须的一步

`WRITE_SECURE_SETTINGS` 属 `signature|privileged|development`，第三方无法自取。一次性授权，卸载重装失效，重启与覆盖安装均保留：

```
adb shell pm grant local.voxfix.debug android.permission.WRITE_SECURE_SETTINGS
```

授予后系统会重启该应用进程；弧柄随无障碍服务重连复活，无需额外操作。本项目已有 PC 侧 adb 通道（`tools/voxfix_phone_companion.py`），这条命令可以直接由伴生工具代跑，不必让用户手敲。

### 3.2 没有授权时的降级（必须有，不能做成死按钮）

按严重度从优到劣：

1. **跳转半自动**：`Intent(Settings.ACTION_APPLICATION_DEVELOPMENT_SETTINGS)` 打开开发者选项，用户点两下。零风险，稳定。
2. **无障碍代点**：弧柄所在的无障碍服务已能读屏，可定位文本「无线调试」并 `performAction(CLICK)`。能全自动，但依赖 ROM 文案与层级，HyperOS 升级即可能失效 —— 只做可选兜底，不进主路径。
3. **Shizuku**：提供 shell 权限，可 `settings put`。但 Shizuku 自身要靠 adb/无线调试启动，**重启后无线调试必然关闭 + Shizuku 已死 → 自举悖论**，恰好是最需要开关的时刻用不了。仅作为"已常驻 Shizuku 用户"的分支，不做默认。
4. **Root**：`setprop service.adb.tcp.port 5555` + 重启 adbd，端口固定最省事。设备未 root，不纳入。

## 4. 弧柄方案设计

### 4.1 塌缩态（24×64dp，几何不动）

弧线几何与**已安装版本完全一致**，不得镜像：`M21,18 Q15,32 21,46`（弧顶朝屏幕内，即"("形；真机实测中点比两端内收 3dp、端点距屏幕边 1.7dp、弧高 26dp）。待机 2dp / `idle` 色；**开启时改 2.6dp / `active` 色**，沿用 `HandleTone` 的"明度 + 线宽"双通道，与按下态同一套语言（按下是瞬时的，不会混淆）。

**不再在弧线下端加圆点**：实测 2dp 圆点落在弧线端头下方 2dp 处，在 24dp 宽的边缘读起来是"!"，会被误解成告警。手机侧扩展用"弧线本身变实变粗"表达更稳，也仍然不改几何。**这是手机侧扩展，原版 Snow Shot 无此行为，须在复刻记录里标注差异。**

### 4.1b 无线调试图标几何（48dp 按钮 / viewBox 48）

沿用弧柄现有按钮语言：实心圆盘 `#4A4A4A` @70%（按下 82%），白色描画。

| 元素 | 参数 |
|---|---|
| 圆盘 | 圆心 (24,24)，r=21 |
| 三段弧 | r = 7.5 / 11.5 / 16.5，圆心 (24, 30.15)，半角 55°（跨度 110°） |
| 弧线端点 | (17.86,25.85) / (14.58,23.55) / (10.49,20.68)，对称 |
| 圆点 | (24,30.15) r=2.2 |
| 外环（仅开启） | (24,24) r=17.6，1.1dp |
| 斜杠（仅关闭） | (11.5,11.5) → (36.5,36.5)，2.2dp |

**居中不是把 bbox 摆正就行**：wifi 图形天然下重（弧宽在上、点在下），bbox 居中后会读成"偏下"。圆心取 30.15 而不是 31.65，等于把图形整体上提 1.5dp 做光学补偿 —— 实测量法：外弧顶点距盘顶 10.65、圆点底距盘底 12.65，视觉才平衡。

### 4.2 展开态几何（需要动版，差异须记录）

现状两枚：`close` 在弧心、`full` 在半径 52dp 的正内侧。加第三枚必须扩面板，否则两枚 48dp 按钮会重叠（±24° / r=52 时中心距仅 42.3dp）。

推荐参数：

| 项 | 值 |
|---|---|
| 面板 | 112×200dp（原 104×144） |
| 按钮 | 48dp ×2（截图 / 无线调试） |
| 半径 | 60dp（原 52） |
| 角度 | 截图 +30°、调试 −30°（中心距 60dp > 48dp，不重叠） |
| 弧心 | 与塌缩态中点重合（面板向上、向下各扩 28dp） |
| 关闭圆 | 仍在弧心，48dp |

**实现陷阱**：现在 `render()` 用 `originY = collapsedY + dp(32) - params.y` 隐式推导弧心。面板变高后 `clamp()` 在屏幕上下边缘会平移窗口，这个隐式式子的结果就不再是真实弧心 → 靠近底部呼出时按钮错位。必须改成显式 `arcCenterY`（屏幕坐标），`prepareMenu()` 里 clamp 之后重新计算。

### 4.3 状态与交互流程

```
点击「无线调试」
  ├─ 未授权  → 打开开发者选项（4.2 降级 1），图标不做状态变化
  ├─ Wi-Fi 未连 → 抖动 + 提示「需先连 Wi-Fi」，不写
  └─ 已授权且 Wi-Fi 在线
       写入 250ms 后回读，最多 5 次（1.2s）
       ├─ 值变化符合预期 → 播开/关动效 + 触感
       └─ 值回滚 → 抖动 + 提示原因（NO_WIFI / NO_DEV_OPTIONS / REVERTED）
```

状态同步 **不能只靠点击**：无线调试会被系统自行关闭（断 Wi-Fi、重启、开发者选项关闭、系统超时）。弧柄需同时挂：

- `ContentObserver(Settings.Global.getUriFor("adb_wifi_enabled"))`
- `ConnectivityManager.NetworkCallback`（Wi-Fi 丢失 → 立刻置灰为关）

否则图标迟早说谎。图标永远画 **读回来的值**，不画"刚点下去的值"。

### 4.4 动效规格

时间尺度沿用现有 `PathInterpolator(.32,.72,0,1)`、展开 220ms / 收起 180ms。

**常驻形态（已按动效稿定稿）**：三段弧与底部圆点始终存在，关闭态压暗到 alpha 46% / 58%，斜杠只在关闭态出现。比"弧线凭空长出"更容易在任意壁纸上一眼认出这是 wifi，状态差异由 **亮度 + 斜杠有无 + 外环有无** 三重叠加，不靠色相。

**关 → 开（约 260ms）**

| 时间 | 动作 |
|---|---|
| 0–140ms | 斜杠 `strokeEnd` 回抽 0→1 并在 120ms 内淡出（"擦掉禁用线"） |
| 40 / 80 / 120ms 起 | 三段弧由内向外依次 alpha `.46→.95`（每段 160ms） |
| 0–260ms | 外环 scale 1.16→1、alpha 0→.42，之后进入 4s 呼吸 |
| 120ms | `HapticFeedbackConstants.CONTEXT_CLICK` |

**开 → 关（约 180ms）**：三段弧由外向内 0 / 20 / 40ms 依次压暗回 .46 → 斜杠在 100ms 后从中心向两端画出 → 外环 alpha→0，结束 `CLOCK_TICK`。

**写入中（≤1.2s）**：外环改 1.5dp 虚线，900ms/圈旋转，弧线整体压到 30%；不改变图标主体形状。

**失败**：整体 ±3dp 水平抖动 ×2（160ms）+ 外环加粗到 2dp 闪一次 + Toast 说明原因。**不用红** —— 弧柄是纯灰阶体系（`HandleTone` 三档），红色会破坏它在任意壁纸上的中性。

**省电**：所有动画只在被点击时或面板展开时运行；呼吸脉冲仅限"开启后 30 分钟"窗口内，且塌缩态用 300ms 低频脉冲，不常驻重绘。

### 4.5 无法做到的两件事（必须在文案上诚实）

1. **读不到端口**（E4）。手机端只能当"闸门"，不能当"连接器"。PC 侧用 `adb mdns services` 自己发现端口（E5），这一步已经在现有伴生工具的能力范围内。
2. **感知不到"是否有主机正在连着"**。`dumpsys adb` 需要 shell 权限。所以"空闲自动关"只能按时间做，不能按连接做。

## 6. 技术障碍清单

按"会不会让方案作废"排序：

1. **无公开 API**，唯一入口是 `Settings.Global.adb_wifi_enabled`，属实现细节，Google 不承诺兼容。已在 Android 15 实测通过；Android 16 若改键名需重测。
2. **`WRITE_SECURE_SETTINGS` 必须一次性 adb 授权**。无授权 = 方案降级为"跳设置页"。卸载重装丢失。
3. **Wi-Fi 未连接时系统静默回滚**（E2 已证）。写 UI 必须回读，且失败要给原因，不能"点了没反应"。
4. **端口随机且不可读**（E4）。每次开启端口都变，且首次需 `adb pair`（6 位配对码，在当前设备上 `is-wifi-qr-supported=true`，可扫码配对）。弧柄不解决"配对"，只解决"开关"。
5. **重启后自动关闭 + 断 Wi-Fi 自动关闭 + 系统超时关闭**。图标必须被动同步，否则状态不可信。
6. **开发者选项关闭时全链路失效**（`development_settings_enabled=0` 时写入无效）。需单独识别并提示。
7. **HyperOS 差异**：已观测到"命令成功但值回滚"；另 QMS/后台策略可能回收无障碍服务导致弧柄消失（当前 `dumpsys accessibility` 的 `Binding services` 为空，即此刻未绑定）。弧柄不在 ⇒ 入口不在，这是本方案唯一的架构性依赖。
8. **安全面**：开启后局域网暴露 adbd 端口，任何持有已配对密钥的主机可连。建议默认 30 分钟自动关闭，并在开启时给出可见提示；不建议做成"常开"。
9. **桌面小组件动效不可实现**（第 1 节）。若坚持桌面形态，只能做静态状态图标 + 点击切换，动效为零。
10. **崩溃隔离**：写设置抛 `SecurityException` 必须就地捕获。弧柄窗口崩掉会连带截图工具不可用，代价远大于开关本身。

## 7. 实施前待测（3 条命令级）

1. 授权后，应用内 `Settings.Global.putInt` 是否被 HyperOS 放行（E3 是 shell 身份，应用身份未验）。
2. 同网段下 `adb connect` + 首次 `adb pair` 后，弧柄开启 → PC 能否在 2s 内连上。
3. 弧柄面板 200dp 高、靠近屏幕底部呼出时的夹取行为（配合 `arcCenterY` 修正）。

## 8. 不做什么

- 不做桌面 AppWidget（动效不可实现）。
- 不做"常开"开关、不做开机自动开启（安全面 + 系统本身会关）。
- 不把 USB 调试开关一并放上台面（同一机制可写 `adb_enabled`，但常开 USB 调试的风险更高，且当前已为 1，无需求）。
- 不改弧柄弧线几何、不改 `HandleTone` 灰阶体系、不加红/绿状态色。

### 9.1 落点

| 文件 | 实际改动 |

### 9.2 落地时才发现的两件事

1. **Toast 全被 HyperOS 吞掉**。logcat：`NotificationService: Suppressing toast from package local.voxfix.debug by user request.` —— 所以状态提示改成**画在自己悬浮窗里的深色小条**（面板下方 104×38dp，1.6s 自动淡出）。失败靠它而不是 Toast，否则用户会觉得"点了没反应"。
2. **不再用"弧下圆点"表达状态**（见 4.1）。实测圆点落在弧线端头下方 2dp，读起来就是"!"，像告警。改为弧线 2dp/`idle` → 2.6dp/`active`。

### 9.3 真机实测（K60 / Android 15 / HyperOS V816，密度 2.625，窗口 63×168px）

| 场景 | 结果 |
|---|---|
| 已授权 + 已连 Wi-Fi，点开关 | `adb_wifi_enabled` 0→1，图标换形 + 外环，提示「已开启」 |
| 再点一次 | 1→0，斜杠回来，提示「已关闭」 |
| 无 Wi-Fi 时点开启 | 不写入，抖动 + 「需先连 Wi-Fi」 |
| 撤销授权后点 | 抖动 + 「缺少授权 / 见设置页」 |
| 开启中手动关 Wi-Fi | 系统把值改回 0，`ContentObserver` 立即把图标翻回关闭（无用例改代码） |
| 单元测试 | 454 项 0 失败 |
| 装机前后 | 默认输入法仍是 VoxFix、包列表无变化 |

授权后 `pm revoke` / `pm grant` 都不会杀掉进程（实测 pid 不变），`checkSelfPermission` 走 IPC 即时生效；但**首次授权后建议重开一次无障碍服务**（重装本来就重启进程），避免个别 ROM 上 PackageManager 缓存未刷新。

### 9.4 贴边夹取（已补测，2026-11-09 10:45）

把弧柄分别挪到屏幕顶部（`y=0.012`）和底部（`y=0.95`）后展开：

- **按钮永远完整**，不会被状态栏或导航栏裁掉。`prepareMenu()` 里 `snap()` 之后按 `params.y + height/2` 重算 `centerY`，所以弧心跟着窗口一起被夹回来，`render()` 里的插值让整个组在 220ms 内滑到夹取后的中心，不是瞬移。
- 代价：贴边时展开，按钮组相对手指位置会平移 **60–100dp**（顶部约 155px、底部约 260px @2.625 密度）。这是"面板固定 200dp 高度"的必然结果；要完全不动，得改成非对称排布（两枚按钮只朝有空间的一侧展开），属于另一次改动，没做。
- 复位：`shared_prefs/screen-text.xml` 的 `y` 改回 `0.37231183`，弧柄回到屏幕中部。

### 9.5 无线连接链路（已补测，能验的都验了）

**本机不可能做真正的局域网连接**：这台电脑只有以太网 192.168.1.4，没有无线网卡；手机在 192.168.2.40，跨网段 `ping` 100% 丢包。这不是软件问题，是环境限制。

改用等价路径验证 adbd 的无线端口本身：

```bash
adb shell ss -ltn            # adbd 监听 *:40627（每次开启端口都变，上次是 41607）
adb forward tcp:15555 tcp:40627
adb connect 127.0.0.1:15555  # → connected，adb devices 显示 device
adb -s 127.0.0.1:15555 shell echo ok   # → ADB_OVER_ADBD_PORT_OK
```

结论：**端口监听、TLS 握手、密钥授权三环全通**，而且这台电脑此前的配对记录仍然有效（否则会报 `failed to authenticate`）。剩下唯一没验的就是"同一网段内 IP 可达"这一跳 —— 换一台在同一 Wi-Fi 的机器：

```bash
adb mdns services                 # 找到 _adb-tls-connect._tcp 的 ip:port
adb connect <ip>:<port>           # 已配对直接上线；未配对先 adb pair <ip>:<配对端口> <6位码>
```

## 10. 连接可用性判定（2026-11-09 11:00 追加）

用户的实际诉求不是"开关开没开"，而是**"电脑那边到底连上没有、剪贴板现在能不能用"**——不想靠复制粘贴去试。

### 10.1 手机单独判断不了

`adb` 是谁连上来的，手机侧没有任何公开接口可查（`dumpsys adb` 要 shell 权限，`/data/misc/adb` 要 root）。所以**唯一可信的信号源是电脑端的伴生工具**：它就是那个 adb 客户端。

### 10.2 心跳

`tools/voxfix_phone_companion.py` 每 5 秒（`HEARTBEAT_SEC`）在设备在线时发一次广播：

```
am broadcast -a local.voxfix.debug.PC_STATE -p local.voxfix.debug \
    --es transport usb|wifi --es clip 0|1
```

手机侧只存 `pc.beat`（`SystemClock.elapsedRealtime()`），**15 秒没心跳就当断开**——拔线、切网、电脑休眠都会让心跳自己停，不需要手机去猜。

> 踩坑：**必须带 `-p <包名>`**。Android 8+ 不再投递清单里的隐式广播，实测不带 `-p` 时 `Broadcast completed: result=0`、没人收。

### 10.3 用户看到的

| 时机 | 表现 |
|---|---|
| 面板展开、电脑在线 | 面板下方常驻一行：「电脑已连 · USB」/「电脑已连 · Wi-Fi」 |
| 剪贴板守护没跑 | 追加「· 剪贴板未启」 |
| 15 秒没心跳 | 变「电脑未连」 |
| **刚连上那一刻** | 轻触感一次 + 弧线加粗脉冲 600ms（面板关着也给，不需要盯着看） |

全程没有 Dialog、没有 Toast（HyperOS 会吞 Toast，见 9.2）。

### 10.4 开启前的原因拆分（点一下就知道卡在哪一环）

| 检测 | 判定 | 提示 | 附加动作 |
|---|---|---|---|
| 手机没连 Wi-Fi | `NO_WIFI` | 「先连 Wi-Fi」 | **自动拉起系统「互联网连接」面板**，一键就能开（Android 10+ 禁止应用自己开 Wi-Fi，这是能做到的极限） |
| 从没收到电脑地址 | `NO_PC_INFO` | 「电脑端没运行」 | — |
| 手机网段与电脑地址都不匹配 | `DIFFERENT_NETWORK` | 「不在同一 Wi-Fi」 | — |
| 同网段但探测不到 | `PC_OFFLINE` | 「电脑端没开」 | — |
| 三关都过 | 写入 `adb_wifi_enabled` | — | — |

探测方式：电脑地址由伴生工具在设备连上时（以及每 60 秒）推一次 `PC_INFO`，手机对**同网段的那个地址**做一次 700ms 的 TCP 连接，电脑端回一行 `VOXFIX`（端口 18768，伴生工具里的 `ping_server`）。

### 10.5 实测（2026-11-09 11:00–11:15，K60 + 本机）

| 场景 | 结果 |
|---|---|
| 电脑在线（USB） | 面板显示「电脑已连 · USB」，开关可正常写入 |
| 停掉伴生工具 → 19 秒后 | 自动变「电脑未连」 |
| 重启伴生工具 | 自动变回「电脑已连 · USB」 |
| 只推以太网地址（192.168.1.4） | 「不在同一 Wi-Fi」，且**没有写入** |
| 同网段但伴生工具停着 | 「电脑端没开」，且**没有写入** |
| 关掉 Wi-Fi 后点开启 | 「先连 Wi-Fi」+ 系统网络面板自动弹出 |

### 10.6 限制

- 心跳依赖伴生工具在跑；它没跑就只能显示「电脑未连」，分不清是没开还是网络不通。
- USB 和无线同时在时优先报 USB（`pick_serial` 的既有策略）。
- 电脑端的 18768 若被 Windows 防火墙拦住，会误判成「电脑端没开」——首次运行需要放行一次。

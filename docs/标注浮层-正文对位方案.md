4. **形状按用户给的两张参考图 1:1 复刻**：高亮用**实心米色**，起点竖线用 **2px 直角**。

## 二、1:1 复刻规格（逐像素量得，按"字框高 H"归一）

参考图是放大截图，所以一切换算成相对字框高的比例，宿主字号变了等比缩放；`AnnotationGeometry` 里就是这几个常量。

| 元素 | 参考图实测 | 折算 |
|---|---|---|
| 起点竖线 | 宽 2px、高 22px（≈整行） | 宽 2dp、高＝H；1.06s 一亮一暗 |
| 未选中水滴 | 21 宽 × 28 高，钝头（≈1/3 宽）在上、圆底在下，顶端贴在光标底边 | 0.95H × 1.25H，`DROP_WIDTH/DROP_HEIGHT` |
| 选中高亮 | 实心米色 `#FDF7E1`，盖住整行（上下各外扩约 0.15 行高、不吃行距） | 逐行合并的字符框 ±0.15H（夹 2~6dp） |

## 三、数据来源

`InputConnection.requestCursorUpdates(mode)` + `InputMethodService.onUpdateCursorAnchorInfo(CursorAnchorInfo)`：

| 来源 | 用途 |
|---|---|
| `insertionMarkerHorizontal / Top / Bottom` + `insertionMarkerFlags` | 竖线位置（`FLAG_HAS_VISIBLE_REGION` 判断可见）；报不出来时退回该字框的一侧 |
| `getCharacterBounds(i)`（i 是**绝对**字符偏移） | 字符矩形 → 高亮按行合并、手柄落点、拖动时"像素→偏移"的反查 |
| `visibleLineBounds` | 备用（当前只取端点附近 ±80 字，够画也够拖） |
| `matrix` | 非单位阵时把编辑器坐标换算到屏幕坐标 |

过滤位与模式（用 `javap -constants` 从 `sdk/platforms/android-35/android.jar` 核对过，不要凭记忆写）：`CURSOR_UPDATE_IMMEDIATE=1`、`CURSOR_UPDATE_MONITOR=2`、`FILTER_EDITOR_BOUNDS=4`、`FILTER_CHARACTER_BOUNDS=8`、`FILTER_INSERTION_MARKER=16`、`FILTER_VISIBLE_LINE_BOUNDS=32`、`FILTER_TEXT_APPEARANCE=64`。**MONITOR 模式必须在每次 `onStartInputView` 重新请求**（平台要求）。

## 四、实现结构

1. **视觉层**：`PopupWindow`，宽＝屏宽、高＝键盘上方整片区域，`NOT_FOCUSABLE | NOT_TOUCHABLE | LAYOUT_NO_LIMITS`，自绘竖线 / 高亮 / 水滴；竖线闪烁靠 popup 内自绘 + 定时 `invalidate()`。
2. **手势层**：两枚水滴各一个 48dp 小 `PopupWindow`（可触摸），中心对齐画出来的那枚；拖动时用 `getCharacterBounds` 反查偏移。
3. **拖动语义**：按下时记下"不动的那一端"，之后每次移动把被拖的那一端**一次写入**宿主选区（`setSelection(fixed, target)`）；未选中（只有起点）时拖动＝移动光标并在新位置重新标定起点。
4. **显示时机**：只在起点锁定期间（`selectionLockedAnchor >= 0`）；解锁、打字/删除/回车、换输入框、收起键盘、结束输入都会 `hide()`；键盘高度变化时 `reposition()`。
5. 位置沿用"来自剪贴板"标签那套 popup 做法（挂 IME 窗口、`showAsDropDown` 负偏移），**不占键盘高度**。

- **数据源铁律**：`requestCursorUpdates` **一次只能发一个模式**；连发 `MONITOR` 后 `IMMEDIATE` 会让后者覆盖前者，监视实际没开成（只见一帧一次性数据，且在锁定前被丢弃）。现只发 `MONITOR|FILTER_CHARACTER_BOUNDS|FILTER_INSERTION_MARKER`，在每次 `onStartInputView` 与锁定瞬间各请求一次；锁定后 900ms 无帧则退回不带过滤位的纯 `MONITOR` 重试。
- **已发生的事故**：浮层绘制函数与 `View.draw` 重名导致 `onDraw` 无限递归、栈溢出杀进程（键盘呼不出）。已改名 `render(canvas)`，并给 `update/show/hide/reposition/onDraw/触摸` 加 `guard` 兜底——浮层出任何异常只关自己，不再影响输入法。
- **搁置时的未验证项**：① WebView（小米笔记/微信）是否真的回 `CursorAnchorInfo`；② 挂在键盘上方的 popup 能否收到触摸；③ 对位精度、滚动跟随、手柄手感。
- **降级**：宿主完全不回坐标时，浮层不会出现（`Log.i("VoxFixSel","anchor …")` 一行都没有），此时退回"键盘内标注条"（占面板页头 32px、随面板显隐、不增键盘高度）。


## 六、风险

- WebView（小米笔记正文、微信）是否实现 `CursorAnchorInfo` 未知，必须在 K60 实测。
- 坐标可能来自编辑器局部坐标系 → 用 `matrix` 判定并换算。
- popup 与正文抢触摸：视觉层必须 `NOT_TOUCHABLE`，手势层只占 48dp。
- 闪烁靠 popup 内自绘 + 定时 `invalidate()`，不要用网页 CSS 去驱动。

## 七、验收判据

1. 竖线与宿主真实插入点重合（误差 ≤ 2px），连续拖 5 行后仍重合；
2. 高亮逐行贴合选中文字，左右端不越界、不盖行距；
3. 水滴拖动只改对应那一端，松手后落点是手指所在字的边界；
4. 除水滴 48dp 外，正文触摸行为不变；
5. 收起键盘 / 改正文 / 换输入框后浮层立即消失（本次会话内有效）。

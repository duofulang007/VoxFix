- 共用 `VoiceRecorder` / `PcmCapture` 原生采音，保留20ms采样包、冷加载期间缓存、松手停止和时间戳尾音边界。长按空格240ms、上滑取消；单轮最多3分钟。键盘出现即预热 R5，主输入法空闲5分钟释放模型，验证页 `MainActivity` 为30秒。

## 点按语音改为「就地定稿」（2026-10-25 晚，用户反馈后修正）

用户实测两个现象：说话上屏后打字，打字期间说的话会在打完字后倒回语音起点；删掉刚上屏的字再说一句，会提示「输入位置已变化」且文字不上屏。根因是点按语音走的是「并发草稿」路径：`ConcurrentVoiceInput` 把语音文本攒在会话起点 `voiceStart`，等 `composingStart == null`（用户打完拼音）才 `replace()` 写回，光标变化又会整轮 `cancelRecording()`。

- 删除 `ConcurrentVoiceInput.kt`、`mixedVoice` / `mixedDraft` / `mixedPending` / `mixedFinalMessage` / `flushMixedVoice()` / `finishMixedVoice()`；`startMixedVoice()` 保留为兼容别名，行为等于 `beginVoice()`。点按语音与长按空格现在是同一条链路。
- 语音结果实时 `setComposingText` 落在**当前光标**，不再记会话起点；`beginVoice` 的 `getExtractedText` 改用 `hintMaxChars = 0`——`hintMaxChars = 1` 会让部分宿主截断返回文本，把 `voiceStart` 算错成「用户挪了光标」。
- 新增 `settleVoice()`：语音还在收字时用户打字、挪光标、回车，先把已识别这一句就地定稿（只在 `voicePreviewWritten` 为真时 `finishComposingText()`，避免定掉用户自己的拼音），再继续打字。不再整轮丢弃，也不再弹「输入位置已变化」。
- `editInput(typing = true)` 覆盖 `compose` / `commit` / `completeEnglish` / `delete` / `enter` / `moveCursor`；拖动滑轨导致的光标变化由 `onUpdateSelection` 兜底。
- 验收：`preview/native-ime.test.mjs` PASS（断言点按以 `startVoice` 开始、`startMixedVoice` 为 0；`--mic-scale` 阈值由 1.4 校正到实现值 1.05，这是此前未提交的呼吸幅度改动留下的漂移）；`assembleDebug` 与 `assembleDebugAndroidTest` 通过；装机后 base.apk sha256 与本地产物一致（389,527,288 bytes）；`desktop-delivery` 8 checks 通过。**真机未验**，等用户实际操作确认。

## 语音保持常驻、按段上屏（2026-10-25 晚，二次更正）

用户澄清：右下角语音是**常驻**的，只有他自己点关闭才该结束。上一节「打字即就地定稿并结束整轮」因此被否掉——他删一个字、打一个词，语音就自己关了。

- 打字 / 删字 / 挪光标**都不结束语音**。`settleVoice()` 删除，`onUpdateSelection` 不再因光标变化动语音；`editInput(typing = true)` 改调 `handOffVoiceToTyping()`：只把**还没定稿的草稿**从 composing 撤下（不落字，避免与拼音抢 composing），录音与识别继续跑。
- `DesktopSpeechEngine.transcribe/record` 增加两个回调：`onSettled(这一段自己的定稿文本)`、`onDraft(当前这一段未定稿草稿)`。IME 收到定稿段就 `commitText` 落到**当前光标**，不再拿累计全文去覆盖 composing——累计全文里含已经提交过的部分，会重复。
- 用户正在拼拼音时（`composingStart != null`）定稿段先进 `voicePendingCommit`，`commitInputText()`（候选上屏）立刻补进去，最多等一个词，不会攒整轮。
- 结束只由用户点关闭或取消触发：收尾时 flush 挂起段、收起草稿，`voiceDone` 不再报「输入位置已变化」。
- 运行时不再调用 `VoiceInputDelivery` 和 `InputSession.isVoiceSelection`；两者连同 `ParagraphSelection` 及其单元/仪器测试已在本轮清理中删除（可从 Git 历史追溯），行为由 `VoxFixImeService` 的按段 `commitText` 路径承接。
- 验收：`assembleDebug` + `assembleDebugAndroidTest` 通过；`preview/native-ime.test.mjs` PASS；装机后 base.apk sha256 与本地产物一致（`e3786be7…`）；默认输入法与包列表未变；`desktop-delivery` 8 checks 通过。**真机未验**，等用户实操确认「打字不关语音、每句落到光标」。

## 打字期间识别静音（2026-10-25 晚，三次更正）

用户把语义说清楚了：麦克风常驻挂着，但**一打字就要把识别关掉**，等他选完字再从那个光标起算新的一句；打字时说的话绝不能上屏。上一节「打字也继续按段识别」正是他遇到的毛病——说完一句去选候选，选完字，打字期间说的话被 VAD 当成新段自己冒出来。

- `VoiceRecorder.record` 增加 `isMuted`：为真时把采集样本整帧换成静音再交给引擎（麦克风继续读，不阻塞、不重开会话），电平上报 0。腾讯/宿主侧看不到「录音中断」，但 VAD 拿不到语音，不会成段。
- `VoxFixImeService`：`voiceMuted`（`AtomicBoolean`，worker 跨线程读）+ `pauseVoiceForTyping()` / `scheduleVoiceResume()` / `resumeVoiceInput`。
  - `editInput(typing = true)`（compose / commit / completeEnglish / delete / enter / moveCursor）进入时先 `pauseVoiceForTyping()`：静音、撤掉未定稿草稿（`setComposingText("")`，不落字）。
  - `commitInputText` / `delete` / `enter` / `clearComposition` 结束时 `scheduleVoiceResume()`：静默 400 ms（`VOICE_RESUME_DELAY_MS`）后恢复；拼音 `composingStart` 还在就每 400 ms 再看一次，上屏那一刻才真正恢复。
  - `onSettled` / `onDraft` 在 worker 线程入口和主线程执行前各查一次 `voiceMuted`：静音期间到达的段与草稿直接丢弃，连排队都不进。
- 恢复后 VAD 从当前音频重新开段，句子从打字后的光标起算，不接着打字前那半句续写（半句会被丢弃，这是「打字即打断」的必然代价）。
- 验收：`assembleDebug` + `assembleDebugAndroidTest` 通过；装机后 base.apk sha256 与本地产物一致（`ed0f2a1d…`）；默认输入法与包列表未变；`desktop-delivery` 8 checks 通过。**真机未验**，需用户实测「说话→打拼音选字→再说话」这条链路。

## 以候选框存亡判定是否识别（2026-10-25 晚，四次更正）

上一版用 `composingStart == null` 判「打完字」：选掉第一个候选后 composing 已经提交，但**联想候选框还挂着**，于是提前恢复收音，把用户接着说的话打进候选。用户要求改成按候选框判定——框在就不识别，框不在才识别并落到光标后。

- 前端 `preview/app.mjs` 新增 `candidatesVisibleNow()` / `reportCandidatesVisible()`：判据与 `toolbar()` 生成 `.candidate-bar` 的条件一致（`state.comp` / 中文联想 `associatedWords` / 英文 `englishPrefix` / 展开的 `state.page==='candidates'`），键盘收起或本地剪贴板搜索时为 false。每次 `render()` 末尾上报，缓存去重。
- 原生 `@JavascriptInterface fun candidatesVisible(visible)` 写入 `candidatesShown`（`@Volatile`）。
- `resumeVoiceInput` 的恢复条件改为 `!candidatesShown && composingStart == null`，每 400 ms（`VOICE_RESUME_DELAY_MS`）复查一次，两个都消失才真正恢复；`voiceTyping` 标记本轮静音是否由打字引起，语音自己上屏不会置位，避免被残留联想候选永久卡住。
- 选候选用 `commitInputText` → 前端同步 `rememberContext` → `refreshAssociations` → `render` → 上报，全部同步，所以 `candidatesVisible(true)` 的 `main.post` 一定排在 `commitInputText` 的 post 之后、400 ms 定时器之前，不存在「先恢复收音、联想候选后到」的竞态。
- 排障日志：`VOICE_CANDIDATES visible=… muted=… typing=…`、`VOICE_RESUME`（`adb logcat -s VoxFix`），不记任何转写内容。
- 验收：`assembleDebug` + `assembleDebugAndroidTest` 通过；`preview/{native-ime,ime-regressions,candidates}.test.mjs` 全 PASS；APK 内 `assets/keyboard/app.mjs` 已含新函数（`zipfile` 读回确认）；装机 sha256 `e68669fb…` 与本地一致；默认输入法与包列表未变；`desktop-delivery` 8 checks 通过。**真机未验**。

## 打字即「收尾定稿」而不是撤稿（2026-10-25 晚，五次更正）

用户实测确认了两件事：带横线的文字是「正在识别」，横线消失才算确定上屏；他主动取消语音时横线立刻消失、那段话被锁定，比等 VAD 静音（0.65 s）+ 解码（0.3–0.9 s）快得多。三次更正里的 `setComposingText("")` 正好相反：话说完了、识别还没转完就打字，屏幕上那半句**整段消失**。这一轮把「撤稿」改成「收尾定稿」。

- `pauseVoiceForTyping()`：`voicePreviewWritten` 为真时改为 `finishComposingText()`（与用户主动取消语音停在同一处），横线消失、文字留下，之后打的字接在后面。语音本身不结束，麦克风继续常驻。
- **这一段语音到此为止**：`finishComposingText()` 只锁定屏幕上已有的字；那一段的正式定稿（VAD 静音 0.65 s + 解码后才到）不再往输入框写任何东西。理由见下一节——先补尾巴、再按段上屏两种做法都会让用户看到重复或顺序错乱。
- 排障日志（不记转写内容）：`VOICE_FINALIZE key=…`、`VOICE_MUTE`、`VOICE_SETTLE dropped=finalized key=…`。

## 打字收尾只锁定屏上文字，那一段的定稿直接丢弃（2026-10-25 晚，六次更正）

五次更正曾用「草稿前缀对账 + 只补尾巴」把没转出来的字补回去。用户实测报出 bug：说一句、趁横线还在快速打拼音选字，上一句被**重复**写出，后续内容还落在打的字后面（例：「我打这个bug，还有」之后再出现一遍）。根因是正式定稿会整段重新解码，正文与屏幕草稿并不保证前缀一致，补出来的尾巴和已锁定文字在用户眼里就是重复；而补尾巴只能在候选上屏后落字，顺序必然插在打字之后。用户明确表示不要这个机制。

- 删除 `voiceSettledText()`、`voiceTailSettles`、`voiceDraftText`、`voiceFinalizedDraft`/`voiceFinalizedAt`、`VOICE_SETTLE_TAIL_MS`，以及只服务于它的 `DesktopVoiceRules.contentful()` 和 JVM 用例。

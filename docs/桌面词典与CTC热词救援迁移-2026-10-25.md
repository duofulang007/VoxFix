# 个人词典模块与语音链路精简（2026-10-25）

同日前一轮先把电脑版词条用数据库表 `voice_rules` 导入安卓、并接上 CTC 救援。用户随后决定：
**照电脑版的「词典」模块 1:1 复刻到安卓**，删掉表结构那套与旧的自动学习，只留
「拼音候选记忆 + 词典（词/错法）+ CTC 救援」。本文是最终形态。

## 现在的三层，各管一件事

| 层 | 数据 | 谁写 | 谁读 | 不做什么 |
|---|---|---|---|---|
| 拼音候选记忆 | `personal-lexicon.db` 的 `entries`（librime 个人词库、词频、置顶） | 选词、`添加拼音词语`、导入备份 | 拼音候选/联想 | 不参与语音文本改写 |
| 个人词典 | `files/voice-dictionary.json`（与电脑版 `dictionary.json` 同格式） | `DictionaryActivity`（功能菜单「词典」） | 定稿文本替换 + 救援候选词 | 不读自己输出、不再迭代多轮 |
| CTC 热词救援 | 读上一层的词 | 只读 | 定稿段的偏置再解码 | 不新增词条、不学习、不碰草稿 |

管线只有一条：`定稿 → 救援 → 词典替换 → 标点`。删除自动学习后，同一处文字只有一个主人。

## 词典文件与模块

- 路径 `files/voice-dictionary.json`，首次由 `assets/dictionary/desktop-v1.json`（与电脑版
  `dictionary.json` 逐字节相同）播种；真机实测 16 词 / 60 错法（14 个桌面词 + 用户手动词
  `Excel`、`张玥`），`rules` 与桌面文件深度相等。
- 写入沿用桌面格式：全部词进 `hotwords`，只有填了错法的词才生成 `rules`；错法顺序按用户输入，
  匹配端自己做「长变体优先」。
- `DictionaryActivity` 以手机竖屏方式复刻桌面两栏：列表（搜索词/错法、每行「N 种错法」或
  「仅救援」）→ 详情（`容易识别成` 每行一项、粘贴自动整理、`文字预览`、`删除这个词语`）。
  计数、文案、守卫与状态行照搬：`词语 N · 纠错 N · 救援 N/64`、`未填错法 · 仅加入救援词表`、
  `中文、纯英文、混说 · N 种错法`、`错法冲突：…`、`词典已被外部修改，请重新打开后再编辑`、
  `词典已保存 · 下一句生效`、删除后 10 秒撤回。
- 入口：键盘「功能菜单」→ 词典（`nativeIme.openDictionary()`）。设置里的「个人词库与迁移」
  只保留拼音词条的添加/备份/导入。

## 删掉的旧语音链路

- 源码：`SpeechEngine.kt`（旧双遍）、`SpeechEnglishRecovery`、`SpeechSecondQueue`、`SpeechSegment`、
  `SpeechEvidence`、`SpeechAudioWindow`、`VoiceLexicon`、`VoiceEditExtractor`、`VoiceCorrectionTracker`、
  `VoiceEditorSnapshot`、`VoiceRefinement`、`Punctuator`、`VoiceLanguage`。
- 运行时：`voice_words` / `voice_corrections` 不再被读取；`voice_rules`、`voice_rule_skips` 与导入器删除。
  真机上的 186 条语音词语、196 条学习记录**留在库里当档案**（`archivedVoiceCounts()` 可查），
  备份不再携带它们。
- 测试：删除 19 个只跑旧引擎的真机用例、4 个 JVM 用例；`VoxFixSmokeInstrumentation` 精简为
  `desktop-delivery / desktop-live-* / hotword / hotword-migrate / meme-search / lexicon / pinyin / 默认加载`。

## 首次激活为什么慢（已改）

R5 int8 图 229 MB，`OfflineRecognizer` 构建在 K60 上 **2.7–3.3 s**；旧实现是「长按空格才建引擎」，
所以第一句在模型还在加载时就已经说完，草稿自然不出。现在：

- `onStartInputView` 一开始就在 worker 线程预热（`IME_ENGINE_WARM ms=…`），键盘一出现就开始读模型；
- 引擎保留到键盘收起或系统回收（空闲释放 30 s → 300 s，`onTrimMemory(BACKGROUND)` 仍会释放）；
- 预热完成后，首句与后续句子走同一条 550 ms 出草稿的流式路径。

日志证据：`IME_ENGINE_WARM ms=2726`、`ms=3255`；一次 18:52 的实测里，用户按下时引擎仍在这 3.2 s
冷加载里，`IME_STREAM_FINISHED characters=0`（那次还叠了两次装机导致进程重启）。

## 验证

- JVM `testDebugUnitTest` 通过（`DesktopHotwordTest` 12 项；旧引擎测试已删）。
- 网页 `ime-regressions.test.mjs` 38 项通过，含「功能菜单词典入口 → openDictionary」。
- 真机 `HOTWORD_PASS checks=3`：词典 14 词/60 变体、文件往返、粘贴整理、冲突拒绝、CTC 明文/偏置/守卫。
- 真机 `HOTWORD_MIGRATE_PASS entries=3205 archivedWords=186 archivedRules=196 manual=2 dictionaryWords=16 rules=14`。
- 词典页截图：列表（16 词、计数、搜索）与 JSON 详情（8 行错法、预览、删除）见
  `.android/dict-module-20261025/dictionary-{list,detail}.png`。

## 仍未验证

- 真人麦克风下「词典词/错法」的实际命中率与误伤；只有 TTS 固定音频。
- 预热常驻期间的内存（K60 未量）；救援会话另占约 290 MB 级。
- 首句在「键盘刚出现 3 s 内」长按仍会等模型；这是模型大小决定的物理下限。
- 词典页真机点击手感、系统返回键与横屏布局。

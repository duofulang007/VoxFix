# 桌面语音迁移：实时模块与VAD验证

日期：2026-10-25。接续[第一轮计算评估](桌面语音迁移安卓评估-2026-10-25.md)。本轮把预生成分段替换为真正的安卓在线VAD，并移植文字词典规则。**尚未切换日用语音，也没有迁移个人词条。**

后续已按用户授权[接入并安装0.2.0-r5主包](桌面R5语音接入与安装-2026-10-25.md)。本文保留隔离阶段的测试条件；其中“尚未切换”指该阶段当时状态。

## 实现范围

独立候选模块放在 `android/app/src/voice/java/local/voxfix/debug/`：

- `DesktopSpeechEngine.kt`：R5两线程、ITN关闭；100ms VAD输入、统一轻声增益；最新草稿覆盖、定稿优先、24段队列；取消和错误恢复；单轮180秒；释放保护；音频只在内存里使用。
- `DesktopVoiceSegments.kt`：400ms边界补偿、短句收尾保留开头、10秒强制切段附近低能量切点及剩余音频续接；550ms最短草稿、350ms更新间隔。
- `DesktopVoiceRules.kt`：模型标签剥离、英文段间空格、产品语言范围、标点正文保护和已有标点去重。包含Python空白字符与Android正则的兼容处理。
- `DesktopVoiceDictionary.kt`：按词条顺序替换、条内最长错法优先、英文词界、大小写忽略、整轮中文上下文、字面替换、坏文件回退；解析64词热词上限，尚不运行CTC热词救援。

Gradle只把该目录加入 `test` / `androidTest`，**不加入main，不进入日用主APK**。没有新依赖、额外模型或新的共享库。现有 `SpeechEngine.kt`、`PcmCapture.kt`、`VoxFixImeService.kt` 和前端交互未由本轮改动。

词典文件默认缺省，本轮只在独立缓存目录写入并删除合成词典测试文件，不读取个人词库。候选模块遇到非空 `hotwords` 配置会明确报尚未接入救援，不能把普通文本替换当作救援已实现。

## 当前语段起点

现有Kotlin VAD接口提供原生语音标记和已完成语段，但不提供Python的 `current_segment.start`。继续使用现有sherpa原生神经VAD，按固定版本的缓冲区公式追踪其当前起点和已丢弃音频位置；没有另写一套神经VAD或增加运行库。

依据为[sherpa-onnx v1.13.8的实现](https://github.com/k2-fsa/sherpa-onnx/blob/v1.13.8/sherpa-onnx/csrc/voice-activity-detector.cc)。限制为512样本窗口的v4模型，初始化校验VAD资产SHA256：`9e2449e1087496d8d4caba907f23e0bd3f78d91fa552479bb9c23ac09cbb1fd6`。运行时或模型升级时必须重新逐帧验证。来源及既有Apache-2.0许可记录保留在 `src/main/licenses/sherpa/UPSTREAM.md` / `LICENSE`。

## K60实际验证

设备 `6959dba1`，sherpa-onnx 1.13.8，R5与第一轮同一SHA256。仍用原36条固定音频，共133.021秒；没有打开麦克风、向真实宿主输入或保存日常录音。

1. **真实VAD边界**：PCM直接进入安卓VAD，桌面计划仅用作断言。36条、1381帧的语段起点、已完成分段、草稿区间和触发时机逐项零差异。
2. **真实时间回放**：20ms供给原始PCM，安卓自己增益、VAD、分段、调度和解码。36条全部完成，1381帧仍零差异，最终文字与第一轮同权重/两线程的预生成分段结果36/36相同。
3. **文字规则**：从桌面现行 `recognize.py` / `dictionary_rules.py`直接生成26个合成对照。K60上的词典、标点正文保护、语言范围及段间拼接全部相同；独立验证坏词典停用、修改后生效、尾随垃圾拒绝和64词上限。
4. **生命周期**：最终8项检查通过，涵盖开始即取消、出字时取消且无迟到回调、连续重开、取消后再用、坏音频后恢复、重复释放与已释放拒绝；并检查运行中不能直接释放模型。异常音频覆盖NaN、空块和超过1秒的输入块。最终包重跑该组及26项文字规则通过。
5. **源码与构建**：新增9项JVM测试，完整JVM报告145项、零失败；测试包构建成功。测试包安装不等于主输入法安装。
6. **网页交互**：`preview/native-ime.test.mjs`及`preview/voice-orb.test.mjs`本轮均通过。上一轮着色器失败此次未复现；本轮没有改绘制代码。

基线沿用前一轮结果，没有进行温控交错复测。因此这组数据支持计算可行性及边界等价，不能承诺实际更快、更省电或总体更准。仍保留第一轮已知的短句“谢谢”增字、部分标点/粤语差异；固定合成与公开样本不代替独立真人准确率验收。

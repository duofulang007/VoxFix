# 横屏适配（2026-10-25）

## 官方依据

用户在 K60 手动打开讯飞小米版横屏，ADB 核对当前输入法为 `com.iflytek.inputmethod.miui/.FlyIME`。截图 `.android/landscape-official-20261025.png`（本地证据，不提交）：3200×1440、density 560。官方为全屏编辑，上方编辑区与完成按钮，下方约 258dp 高键盘；字母区约 696dp 宽，居中，按键高约 47dp，不保留竖屏底栏。APK 内 `assets/theme/white/config-1080/dimen-land.ini` 另有横屏尺寸配置，不能直接当成当前运行时尺寸。

## 实现

- 取消强制关闭 Android 全屏编辑，沿用系统的横屏判定和宿主 `IME_FLAG_NO_FULLSCREEN` 限制。
- 原生首帧及前端横屏基高均为 258dp；700px 居中键区，47px 字母行，隐藏底栏；竖屏继续 351dp。
- 横屏由原生实际方向通知前端，不根据固定 550dp WebView 画布的宽高比推测。
- 剪贴板搜索、共享编辑框与表情搜索扩高受屏幕高度约束，保留顶部至少 64dp；共享编辑框操作改为横排，避免三个按钮撑破高度。
- 候选、数字、符号、拆词、方向盘与语音面板增加横屏尺寸约束；未更改语音模型、词库与学习数据。

## 用户反馈后的原生窗口修复

首版未核验原生窗口左右边界，用户截图确认左侧露出宿主按钮与文字；不能把首版记作真机通过。

按用户明确授权自行切换输入法，在同一个项目测试框对照。讯飞 IME 窗口为 `layoutInDisplayCutoutMode=shortEdges`，frame `[0,138][3200,1440]`，全屏编辑状态为 true；VoxFix 默认刘海策略令左边缩进 138px。`preview/landscape-window-device.test.mjs` 修复前实际失败 `138 !== 0`。这属于 Android WindowManager 刘海区域布局，前端 CSS 无法修复窗口外的露底。上方编辑区使用 Android 输入法全屏提取编辑机制；此次未反编译确认讯飞每个键的绘制实现。

只为原生 IME 窗口补上 `LAYOUT_IN_DISPLAY_CUTOUT_MODE_SHORT_EDGES`，未继续调整按键布局。重新构建、自检、保留数据安装成功。原生窗口回归在 ROTATION_90 与 ROTATION_270 均通过 `[0,138,3200,1440]`；实际截图 `.android/landscape-window-fixed-20261025.png` 确认不露出宿主内容。`landscape.test.mjs` 通过。用户日常触感仍待确认。

# 滑轨把光标送出输入框 · 宿主 EditText 在文本边界交出焦点

2026-10-13。用户报：滑轨往左滑之后「光标都不再输入文本框了，一动滑轨都跑出去了，找不到了」。

## 现象与现场

真机（K60，MainActivity 试用框，内容 6 字）：滑轨左滑一次后，`uiautomator dump` 里 `focused="true"` 的节点从
`android.widget.EditText`（`content-desc=VoxFix输入法试用框`）变成 `android.widget.TextView`（页面上的按钮）——
光标确实离开了输入框，输入框里再没有插入光标，之后滑轨怎么拖都找不回来。空文本时更早触发（任何方向立刻越界）。
触发条件：光标已经在**文本开头（继续拖左）或末尾（继续拖右）**。

## 根因

`VoxFixImeService.navigateSelection()` 移动光标走的是**给宿主发方向键**
（`connection.sendKeyEvent(DPAD_LEFT/RIGHT)`，为的是能跨段落）。但 Android 的 `EditText` 在文本首/尾再收到一次方向键时
不会停住，而是 `focusSearch` 把焦点交给上一个/下一个可聚焦 View —— 光标就此离开输入框。

对照：`moveCursor()`（候选/编辑操作那条路）用 BreakIterator + `setSelection`，不经过方向键，所以不会越界；
问题只出在滑轨这条用方向键的实现上。

## 修复

新增 `CursorBoundary`（`android/app/src/main/java/local/voxfix/debug/CursorBoundary.kt`）：由提取文本的
`completeText / startOffset / selectionStart / selectionEnd / textLength` 判断目标方向还有没有字符；
`navigateSelection()` 只在该方向可移动时才发按键，否则整批跳过（`movable = 0`）。判定要点：

- 有选区 -> 不封：方向键只做折叠，不会把焦点送出输入框；
- 提取文本是**局部**的（`partialStartOffset/partialEndOffset != -1`）-> 不封：边界留给方向键跨段；
- 拿不到提取文本 -> 退回 `getTextAfterCursor/getTextBeforeCursor(1, 0)`；探测返回 null（宿主没实现）一律放行 ——
  **宁可不封也不误封**。

## 验证

- 新增单测 `CursorBoundaryTest`（5 条：两端封死、中间双向可走、startOffset 平移边界、有选区不封、局部文本不封）。
  `testDebugUnitTest` 全绿：CursorBoundary 5 + InputSession 2 + PcmCapture 3 + SelectionDrag 2 + SelectionSteps 2 + SpeechEngine 11。
- 真机（新 APK `install -r -t` 后，试用框内容 `abcde`，滑轨设备坐标 y=3051）：
  - 光标移到末尾后右滑两次 -> 位置停在 **5/5**，`focused="true"` 仍是 EditText；
  - 左滑到开头后再左滑三次 -> 停在 **0/5**，焦点仍在 EditText；
  - 中间段左滑正常从 5 走到 0（没有把正常移动封死）。
  - 修复前同一操作：焦点变成 `TextView`（见上「现象」）。

## 边界

只作用于**非框选**的光标移动；框选（`gestureSelecting`）带 SHIFT，方向键语义是扩展选区，不在此列。
宿主既不返回提取文本、`getTextBefore/AfterCursor` 又返回 null 时，仍按原样发方向键（无法判断边界）。

# 滑轨拖动与触控点分档速度

更新时间：2026-10-14。适用主滑轨与编辑框方向盘，替代旧360度两轴混合输出和首次向上“就位”动作。**主滑轨只保留左右**（拖动丢弃纵向分量、短按按中线左右精调一个字），八方向只存在于编辑框方向盘。

## 已复现的问题与修正

旧跟手路径按最新位移走，持续移动却按相对旧按下点的向量走。向上拖到高速区后转成横向，真实前端仍向原生桥发送负纵向位移。`selection-pad.test.mjs` 旧版明确失败，修复后转向停留不再输出旧纵向分量；此复现证明代码缺陷，不单独证明用户视频全部症状来源。

主滑轨跟手和持续移动都只用水平分量：`dragSelection` 对主轨把纵向分量直接置零，因此原生桥只会收到 `gestureMove2D(dx,0)`。方向盘继续使用最近确认的八方向，扇区按实际屏幕角度45度划分，保留旧方向至夹角达到30度，以免边界抖动。转向清理原生 `SelectionSteps` 和网页不足一步的余量，保留按下点与推距，不要求回到旧原点或重新按下。待转向位移累计达到8px才确认，避免1px垂直手抖把水平持续推移打断。

编辑框方向盘改按可见3×3空间：仅中心按钮可开始拖动，推入外围八区立刻按该区方向续移，中心区跟手，回中/松手停止。外围箭头是独立点按精调按钮，不从箭头开启拖动；中心单击重设起点，与拖动在松手时判定互斥，拖动不改变起点。圆点推时有受限跟手反馈，松手回中。

横向11px一字、纵向28px一行，增量累计。主轨只用横向那一条，纵向步长只服务编辑框方向盘。跟手只输出当前方向允许的轴；持续移位沿同一方向输出，不能把已经停止的纵向再叠进横向精调。首次长按后即可直接拖动框选，不再先“抬到上面就位”。

## 速度与收尾

沿用 `core.mjs` 超椭圆推距（指数3）、上下分别取半径、两档门槛 `[0, 0.78]`、降档迟滞0.06。各半径最大96 CSS px，因此直线推约75px即可进入持续档；不再以上方整张键盘的高度作为行程。K60旧版真人记录中上推停住只有微抖指令，未进入持续档，上一轮防抖回归没有覆盖此触发距离问题。普通区域跟手，推远才进入持续档。

**进入持续档不是立刻最高速，而是按住越久越快**，和长按删除共用同一条曲线：`joystickHoldRate(elapsed) = min(24, 1000 / repeatDelay(⌊elapsed/110⌋))`，`repeatDelay(step) = max(35, 110 − step×8)`。刚进持续档约 9.1 字/秒，之后每 110ms 提一档（110→102→…→35ms 一个字），约 0.8 秒封顶 24 字/秒。转向、回中、松手都把计时清零，重新起步；摇杆与长按删除不再各自维护一份起始速率。

方向盘横向按上式输出，纵向单独限制为 `min(4, rate/6)` 行/秒，斜向同时输出字/行增量；主轨没有纵向可输出。点按斜向的行首/行尾快捷跳转不用于拖动。

rAF 每帧间隔夹到50ms，不足一步的位移继续累计；回到按下点11px内、松手、断触、失焦、宿主阻止、输入会话重置都停止续移。小方向盘不额外显示说明文字或辅助环。

## 验证边界

网页覆盖主轨纵向输出恒为零（含原生桥只收 `gestureMove2D(dx,0)`）、主轨短按左右精调一字、转向后纵向输出归零、点按/拖动互斥、方向箭头长按不解锁、连续斜向从最新终点出发、反向续选、复制首次点击、48px触控区、原点停移与断触清理；JVM覆盖跨行后清空旧余量。具体K60手感、微信/笔记行边界和复制结果需要用户确认，不运行旧设备触摸注入套件。

# 滑轨锁定与编辑框：交互约定与实现映射

更新时间：2026-10-16。以本页为当前规则，旧上下选段和扁长小滑轨已被替换；主滑轨（键盘底部空白）只保留左右，纵向跨段只在编辑框方向盘里做。

## 锁定与面板

- 主滑轨长按一次切换锁定/自由：锁定当前活动端为起点并呼出编辑框；解除时收成活动终点，反向选区不能用较大索引。
- 主滑轨呼出编辑框后，本次按住的拖动继续到松手。编辑框显示期间不能从遮罩背后的主滑轨启动新手势。
- 松手只结束拖动，选区与固定起点保留，编辑框里的按钮立即可用。
- 右下角常驻语音允许滑轨与宿主选区打开编辑框；从滑轨开始移动到编辑框关闭期间暂停语音送字，已显示草稿固定，迟到结果不改选区。关闭后仍等待候选框/拼音组合结束，再按原有延迟恢复。空格长按语音球仍独占手势。见[冲突修复记录](常驻语音与滑轨编辑冲突修复-2026-10-29.md)。
- **手动在正文重定位光标或拖动原生选区手柄 = 退出旧拖选**：清除内外锁定、停止旧续移并收起面板，保留宿主刚改好的位置，不调用解除锁定把光标拉回旧活动端。单侧手柄调整共享旧边界且仍重叠，不重新呼出；新的整段选词可以直接替换旧选区后呼出（不要求先收成光标），主滑轨长按也可重新锁起点。输入法自身跨行/方向按钮/全选及松手后的延迟回调不当成手动重定位。
- 点击框外只收起面板，不移动光标、不改选区、不解锁，也不能穿透点击键盘。收起后主滑轨重新可用。
- 正文双击/长按选词允许一字、两字或多字；合并同一次选词的连续回调，稳定120ms后按最终选区呼出。先报一字再扩成两字不视为手动改起点；若期间收成光标、换输入框或开始新的键盘操作，则取消待呼出，不能迟到弹框；单纯松手收尾不延长自身操作抑制，也不取消新的宿主选词候选。
- 中心圆点单击：将当前活动终点重设为新起点并收成光标，保持编辑框。中心拖动：保留原起点、只调整终点；松手圆点回中并停移。原有中心长按锁定/解除保留。八个方向按钮只点按精调，按住箭头滑出去不启动拖选，也不补发点击。
- 解锁后同一次触摸不再移动，抬手后恢复自由移动；换输入框、结束会话或改正文清理旧锁定。

## 两栏布局

页头左侧显示已选字数，右侧原有空白放一个删除钮（浅红底、深红图标，按下加深）；页头高度 32px 与面板尺寸不因它改变。

左侧从上到下：全选、复制、剪切、粘贴，四个按钮的按钮框、间距与颜色一律不变，只有内容是线宽统一的深灰图标——虚线选框（全选）、两张重叠纸页（复制）、剪刀（剪切）、带纸页的剪贴板（粘贴）；无选区时复制、剪切沿用浅色禁用态，中文功能名保留在可访问名称里。右侧近方形 3×3 方向盘，中心点表示锁定，八方向各有独立点击区。删除上下选段、独立左右微调和可见“拖动／点按”提示；功能说明留在可访问名称中。

面板宽最多 288 CSS px，左右留 14px，底部留 23px；左侧 76px 宽，四行 48px，右侧三行共 204px。320px/393px 网页检查各点击区均至少 48×48 CSS px且不重叠，26键布局/高度不变。

## 点按与拖动

主滑轨（键盘底部那条空白）**只输出左右**：拖动时的纵向分量一律丢弃。footer 只有 44–50 CSS px 高，上下行程短、又夹在工具栏与字母键之间，纵向极易被误判成横向而"跨段"跳行，收益却很小；跨行/跨段选择只在编辑框的八方向盘里做。主滑轨**短按＝精调一个字**：落点在中线左侧左移、右侧右移（与方向盘箭头走同一套 `selectionStep`；未锁定时移光标，锁定时移活动终点），不形成选区、不重开面板。拖动仍按推距续移。

| 方向 | 点按 |
|---|---|
| 左/右 | 活动端移动一个字（按字素，不能拆开emoji） |
| 上/下 | 移动一行，保留大致列位置 |
| 左上/右上 | 上一行开头/末尾 |
| 左下/右下 | 下一行开头/末尾 |

每次从当前活动端所在行出发；重复右上会继续向更上一行走，不是在同一行从开头跳到末尾。行首在第一个字之前，行尾在最后一个字之后。锁定时只改终点，未锁定时移动光标，终点可以越过起点形成反向选择。

方向盘必须从中心按钮开始拖动，可拖出点击区，指针捕获到键盘根节点；经过复制/剪切等按钮不会误触，松手后按钮正常。中心区内短推跟手；推入外围八方向空间立刻进入对应方向持续档，回中停移。小于8px按点按处理；明确拖动取消待触发长按，拖动松手不重设起点或补发方向点击。主滑轨仍按推距续移；方向盘按空间区域判方向。

文首/文末发键前按保存的活动端拦截；一次大幅拖动中的多步逐步检查，不能先发一批越界键再停。收到Blocked后锁住本方向，轻微手抖不会重启或重复改选区；回中心、换方向或新手势可重新移动。中心单击后的兼容click按同次松手坐标识别，不能因DOM重绘误落到遮罩关框，也不能吞掉新按钮的首次点击。

## 删除

页头右侧的删除钮与主键盘删除键**是同一个动作**（同为 `data-action="delete"`，同走 `deleteText()`）：有选区删所选，无选区删光标前一字；点按一次删一次，长按按主键盘同一节奏连删（先 110ms、每档 −8ms、35ms 封底）。无选区时仍可用，不因“已选 0 字”禁用；不新增确认弹窗。

删除后计数立即刷新为 0、复制/剪切转禁用，起点锁定随之失效（原生 `delete()` 本来就会清 anchor），但**面板保持打开**——面板仍只由点框外或改正文收起。松手、指针取消、失焦、指针捕获丢失或面板被收起，都立刻停掉连删；连删期间每次重绘都在新按钮节点上补回按压态。

实现：`preview/app.mjs` 的 `deleteText(keepPanel)`、`scheduleRepeat()`、`clearKeyPress()`、`render()` 的按压态恢复。回归 `selection-delete.test.mjs`。

## 复制与桥接

复制单击执行，保留面板、选区和起点；原生发出复制请求后不立即回读旧剪贴板，由系统实际变化通知刷新预览和历史；空选区禁用复制/剪切，粘贴保留。滑轨松手后的兼容点击只拦截原滑轨/捕获根节点，不能吞掉另一控件的首次点击；其他键盘按键原有防重复保护不变。

网页 `selectionStep()` 用实际字符排版点找相邻行，原生复用宿主上下/左右方向键，斜向随后发 MOVE_HOME/MOVE_END。不按提取文本猜测软换行或把段落边界冒充行边界。

原生锁定选区通过 `SelectionNavigation` 串行处理：**保留宿主原有选区，只用连续 Shift 方向键移动活动终点**，每步等宿主回调（或超时）确认后再走下一步；内部保存逻辑起点与活动终点，回读允许宿主排序，但不再把「回读端点被排序」当成方向键会从右端继续。导航过程中**不逐步重写选区**：小米笔记正文是 WebView，`setEditableSelectionOffsets` 会把写入的反向选区端点排序，而连续 Shift 方向键保留 DOM 的实际起点与活动终点，宿主也据此把视口滚到活动端；旧版「每步收起到终点、再恢复选区」同时破坏了选区方向与滚动目标，已删除，不再恢复（批处理合并路径一并删除）。外部改选区、换输入框、结束会话时取消待执行操作。选区方向、滚动跟随与闪动必须真机确认，`SelectionNavigationTest` 只覆盖模型。

键盘收起时的入口有两路：宿主仍回调 `onUpdateSelection` 时用它建立「待显示」请求；部分宿主只在 `onStartInput` 上带初始非空选区（不再回调），也按同宿主、同端点核销后打开编辑框。请求只在键盘隐藏时建立，`onStartInputView` 消费一次，`onFinishInputView`/`onFinishInput`/收起键盘都作废，避免换输入框后旧请求误弹。宿主完全不提供输入连接或回调时，输入法无从侦测它的触摸。

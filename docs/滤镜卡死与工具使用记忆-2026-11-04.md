# 滤镜卡死与工具使用记忆

## 本次故障依据

用户反馈使用滤镜后退出。K60 的进程退出记录显示，2026-11-04 12:05:47 发生 ANR：`MotionEvent(action=MOVE)` 等待输入响应超过5001ms。旧 crash 缓冲区只有此前测试记录，不能当作本次原因。

系统 DropBox 保存的本次主线程栈位于：`ScreenshotDrawingLayer.onDraw` → `ScreenshotDrawingRenderer.drawStroke` → `LruCache.put/trimToSize` → `sizeOf` → `Bitmap.getAllocationByteCount`。线程名由系统截成 `al.voxfix.debug`，与PID 14093对应；初次通过应用退出接口未取到该段，随后从系统 ANR 条目取得。仅保存本项目主线程段到忽略目录 `.android/filter-anr-main.log`。

修改前增加连续滤镜拖动回归，32次变化中的大图马赛克调用在3秒看门狗内不能完成，报 `SCREENSHOT_FILTER_STABILITY_FAIL: filter cache stalled during a growing drag`。这覆盖实际绘制路径的缓存淘汰，不是仅验证滤镜能处理一张小图。

## 已修复

1. **缓存键不再含可变点集。** 旧缓存用整个 `ScreenshotDrawingStroke` 作键，拖动时其 `points` 是继续变化的列表，hash变化破坏淘汰。现在只用来源矩形、滤镜类型和强度构成不可变键。图片源由渲染器实例固定，颜色、路径遮罩等不影响该滤镜位图，仍在绘制时应用。
2. **淘汰不立即 recycle 位图。** 旧清理逻辑会重复访问已回收的图片；已记录的硬件帧也可能仍引用它。现在保留24MiB缓存上限，淘汰只释放缓存引用，由位图/渲染管线管理生命周期；关闭清空缓存引用。未用吞异常掩盖卡死。
3. **工具记忆跨截图与进程。** 新增 `ScreenshotToolMemory.kt`，生产截图入口与贴图编辑共用 `screenshot-tool-memory` 配置：记住工具组中最后选用项、工具颜色/宽度/字体/描边/填充等创建样式、滤镜与高亮的画笔/矩形各自参数，以及手动设置的起始序号。新截图仍先框选，不自动发起识别或绘图；连续序号在当前文档递增，不把每次自动递增写成下一张截图的默认值。
4. **记忆边界。** 只在确认样式时保存，取消预览不写入；修改一个已选对象不覆盖新建对象的默认样式。枚举、范围、字体、非有限透明度及损坏/错误类型的配置均有回退；最近工具列表和样式JSON有长度界限。存工具选择与参数，不存截图内容或绘图文档。此前未保存的旧选择无法追溯，新记忆从本次更新开始积累。
5. **滑块提交遗漏。** 复现并修复了非拖动调节只停在预览的问题：触摸拖动仍松手一笔提交；无障碍/键盘等非拖动调节直接提交。取消恢复数值与控件显示，切换工具会结束未提交的样式预览。

工具组最近选择与高亮/滤镜子模式的参考仍是 Snow Shot 1.1.8 的 `rememberedDrawingMode` / `selectDrawingItemGroupEntry`；跨应用进程的配置持久化是用户本轮明确要求。未扩大到记录用户操作流水的历史页面。

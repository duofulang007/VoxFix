# 离线翻译（截图工具条首版）

时间：2026-11-03。范围：截图工具条的离线翻译，语言为中英日韩双向；不接剪贴板与屏幕取字面板，不引入前台服务。用户后续要求继续复刻 Snow Shot，已改为逐块原图翻译，并增加整段编辑；维护记录见[Snow Shot 复刻维护](SnowShot复刻维护-2026-11-03.md)。下方旧交接保留作历史，当前呈现以本节为准。

## 模型与兼容处理

- 模型：腾讯 Hy-MT2-1.8B，1.25bit GGUF。
- 文件：`Hy-MT2-1.8B-1.25Bit.gguf`，461,860,800 字节。
- 原始 SHA-256：`cc497fe8f033b52b3b8b00a7669e9661435432f9d4cd43f7ed24400c01507a93`。
- 重标后 SHA-256：`f1e0adf9183536e42589650348305176c570be9e588fe6955bcdef82d7f66a01`（只改类型字段，长度不变）。桌面 `models/hy-mt2/` 与手机 `files/translate/` 里的都是这一份；`TranslateModelStore.ready()` 只比长度，不比重标后的哈希。
- 许可：Apache-2.0；权重不入库、不随 APK 分发。
- 上游：<https://huggingface.co/tencent/Hy-MT2-1.8B-1.25Bit-GGUF>；国内镜像 `hf-mirror.com`，备用 ModelScope `AngelSlim/Hy-MT2-1.8B-1.25Bit-GGUF`。

**张量类型改写**：官方文件把 224 个张量标为旧 STQ_0 类型 `42`；上游随后把 `42` 分配给 Q2_0，STQ1_0 改为 `43`。因此加载前必须把类型字段 42 改为 43，否则会按 Q2_0 解析失败。本轮不改权重数据，只改 224 个四字节类型字段：

- 偏移表：`android/app/src/main/assets/translate/stq-type-offsets.bin`（896 字节，224 个 u32）。
- 手机端：下载并校验原始 SHA-256 后，由 `TranslateModelPatcher` 在首次加载时改写；幂等。
- 桌面端：`tools/prepare_translate_model.py` 下载并校验后改写同一批字段。
- 与上游 Android 移植 `dodola/hy-mt2-android` 的处理一致；该移植同时说明 1.25bit 依赖 STQ1_0 内核。

不采用 v2 `Hy-MT2-1.8B-1.25bit-v2.gguf`：其张量类型为 40，属另一套量化，不能由同一内核直接加载。

## 运行库

- llama.cpp 固定提交 `de7fa0a3c6a2e1b4cd9f22eb8d6bf5b12dbdb63b`（2026-10-08，MIT）。
- 补丁：`tools/patches/llama.cpp-de7fa0a/0001–0005`，来自 `dodola/hy-mt2-android`（MIT）；0001–0003 对应上游仍开放的 PR #22836，0004 为预填充优化，0005 修复 `GGML_BACKEND_DL` 线程池。
- 构建：CMake + Ninja + NDK r28b，只编 `arm64-v8a`，`c++_static` 链接成单个 `libvoxfix_translate.so`，`-Wl,-z,max-page-size=16384`。
- 参数：4 线程、`n_ctx=2048`、`n_batch=256`、KV `Q8_0`、贪心解码、单块超时 60 秒。
- 加载：首次点「翻译」才加载；加载前请求键盘释放语音模型；空闲 120 秒释放；`onTrimMemory`、锁屏、关闭截图会话时释放。
- 不改动 sherpa 1.13.8、onnxruntime 1.17.3 与语音链路。

## 交付与存储

- APK 不打包权重；加运行库后从 403.27MB 涨到 410.39MB（`libvoxfix_translate.so` 6,060,904B）。
- 首次使用下载：主源 `hf-mirror.com`（支持 Range），备源 ModelScope（302 到签名 CDN）。
- 落盘：`filesDir/translate/hy-mt2-1.8b-1.25bit.gguf`，续传 `.part`。
- 断点续传：`Accept-Encoding: identity`；逐跳重设 `Range`；`206` 追加、`200` 截断重下、`416` 删除重下。
- 校验：长度 461,860,800 + SHA-256 通过后才改名；失败删除并提示重试。
- 开始前要求可用空间 ≥620MB；删除只在空闲时允许。

## 界面

- 最新呈现：不使用进度条或识别/翻译中的提示文字；OCR完成后直接整批上屏，翻译通过真实token回调逐步回填。处理时只保留一个取消按钮，语言条在完成后恢复。

- 框选后即可并列选择识别或翻译。翻译按钮内部先OCR、再翻译；不要求用户先手动识别。已有识别/编辑草稿时复用当前文字，不重复OCR；只有内部OCR阶段读取图片像素，模型阶段只读文字。
- 工具条按阶段收起入口：框选前整屏/关闭；框选后识别/翻译/保存/关闭；出字后隐藏整屏与重复识别。译文态保留一个「显示原文」动作及保存/复制/原图/编辑/关闭，不重复显示翻译启动入口。
- 「翻译」在有效框选后即出现；内部OCR及翻译期间同一按钮均可取消。取消后丢弃迟到OCR结果，不自动继续翻译。
- 语言切换**始终一行**：`自动检测 ⇄ 简体中文`。点任一侧，整行原地变成语言选项（源：自动检测/简体中文/英文/日文/韩文；目标不含自动检测），选完回到单行；中间 `⇄` 交换方向。默认 `自动检测 → 简体中文`，自动检测不会覆盖已选目标；重复选相同语言不重译。上次选择写入 `SharedPreferences("screen-text")`。
- 原图译文：依次翻译当前识别文字块，保留块坐标、采样背景与黑白字色，自动换行并缩放字号以适应原块；原文与译文是独立草稿，不再弹整段译文卡片。取消或失败不把半成品写回原文。
- 「复制」在译文可见时复制译文，标签变为「复制译文」。复制成功/失败改用覆盖层内的白色小胶囊提示（1.6 秒后消失），不再依赖系统 Toast：Android 12+ 对后台窗口的 Toast 有限制，截图覆盖层下可能不显示。
- 点击取字/译文文字或编辑按钮，均打开正常字号的可滚动统一文本容器，支持跨行选择与新增换行；长文输入不缩字，只移动编辑区避让键盘，完成后回到原图排版。保存导出当前可见的原文、译文或原图。
- 长译文按原块适配字号，窄小文字块可能字很小；尚不支持自动段落合并、旋转与透视排版。整段编辑用正常字号滚动，避免只能操作小字。

## K60 实测（2026-11-03）

| 项目 | 数值 | 说明 |
| --- | --- | --- |
| 模型加载 | 645–923ms | 页缓存已热；首次冷加载未单独测 |
| 短句总耗时 | 2068–3771ms | 同句重复测量；设备在播直播时明显偏慢 |
| 预填充 | 1057–1059ms / 34 token（约 32 t/s） | 含模板与提示词，稳定 |
| 解码 | 1005–2708ms / 13 token（约 4.8–13 t/s） | 4 线程、绑定 cpu4–7；随设备负载/降频波动 |
| 输出 | 「会议于上午9:30在1204号房间开始。」 | 数字与房间号保留 |

结论：短句可用；按 13 t/s 估算 300 字约 25–30 秒，按最低 4.8 t/s 会更久，长文体验不合格。下一步应在不换模型的前提下测线程数/绑核与 KV 参数，仍不达标再考虑 Q4_0 或更小模型。速度数据不外推到其他机型，也不把桌面 x86 的 4 t/s 当作 K60 数据。

### 重建步骤


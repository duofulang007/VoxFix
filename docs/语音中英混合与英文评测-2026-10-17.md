# 语音中英混合、英文句子与单词评测（2026-10-17）

结论：这组清晰合成音频中，英文整句明显好于独立单词和中英夹杂。短板包括夹杂英文漏词、技术名称/同音词、英文二遍纠错被安全规则拦截，以及实时分段结果比孤立模型更差。首轮只做评测、未改生产逻辑；同日随后完成实时分段与英文二遍采用的最小修复并保留数据安装，实时整条匹配 6/40 → 22/40，见文末「实时分段与英文二遍采用修复」。

## 要补的短板，按优先级

1. **先查实时分段与尾部完整性。** 同一段GitHub音频，孤立流式是“请把代码提交到”，实时为“请把代码提交到到”；API例子末尾“数据”少一个字，VoxFix从“VOX FIX”变成“Vox fi”。已经复现链路额外劣化，但尚未定位VAD分段、重置/拼接或尾段上下文中哪个环节负责。应先记录同一固定样本的分段边界、逐段流式/二遍结果，保留松手不等待的约定，不能只换模型掩盖。
2. **英文二遍纠错需要更细的采用规则。** `SpeechEngine.refine` 对英文比较不一致立即退回流式；`bug`、`GitHub`、`offline`的正确二遍因此不能纠正漏词/错词。当前保护也避免 `PDF → PF` 等劣化。应以固定语料做受限对照，保留数字/否定保护；不能直接取消全部安全门槛或无条件使用二遍。
3. **英文词界保护有缺口。** `refine` 先去除空白再比较英文，`JSON` 与 `J S O N`、`VOXFIX` 与 `VOX FIX`被当成一样，能接受错误拆词。本轮组合检查的混合样本从流式5/16降至4/16，包含已正确的JSON被拆开、已正确的“我想用VOXFIX”被改成“或想用VOX FIX”。应单独保护词界与缩写，不能只比较去空格的字符串。
4. **技术词/专名、同音词需要上下文与受控词表。** `cache/cash`声学相同，脱离上下文不能唯一判断；Kotlin、GitHub、VoxFix及git命令也不稳定。安卓流式当前未配置热词，拼音个人词库不会自动进入ASR。若接入术语，只做用户明确提供的词表或明确词表来源，并验证误替换；不能把任何cash全局换成cache，也不自动收集日常录音/转写训练。
5. **短词、语种策略及输出格式。** 独立短词上下文少，本组甚至出现空结果。固定zh也可能加重短英文的汉字倾向，但并非唯一原因。专名恢复（WiFi/GitHub/Python/Android）和疑问句问号仍弱：当前大小写策略会将不在缩写表内的全大写词转小写，`punctuate`仅补句末句号，不能推断英文疑问语气。内容修复优先于格式。

## 2026-10-17 实时分段与英文二遍采用修复（已安装，K60 固定音频复测）

结论：实时链路比孤立调用差的主因不是 VAD 判错，而是「每次停顿立刻 `getResult()` 再 `reset()`」。
zipformer 每 320ms 才输出一块，停顿那一刻最后一块往往还没算完，`reset()` 把这段尾音永久丢掉；
同时每个停顿都重置解码器，一句话被切成没有左上下文的片段。修复后同一 40 条固定音频的实时整条
完全匹配 6/40 → 22/40，词错误率 0.280 → 0.208，16 条改善、0 条整条退化；仍有 4 条拼接样本
「更长但更乱」，列为遗留。

### 实测证据（K60 当前安装版，同一固定音频）

- 新增 `ASR_SEG` 逐段日志（只写日志，不改行为）显示提交时读到的文本比最终少最后一块：
  `word-3 keyboard` 在 `fedMs=900 / audioMs=512` 提交，文本 `Keybo`；`word-2 computer` 为 `Comp`；
  `word-15 API` 为 `Ap`；`word-1 hello` 为 `Hell`。同一文件孤立调用全部正确，差异只出现在提交/重置环节。
- 电脑用同一模型复现同一段音频：停顿处读到的文本是 `请把代码提交`，在**同一个 stream** 上再投
  120ms 静音后变成 `请把代码提交到`；`这` → `这个`。实测解码块间隔 320ms，对应丢掉的 1～4 个字。
- 分段边界（电脑 silero，本版 `min_silence_duration=0.25`）：拼接样本在中英拼接处有 0.76～0.99s
  间隙，被切成 2～3 段（`这个｜bug｜已经修好了`）；后半段只听到英文时，流式会补出 `到`、`放开`、
  `派散` 这类没有声学来源的字，拼回去就是 `请把代码提交到到`。
- `refine` 比较前把空白全删：`JSON` 与 `J S O N`、`VOXFIX` 与 `VOX FIX` 成了同一个串，二遍的拆词
  被放进来（`mix-switch-5` 的 refined 由正确变成 `J S O N`）；英文内容一旦不同就整段退回流式，
  `bug`、`OFFLINE` 因此无法采用。

### 改动（`SpeechEngine.kt` + 回归测试，未换模型、未加依赖）

1. `commitSegment` 读结果前先 `flushDecoder()`：往同一个 stream 补两块 200ms 静音并解码，让已经
   收下、还差最后一块的语音落地后再 `getResult()` / `reset()`。收尾那一刀 `finishing` 不投音频，
   交给已有的 `inputFinished()`，不增加松手等待。
2. 停顿后再等 0.25s 才真正切段（`COMMIT_SILENCE_SAMPLES`）。本版 silero 的 `min_silence` 是 0.25s，
   原逻辑「报出即切」等于 0.25s 换气也算一句；加 0.25s 后门槛回到 0.5s 静音。停顿瞬间仍先提交一次
   二遍（`early`），没有新语音并入就沿用它，因此二遍开始时间不变、松手不等待。测过 0.9s 的长合并：
   1s 内的句子并成一段后混合样本从 5/16 掉到 4/16，未采用。
3. `commitSegment` 不再因为「没有 VAD 段」就丢掉解码器里已有的文字（不足最短语音的尾音）。
4. `refine`：改为比较英文**词序列**（撇号归一），词界/词数变化一律算差异；数字与否定词保护保留。
   只放行两类能自证的二遍改写——纯中文流式补出完整英文词（汉字须逐字相同，补进来的词要 ≥3 字母
   或在既有缩写表里，挡掉 `BU` 这类半截词），纯英文内容且字母总数不变的改写（`ARE FINE → OFFLINE`；
   `PDF → PF`、`COMPUTER → MPUTER`、`API → APPI` 字母数变了仍然拒绝）。
5. `comparable` 保留英文词之间的空格，其它空白照删。

### 遗留（未通过，不要当成已修好）

- 拼接样本里 0.8s 级句内间隙仍会切段，片段本身可能补出 `放开`/`派散`/`A p I`：`mix-switch-1/3/5/6`
  修复后「更长但更乱」。真人句内 0.8s 停顿是否常见、要不要为它接受更长合并，需要真人录音再定；
  本轮测到的 0.9s 合并反而降低整条匹配，未采用。
- 技术词/专名仍不稳定：`Kotlin → Code`、`VoxFix → Vox fix`、`GitHub` 单独读正确但句中常错、
  `cache → cash` 需要上下文。本轮没有接流式热词或术语表，也没有自动收集录音/转写。
- 英文问号与专名大小写（`Github`、`Vox fix`）未处理，按约定排在内容完整性之后。
- 未验证：真人口音与自然中英混说、噪声/远场、真实麦克风首尾、未预加载的冷启动，以及二遍在 K60
  的真实耗时分布。以上结论只代表这 40 条合成语音的实时链路，不代表日常准确率。

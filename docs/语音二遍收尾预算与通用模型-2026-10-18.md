# 二遍收尾预算与通用 SenseVoice（2026-10-18）

本轮把「松手后要不要等二遍」定成一次有限预算，同时把二遍权重从小语种微调版换回通用版。
两件事互相依赖：预算要能换来真实改写，前提是二遍模型给出的结果可信。

## 1. 二遍模型：换成通用 SenseVoiceSmall（2024-07-17）

| | 旧 | 新 |
|---|---|---|
| 权重 | `sherpa-onnx-sense-voice-zh-en-ja-ko-yue-int8-2025-09-09` | `sherpa-onnx-sense-voice-zh-en-ja-ko-yue-2024-07-17` |
| 出处 | ASLP-lab 粤语微调 | ModelScope `iic/SenseVoiceSmall` → sherpa 官方 ONNX 转换 |
| model.int8.onnx sha256 | `12ca1a2a…` | `c71f0ce00bec95b07744e116345e33d8cbbe08cef896382cf907bf4b51a2cd51` |
| tokens.txt sha256 | `f449eb28…` | `f449eb28…`（同一份 tokens） |
| 许可 | Apache-2.0 | Apache-2.0 |

换的理由是两条实测，不是「新版/旧版」这种说法：

1. **通用版的 LID 能分辨语种，微调版不能。** 同一条普通话夹英文的固定音频 `mix-huihui-1`：

   | 权重 | 文本 | `lang` |
   |---|---|---|
   | 2024 通用 | `这个bug已经修好了。` | `<|zh|>` |
   | 2025 微调 | `这个 BUG 已经修好了` | `<|yue|>` |

   微调版在普通话、纯英文上同样报 `<|yue|>`（上一轮 9/9）。标签没有分辨力时，「按 LID 路由」
   只能是提示；换成通用版之后才真的能当判据用。

2. **通用版自带标点与 ITN。** 同一权重、`language=auto`：

   - `use_itn=True` → `今天天气很好，我们一起出去散步。`
   - `use_itn=False` → `今天天气很好我们一起出去散步`

   所以 CT-Transformer 标点（`Punctuator.kt`）不再是唯一标点来源，而是**超时退回实时文字时的补位**。
   相应地修正了 `Punctuator.kt`、`tools/setup_voice.py` 里「这条权重不产标点」的旧注释 —— 那句话对
   2025 微调版权重成立，对现在的通用版不成立。

连带改动：

- `refine(raw, candidate, lang)` 的 `adoptsForeign` 放宽粤语判据：通用版粤语正文不一定带专用字
  （`两只小企鹅都有嘢食` 只有「嘢」），改为「正文含汉字 + 长度比 0.35–2.8」；日文仍要假名、
  韩文仍要谚文；`lang=""` 与 `<|zh|>` 走原严格比较。旧判据（长句要 ≥2 个不同粤语字）在通用版上
  会误杀真实结果，见单测 `adoptsGeneralModelCantoneseWithoutRequiringSpecialCharacters`。
- 上游记录修正：`models/sensevoice/UPSTREAM.md`、`android/app/src/main/licenses/sensevoice/UPSTREAM.md`
  原来写的是 `ASLP-lab/WSYue-ASR sensevoice_small_yue`，与实测哈希不符，已按通用版权重改正。
- 构建：`tools/prepare_streaming_models.py` 现在把二遍图也做 EXTENDED_CPU 预优化（receipt 里记录），
  `stageModels` 排除 `sensevoice/*.onnx`、只拷优化产物，避免包里同时出现原始图与优化图。

## 2. 松手预算：最后一句最多等 350ms

- `SpeechSegment.finish(waitMs)`：只在松手时对**最后一句**等一次，`FINAL_SECOND_PASS_BUDGET_MS = 350`；
  窗口同时覆盖流式补尾（`inputFinished` + `flushDecoder`）与二遍解码，超时就取消 future、用已有实时文字。
- 松手不再复用「停顿那一刻提交的 early 二遍」，改为按完整样本重投一次（`finishing` 期间也把音频收进
  同一段），否则最后一句拿不到包含尾音的候选。
- 取消：`commitSegment` 后与 fold 后各补一次 `isCancelled()` 判定，松手过程被取消时返回空串。
- **冷启动闸门** `releaseBudget(deadline, isLast, secondLoaded)`：二遍模型还没加载完就不等。等待期全花
  在加载上（K60 实测 0.78–0.84s），预算烧满也拿不到改写，纯属白等。

## 已知问题（本轮不修）

1. **VAD 起点会丢前导语音。** `mix-huihui-1` 的 VAD 只报 710–1824ms，前 0.6s 的「这个bug」没进二遍
   （二遍只得到 `已经修好了。`）。整段音频 vs VAD 裁剪对照：

   | 用例 | 整段 | VAD 裁剪 |
   |---|---|---|
   | mix-huihui-1 | 这个bug已经修好了。 | 已经修好了。 |
   | mix-huihui-5 | 这个AP返回的是JsON数据。 | 这个AP返回的是JsN数据。 |
   | public-para-yue | 有无人知道湾仔活道系点去㗎。 | 有冇人知道湾仔活道系点去噶。 |

   整段并非全面更好（`public-para-yue` 整段丢「冇」），所以保持 VAD 裁剪，不做整段替换。
2. **流式基座本身丢词内英文**：`这个bug` 在流式侧就是 `这个`，二遍又没拿到那 0.6s，最终文本仍缺
   `bug`。这是 2023-02-20 双语基座的能力问题，要换流式模型才能解决。
3. `apple` 这条合成语料两个模型都出空串（79 条里唯一）。
4. 真人粤语仍未验收：粤语语料是 sherpa 公开测试录音，其余是本地合成。

# 语音标点恢复（2026-10-17）

修复「安卓语音输入没有标点」。只记录本轮实测结论与实现边界，旧描述中"SenseVoice 二遍顺便给标点"的说法不再成立。

## 一、原因：不是没启用 ITN，是这条权重根本不产标点

用桌面 sherpa-onnx 1.13.6 加仓库内同一份 `models/sensevoice/model.int8.onnx`，对固定音频
`mix-huihui-0/1/2`（中文与中英混合）与 `sentence-2`（英文疑问句）逐一识别：

| language | use_itn | 标点数 |
|---|---|---|
| zh | true | 0 |
| zh | false | 0 |
| auto | true | 0 |
| auto | false | 0 |

四组输出**逐字相同**，中英文都没有任何标点，疑问句 `COULD YOU TURN OFF THE LIGHT AND CLOSE THE DOOR`
也是全大写无标点。`models/sensevoice/tokens.txt` 里确实存在「，。？；：、」token
（第 24880 行 `，`、9730 行 `。`、24884 行 `？`），但推理结果里从不出现。

结论：**不能把"启用 ITN"或"二遍跑完"当作标点可用**。标点必须由独立环节补。

另外两处与标点缺失叠加的问题：

- `transcribe()` 收尾先置 `finishing = true`，而 `commitSegment()` 只在未 `finishing` 且仍在录音时
  才提交二遍，因此**尾段从不启动二遍**；`SpeechSegment.finish()` 对未完成的结果 `cancel(false)` 后不再采用。
- 原 `punctuate()` 只在句末补 `。`/`.`，句子内部逗号、疑问句问号都不会出现。

## 二、方案：CT-Transformer 离线标点，只吃文本

sherpa-onnx 1.13.8 的 AAR 里已带 `OfflinePunctuation`、`OfflinePunctuationConfig`、
`OfflinePunctuationModelConfig`，不需要升级库、不更换 ASR、不引入大模型。

- 模型：`sherpa-onnx-punct-ct-transformer-zh-en-vocab272727-2024-04-12-int8`
- 来源与校验见 `android/app/src/main/licenses/punctuation/UPSTREAM.md`
- 包内模型 `model.int8.onnx` 75,519,198 字节（与项目早期调研记录的 CT-Transformer 标点模型大小一致）
- Apache-2.0，词表与符号集内嵌在 onnx 元数据，无需额外 tokens 文件

### 为什么这样能覆盖尾段和二遍未完成

标点模型**只输入文本、不需要音频**，与二遍完全解耦：

- 二遍完成 → 用二遍文本加标点；
- 二遍未完成 / 尾段直接松手 → 用流式文本加标点；
- 都不等待：模型加载在首次出字后于后台开始（实测 579 ms），松手时最多等 150 ms，
  超时直接退回流式文本，仍由 `punctuate()` 补句末。

### 三条必须遵守的顺序与边界

1. **标点必须在 `formatNumbers` 之前**。模型会破坏阿拉伯数字：`这个一共120.5元` 输出成
   `这个一共120 . 5元`；而识别原文是「这个一共一百二十点五元」，模型处理正常。
2. **交给模型前先剥句读类标点**。模型对已带标点的文本会叠标点：
   `你好，请问洗手间在哪里？` → `你好，，请问洗手间在哪里？？`。只剥 `，。？！；：、…,?!;`，
   不动 `.`（保护小数点）。
3. **纯英文与含引号括号的正文不交给模型**。模型是中文优先的，整句英文会得到
   `HELLO WORLD，HOW ARE YOU？` 这种中文逗号；引号前会被插入逗号
   （`他说“明天见”就走了` → `他说“，明天见”就走了`）。这两类保持原有句末规则。

## 三、真机固定语料回归

语料 `.android/punct-audit-20261017/fixtures`：Huihui 合成的 6 条中文（16 kHz f32）
加既有中英混合与英文疑问样本，共 9 条。测试 `VoicePunctuationSmoke` 按 20 ms 真实节拍
走完整 `SpeechEngine.transcribe`，断言真实模型输出里的标点。

每条跑两种收尾：带 800 ms 尾静音（二遍有机会完成）与无尾静音（说完立刻松手）。

| 用例 | 期望 | 结果 |
|---|---|---|
| zh-clause-0 中文多分句 | `，`×2 | `我今天上午去了公司，下午下午去了医院，晚上还要加班。` |
| zh-question-0 疑问句（吗） | `？` | `你明天下午有空吗？` |
| zh-question-1 疑问句（怎么） | `？` | `这个功能是怎么实现的？` |
| zh-short-0 短句 | `。` | `好的。` |
| zh-numeric-0 数字金额 | `。` | `这个一共123元。` |
| zh-punct-0 内部已有标点 | `？` | `你好，请问洗手间在哪里？` |
| mix-huihui-0 中英混合 | `。` | `请帮我打开wifi设置。` |
| mix-huihui-2 中英混合缩写 | `。` | `把文件保存成PDF格式。` |
| sentence-2 英文疑问句 | `?` | `Could you turn off the light and close the door?` |

**18/18 通过**（9 条 × 2 种收尾）。冷启动（全新引擎首个请求）有标点；取消返回空串。

| 指标 | 数值 |

| 松手收尾（中文） | 43–92 ms |
| 松手收尾（中英混合，无尾静音） | 84–252 ms |
| 松手收尾（英文疑问句，无尾静音） | 80–392 ms |

**限制要说明**：612 MB 是「流式 ASR + 二遍 SenseVoice + VAD + 标点模型 + 20 次推理」的整条链路峰值，
本轮没有单独切分标点模型自身的增量。标点模型与二遍同生命周期，跟着既有的"空闲 30 秒释放"一起回收，
不额外常驻。

## 五、本轮未覆盖

- **英文疑问句之外的英文标点**：整句英文靠句首疑问词决定 `?`/`.`，不经过标点模型，
  英文内部逗号仍不会出现。要补需要英文标点能力，本轮未做。
- **`zh-clause-0` 出现「下午下午」重复**：这是流式 VAD 分段拼接把上一段尾词重复了一次，
  与标点无关（桌面单模型识别该音频无重复）。属于既有分段问题，未在本次修改。
- **真人麦克风验收**：本轮只跑固定音频。真人语速、口音、噪声下的标点质量需要用户实际说话确认；
  固定音频通过不等于真人通过。

1一比一对照

左边是你给的截图里裁出来的球（原图 512×512），右边是按同一套参数画的。同一尺寸并排，方便逐点看差别。

三条从截图量出来的硬指标（不是感觉）：
① 球是硬边——截图里球外 6 个像素全是 #fcfcfc，没有任何光晕或投影；
② 蓝色集中在上沿一整条（正上 #4374ea、右上 #5080ee），并顺着左边往下渗（左中 #618bed）；
③ 从球心横向看，左中 #618bed → 右中 #dfe5fb，一条水平线上从蓝到白跨度极大 ⇒ 蓝白分界其实是斜的，不是上下分的。

2检测到人声 → 变大、动起来

安静时只做极慢的内部翻涌（「它还活着」）；一旦检测到人声，整颗球跟着音量胀大，同时球内翻涌明显加快。下面是真跑的，拖动滑杆或点自动演示都能看。

胀大倍率 1 + level × 0.16（最大 1.16×）；快旋层用 opacity 浮出而不是改动画周期，所以不会中途跳帧。

三档对比（同一时刻的静止帧）

安静 1.00×

放大倍率刻意压在 1.16× 以内：再大就会挤到「倾听中」那行字，也会让面板边界显得紧张。

这里有个必须做对的细节：音量是每帧写入的 --level。绝不能给 transform 挂 CSS 过渡——挂了就会被 200ms 的缓动拖成「反应迟钝」。正确做法是包络写在 JS 里：快起（attack ≈ 60ms）+ 慢落（release ≈ 320ms），CSS 侧零过渡。

3平时就是「沉浸地在那里动」

没有任何指示加载的转圈、进度条、箭头。球内白雾一直在极慢地翻涌与旋转，这样安静时也像有生命。

球内的雾在极慢地翻涌（46s 转一圈）；上面这颗同时在模拟「有人在说话」
为什么用「慢旋 + 单独一层快旋」而不是「球在动」：球本身一直在动会让人一直盯着它、也会让面板显得躁；而球稳定、内部在动，才像 ChatGPT Live 那种「安静但活着」。

4上滑取消：跟手 + 转红

按住空格说话时，手指往上滑，整颗球贴着手指走（近乎 1:1），同时跟着缩小并交叉淡入红调。没有额外的环、靶心或箭头。

上滑距离 0px

位移 0.9 × 手指（旧版是 0.55，所以显得拖）；缩小 1 → 0.66；红色由 --red 交叉淡入，不加过渡，保证完全跟手。

5关闭特效（三个方案，点一下播放）

退场要和球在同一个语汇里，不能突然换成一个别的形状。都控制在 0.34s 以内，收得干脆。

甲 · 内收成点 推荐

球从外向内缩成一点淡出（340ms），同时从球心向外扩散一圈极淡的波纹——正好是「被吸回话筒键」的语感，和呼出反向。

乙 · 化开

球原地轻微放大、模糊度上升、透明度归零（360ms）。像雾散掉，最「无痕」，配取消收尾很自然。

丙 · 沉回话筒键

球向下平移出面板下沿、微微缩小并淡出（340ms）。方向感最强——「它回到了空格键那里」。

我的建议是甲。唤出时球是从话筒键方向「长出来」的，甲是它的严格反向，一进一出成对；乙最柔和但方向感弱；丙方向感最强，不过向下沉会撞到键盘下方的空白区，面板短的时候会显得空。

# 语音语种自适应：二遍不再写死中文（2026-10-18）

## 起因

用户问「language 写死别写死，粤语需求呢，能自适应识别吗」。原实现 `SpeechEngine.kt` 把
`OfflineSenseVoiceModelConfig(language = "zh")` 写死，粤语/日/韩进不了模型的路。

## 代码事实（sherpa-onnx 1.13.8，aar 反编译 + 上游源码核对）

- `OfflineSenseVoiceModelConfig(language)` 只是查表：模型元数据里有 `lang_auto` / `lang_zh` /
  `lang_en` / `lang_ja` / `lang_ko` / `lang_yue` 六个 token id，原生侧用 `lang2id` 取 id；
  写不认识的值会打 `Unknown language: %s. Use 0 instead.` 并退回 **0 = auto**。
- `auto` 不是额外推理：语种 token 本来就由模型自己吐。
- 结果首 token 就是语种标签，JNI 暴露为 `OfflineRecognizerResult.lang`
  （`javap` 确认 `getLang()` 存在；`ConvertSenseVoiceResult` 里 `r.lang = sym_table[src.tokens[0]]`）。
  所以「自适应」在 API 层面本来是现成的。

## 实测：这条 int8 权重的标签没有分辨力

`tools/asr_eval.py --audio .android/punct-audit-20261017/fixtures`（9 条，PC，RTX/CPU 4 线程）：

| 配置 | 9 条文本 | 耗时合计 | `lang` |
|---|---|---|---|
| `sv_zh` | 与 auto 逐字相同 | 543 ms | **恒为 `<|yue|>`** |
| `sv_auto` | 与 zh 逐字相同 | 563 ms | **恒为 `<|yue|>`** |

补充单条试验（`zh-short-0` 普通话「好的」、`sentence-2` 纯英文问候）：把语言写死成 `zh` /
`auto` / `yue` 三档，文本都一样，`lang` 仍是 `<|yue|>`。即语种标签与音频内容无关，
**不能当作路由依据**。

结论：`language` 换 auto 只做到「不写死」，并不能换来可靠的自动语种判定。

## 实现（本次改动）

- `SpeechEngine.kt`：`SECOND_PASS_LANGUAGE = "auto"`；二遍解码返回 `SecondPass(text, lang)`
  （新类型在 `SpeechSegment.kt`），语种随结果一起带给采用逻辑。
- `refine(raw, candidate, lang = "")` 新增第四道判据 `adoptsForeign`：报出 yue/ja/ko 且
  **正文能自证**时整句采用，跳过 0.85 相似度门（流式基座只有中英，粤/日/韩时它吐的是同音
  汉字，相似度天然极低，用相似度判等于把唯一正确的一路丢掉）。
- 自证条件：日文看假名、韩文看谚文；粤语看粤语专用字，**长句（≥8 字）要求两个以上不同的
  粤语字**（因为标签恒报 yue，一个「唔」不足以作证）。
- 长度闸 `saneLength`：候选/流式的字数量比必须落在 0.35–2.8，挡噪声上「一个字复读成整句」。
- 标签对不上正文时**落回原来的严格比较**，`lang=""`（旧调用、单测）行为完全不变。

## 回归

`testDebugUnitTest` 全绿（`SpeechEngineTest` 23 项、`SpeechSegmentTest` 5 项，含新增：

- `adoptsNonMandarinSecondPassWhenTheLabelIsCorroboratedByTheText`
- `ignoresALanguageLabelTheTextDoesNotSupport`
- `rejectsForeignAdoptionWhenTheLengthIsImplausible`
- `aSingleCantoneseCharIsNotEnoughForALongSentence`
- `cantoneseSecondPassReplacesMandarinHomophones`
- `foreignLabelWithoutEvidenceStillFallsBack`

## 尚未验证

**粤语音频本身能不能被转写**。缺语料：项目固定音频全是普通话；本机只有 zh-CN 音色
（Huihui/Kangkang/Yaoyao），下载公开粤语样例被网络挡住。需要用户在真机上用粤语说一句，
或提供一条 16 kHz 粤语 wav。

## 结论

1. 二遍语种已不写死，语种随结果上报，采用与否由正文证据决定。
2. 靠「模型标签自适应」这条路在这条 int8 权重上走不通，别再花时间在 `language` 参数上。
3. 实时文字（第一遍）仍是中英基座，粤语只能等句段提交/松手时被二遍改写；要有实时粤语，
   得换流式基座（公开可用的流式粤语模型目前没有，只有非流式的 `zipformer-cantonese-2024-03-13`）。

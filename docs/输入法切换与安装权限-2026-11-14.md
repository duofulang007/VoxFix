# 输入法切换与安装权限（2026-11-14）

设备：小米 K60（adb 序列号 `6959dba1`，Android 15 / HyperOS）。证据目录 `.android/ime-switch-repro-20261114/`。

## 1. 真机复现结论（Phase 0）

### 1.1 基线（只读取证）

| 项目 | 结果 |
|---|---|
| `ime list -s` | `com.iflytek.inputmethod.miui/.FlyIME`、`local.voxfix.debug/.VoxFixImeService` |
| `enabled_input_methods` | 讯飞小米版 : 搜狗小米版 : VoxFix（三者全部已启用） |
| `default_input_method` | **`local.voxfix.debug/.VoxFixImeService`（VoxFix 当前就是默认）** |
| `dumpsys input_method` | `mCurMethodId=local.voxfix.debug/.VoxFixImeService` |
| `input_methods_subtype_history` | 含 VoxFix 记录 → 它曾在系统 picker 中正常出现并被选中 |

### 1.2 系统页面取证（截图在证据目录）

1. **「选择输入法」对话框**（点设置页「当前输入法」弹出）：MIUI 定制弹层，分「讯飞输入法小米版」与「其他输入法」两组；**VoxFix（中文 · 本地语音）出现在「其他输入法」组，带勾选标记**。picker 环节当前正常。
2. **「语言与输入法」主页**（`com.android.settings/.inputmethod.AvailableVirtualKeyboardActivity`）：显示「当前输入法 VoxFix / 输入法管理 / 安全键盘（已开启）/ 隐私输入模式（已关闭，仅支持小米版输入法）」。**该深链可用，作为向导跳转目标。**
3. **`InputMethodAndSubtypeEnablerActivity` 在 HyperOS 上是空白壳**（标题「输入法键盘设置」无内容）——AOSP 启用页被 MIUI 架空，**向导不得跳这个组件**；启用管理实际在主页的「输入法管理」子项。
4. **安全中心存在 `com.miui.securitycenter/com.miui.permcenter.install.AdbInputApplyActivity`**（adb 输入法授权申请页）。本次未触发（当前 VoxFix 状态正常），但说明 HyperOS 对 adb 安装的输入法存在一次性授权环节。
5. **安全键盘已开启**：密码输入框强制小米安全键盘（`com.miui.securityinputmethod` 出现在 subtype_history），第三方输入法在密码场景必然不可见，属系统设计，无法绕过。

### 1.3 受阻环节判定

系统级切换链路（启用 → picker 选择 → 默认生效）**当前全部正常**。「已启用但选择列表不出现」的历史体感最可能来自：

- **讯飞键盘内部切换菜单**：那是讯飞私有列表，只含讯飞系（docs/USB真机验收.md 已记录无法插入 VoxFix）——用户在那里永远找不到 VoxFix，最易造成「识别不到」印象；
- 新装/刚启用时未完成「输入法管理」勾选或安全中心对 adb 输入法的一次性授权；
- 密码框等安全键盘接管场景。

**结论对设计的约束**：两步向导成立；步骤 2 用 `showInputMethodPicker()`（MIUI 弹层正常）；深链用 `AvailableVirtualKeyboardActivity`；文案明确「不要在讯飞键盘的菜单里找」。`ime set` 状态变更实验信息增量低（VoxFix 已是默认、picker 正常），**跳过，不做**；App 直写 Secure 的一键切换可行性由 Phase 1 实装后的应用内探针在真机走查中验证。

## 2. 他人常见做法与本机差异（应对思路）

**常见做法（搜狗 / 讯飞 / Gboard 首启向导）**：依赖「系统 picker 必然列出已启用输入法」这一前提——①跳系统输入法设置页让用户勾选启用；②`onResume` 检测 `getEnabledInputMethodList()` 打勾；③调 `showInputMethodPicker()` 让用户点选；④检测 `Settings.Secure.DEFAULT_INPUT_METHOD` 完成收尾。

**本机差异（HyperOS）**：前提基本成立（picker 正常），但有四个坑——启用管理不在 AOSP 组件（空白壳）；讯飞键盘内部菜单是私有列表易误导；安全键盘接管密码场景；安全中心对 adb 输入法有一次性授权页。

**应对**：
1. 向导两级检测（已启用 / 已是默认），onResume 自动刷新；
2. 步骤 2 主按钮 `showInputMethodPicker()`，异常回退深链 `AvailableVirtualKeyboardActivity`；
3. 文案明确「在系统『选择输入法』弹层里选，不要在讯飞键盘菜单里找」；
4. 已授予 `WRITE_SECURE_SETTINGS` 的设备额外提供「一键切换」（直写 Secure 设置绕过 picker），未授权设备 adb 仅作次级说明；
5. 关于「安全键盘」场景写入文档说明，不做无谓绕过。

## 3. 权限与安装（全量清单，随阶段维护）

| 权限 | 类型 | 用途 | 用户动作 |
|---|---|---|---|
| RECORD_AUDIO | 运行时 | 语音识别 | 首次弹窗允许 |
| INTERNET | 普通 | 表情搜索 / 更新检查 | 自动 |
| WRITE_SECURE_SETTINGS | 特殊（需 adb grant） | 无线调试开关；可选「一键切换」 | 电脑执行一次 `pm grant`（App 内有复制命令按钮） |
| FOREGROUND_SERVICE / _MEDIA_PROJECTION / _MICROPHONE | 普通 | 录屏 / 麦克风前台服务 | 自动 |
| REQUEST_INSTALL_PACKAGES（Phase 5 新增） | 普通 + appops | 应用内更新安装 APK | 首次更新时允许「安装未知应用」 |

Manifest 权限 5 → 6 条。非 Manifest 的系统环节：无障碍服务开关、每次录屏 MediaProjection 授权、IME 启用 + 选默认（向导收敛为 2 步）、安装未知应用开关。兼容性：minSdk 30（Android 11+），arm64-only；K60 / Android 15 满足。

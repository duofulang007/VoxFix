# 键盘系统检查：官方公开方法参考

调研日期：2026-10-15。本文只整理官方文档和 AOSP 公开测试中的方法，并给出适用于 VoxFix 的检查建议；不是本项目测试通过记录。未查询、也不声称掌握讯飞、搜狗或 Gboard 的内部测试流程。AOSP LatinIME 也不等于当前商业 Gboard。

## 1. 可直接学习的官方源码实例

| 官方来源 | 实际检查方式 | VoxFix 可采用的做法（本项目建议） |
|---|---|---|
| [LatinIME InputLogicTests](https://android.googlesource.com/platform/packages/inputmethods/LatinIME/+/refs/heads/main/tests/src/com/android/inputmethod/latin/InputLogicTests.java) | `testDeleteSelectionTwice`、`testBackspaceAtStartAfterAutocorrect`、`testManualPickThenType`、`testTypeWithinComposing` 等，验证一串操作后的文本，有的同时检查 composing span | 用“输入→候选上屏→重定位→删除→继续输入”等组合路径验证最终文本、光标与组合态。只采用本项目已有语义，不照搬英文自动纠错规则 |
| [LatinIME RichInputConnectionAndTextRangeTests](https://android.googlesource.com/platform/packages/inputmethods/LatinIME/+/refs/heads/main/tests/src/com/android/inputmethod/latin/RichInputConnectionAndTextRangeTests.java) | 使用 `MockConnection`，`testGetWordRangeAtCursor` 等检查光标附近范围及不同文字 | 在 JVM/纯逻辑层覆盖空文本、边界、不同字符；再到宿主验证真实回调，不能把 mock 当宿主实现 |
| [LatinIME LatinImeStressTests](https://android.googlesource.com/platform/packages/inputmethods/LatinIME/+/refs/heads/main/tests/src/com/android/inputmethod/latin/LatinImeStressTests.java) | 50 轮语言切换，混入随机词/随机 Unicode 码点；随机种子取当前时间 | 在隔离网页测试中混合已有面板切换、输入、取消；建议固定并输出 seed，失败可重放。压力测试没崩溃仍不能代替正确文本断言 |
| [Android CTS InputMethodServiceTest，固定提交 adc36fbe](https://android.googlesource.com/platform/cts/+/adc36fbed552102026317d8b155071a19925f3eb/tests/inputmethod/src/android/view/inputmethod/cts/InputMethodServiceTest.java) | 用 `MockImeSession` 和事件流等待指定回调；`testRequestHideSelf` / `testRequestShowSelf` 同查事件与可见性；`testCursorAfterLaunchAnotherActivity` 查跨 Activity 光标 | 借鉴事件驱动、绑定输入框身份、断言不应出现的迟到事件。显示状态需同时看窗口、WebView 文档和实际画面 |

同一个 CTS 文件中的 `UpdateSelectionTest` 可分别运行于原生 `EditText` 和 `TestWebView`；其 `verifyText` 注释明确 WebView 分支忽略 selection，仅验证文本。因此，即使照着官方测试测出了“文本正确”，也不能外推“WebView 反向选择、活动终点和视口跟随正确”。这是本项目必须补足的独立验收维度。以上为源码阅读结论，不代表在 K60 上执行过 CTS。

LatinIME 链接为调研时的 main，文件页可核对 blob；这里只参考方法，未引入源码。今后若复制实现，须固定上游版本、保留 Apache-2.0 许可并做设备验证。

## 2. 官方生命周期与输入框契约

[Android IME 开发指南](https://developer.android.com/develop/ui/views/touch-and-input/creating-input-method)要求依据 `EditorInfo.inputType` 处理普通文本、数字、电话、URL 等输入框，说明 composing/commit 的区别，并要求密码不在键盘 UI 显示或存储。指南还强调快速呼出、资源加载和隐藏后内存释放。应据此检查输入类型、文本提交和敏感内容路径，而不是只看每个按钮是否能点。

[`InputMethodService` API](https://developer.android.com/reference/android/inputmethodservice/InputMethodService)区分 `onStartInput`、`onStartInputView`、`onFinishInputView`、`onFinishInput` 等回调；关闭输入视图与结束当前输入不是同一事件。本项目建议的故障注入点：正在组合、录音、长按或续移时收键盘、换输入框、切宿主、重开键盘。检查旧会话任务不写入新输入框、定时器停止、按压态清理，并按现有约定恢复锁定状态。

## 3. VoxFix 最小系统检查矩阵

以下是从上述方法推导的本项目检查清单，并非官方规定的测试数量或通过标准。对已有功能做检查，不恢复停用的手写和安卓 Qwen。

| 范围 | 关键路径与边界 | 最低证据 |
|---|---|---|
| 26 键与英文 | 连打、Shift/大小写、空格、删除连发、松手/失焦/取消；中英/数字/符号来回切换后状态一致 | 网页事件与文本断言；K60 触摸验收 |
| 拼音与候选 | 简拼/全拼、未完成音节、选词后继续、空格/标点/删除、展开/翻页/词字切换、滚动恢复；原生引擎不可用 | 前端逻辑与 JVM；librime 装机后实测，不用浏览器词库代替 |
| 输入框类型 | 原生多行、单行、搜索、邮箱、URL、数字、电话、密码；进入特殊框再回普通框；Enter 动作 | EditorInfo/桥接检查 + 真宿主 |
| 编辑与滑轨 | 正反向选区、穿过起点、文首文尾、换行、长文、宿主排序、手动移动光标、锁定与收面板、八方向松手停止 | JVM 导航模型 + 网页手势；K60 原生框和笔记 WebView 独立验收 |
| 剪贴板/常用语 | 复制通知延迟、空选区禁用、一次点击、锁定/滚动、删除与撤销、保存失败、重开/重启持久化 | 隔离数据网页检查 + 真实系统剪贴板；不删改用户数据 |
| 表情与 Unicode | 中英混合、非 BMP 表情、组合符、ZWJ 序列；插入/删除/选择后的文本完整性 | 逻辑与宿主实测；区分 UTF-16 偏移、码点和用户可见字素 |
| 语音 | 短按与长按门槛、上滑取消/松手结束、拒绝权限、录音中切框/收起、两遍结果迟到、连续两次会话 | 纯逻辑检查 + 真机录音；不以电脑服务代替安卓，不留存日常音频 |
| 生命周期 | 冷/热呼出、返回隐藏再开、跨 App、横竖屏、进后台/回前台；旧任务不能串框 | 回调/身份/可见性证据 + 真机画面 |
| 视觉与衔接 | 按压立即出现和清除、无粘色；候选展开、剪贴板/符号/编辑框切换、夜间模式；快速反向切换和中途打断 | 网页几何/类名/截图 + K60 真实触摸；按现有交互约定判定，不自行加动画 |
| 持久化与隐私 | 设置存取失败不丢编辑、密码不进候选/学习/历史、诊断不包含用户输入、覆盖安装保留私有数据 | 源码数据流、隔离故障检查；安装前后受控比对，不能上传私有词库 |

优先验证“内容不丢、不重复、不串框、不泄露”，再看操作状态、最后测速度和视觉。失败需留输入条件、步骤、预期/实际、源码/APK 身份及证据层级；修复后只回归受影响路径。

## 4. 动效、衔接和延迟应怎样查

[Android 键盘动画指南](https://developer.android.com/develop/ui/views/layout/sw-keyboard)介绍通过 WindowInsets 查询 IME，以及让宿主布局跟随 IME 显隐动画。该页主要面向宿主应用，并非要求键盘自己给每个按钮加过渡；不能据此声称 VoxFix 能控制所有宿主的窗口动画。当前 K60 是 API 35，不采用该页新出现的 API 37.2 机制作为本机修复依据。

[Macrobenchmark 指标文档](https://developer.android.com/topic/performance/benchmarking/macrobenchmark-metrics)提供 `FrameTimingMetric`，可报告 P50/P90/P95/P99；API 31+ 的 `frameOverrunMs` 正值表示帧超过截止时间。适合比较同设备、同场景的候选展开、列表滚动和面板切换，不应只报平均帧率。

[Perfetto FrameTimeline](https://perfetto.dev/docs/data-sources/frametimeline)区分预期与实际帧时间；它指出帧可能平滑却呈现偏晚，导致输入延迟增加。因此本项目建议分别记录：按下到按压态、松手到宿主文本出现、候选请求到候选可见、点开到面板稳定、长按语音到开始采集/结束到第二遍完成。上述是不同终点，不合并成一个“响应速度”。

[Macrobenchmark 使用指南](https://developer.android.com/topic/performance/benchmarking/macrobenchmark-overview)提供可重复旅程的基准方法。若后续采用，应确认采集到的是 IME/WebView 所属进程及正确窗口，不能只测承载测试的 Activity。现阶段可先复用既有测试和系统 trace；这份调研不要求新增基准依赖。

建议做同设备、同刷新率、同温度区间、同输入长度的多轮比较，记录样本量和冷/热状态；这是本项目实验控制建议。没有实测前不宣称达到官方键盘延迟或“无掉帧”。录屏可看衔接和闪动，不能单独准确证明触控到显示的毫秒延迟。

## 5. 证据边界与本轮范围

| 层级 | 能证明 | 不能证明 |
|---|---|---|
| 源码审查 | 可达错误路径、状态清理、数据流与 API 使用 | 分支已在真实设备发生 |
| 网页/Playwright | 前端事件顺序、状态、样式、几何与隔离存储行为 | Android InputConnection、原生 Rime/语音、K60 触摸和真实帧率 |
| JVM | 纯逻辑状态机、边界、会话身份与导航模型 | 宿主排序/回调时序、WebView 可见性、系统剪贴板 |
| APK 构建/资源比对 | 可构建，打包资源对应源码 | 已安装、当前运行该包、实际使用通过 |
| 装机与诊断 | 设备包版本、进程/窗口/回调、系统状态 | 真人触摸手感、所有 App 都正确 |
| K60 真人场景 + 现场证据 | 当前 APK 在明确宿主、步骤、设备上的结果 | 未测宿主和长时间稳定性 |

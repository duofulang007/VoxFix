# 长截屏三档滚动：现状原理、不足与优化（2026-11-09）

> 范围：截图工具条「长截屏」（T27）。证据来自 `ScreenshotScrollCapture.kt`、`ScreenshotStitch.kt`、
> `ScreenTextService.kt` 与内置 Rust 拼接器 `.android/snow-scroll-capture/native/crates/snow-stitch-images`。
> 结论先给：**画质本身是原生分辨率、无损 PNG，主要问题不在压缩，而在“采集时机 + 位移估计 + 接缝合成”**；
> 快速滑动会出现无法匹配而丢带，缓慢滑动会出现 1px 级接缝，自动滚动则是固定步长与固定间隔导致的重复/漏拍。

## 1. 当前实现链路

### 1.1 采集（Kotlin）

| 项 | 现状 | 位置 |
| --- | --- | --- |
| 取帧方式 | `AccessibilityService.takeScreenshot`，取整屏后按选区裁剪 | `ScreenshotScrollCapture.kt:92`、`:143` |
| 像素格式 | 硬件缓冲 → `ARGB_8888` 软件位图 → 直接 `copyPixelsToBuffer` | `:135-143` |
| 手动节奏 | 滚动事件到达即请求一帧；两帧最小间隔 **350ms**，无事件时 **460ms** 定时兜底 | `:318-328`、`:499-500` |
| 自动节奏 | 注入 440ms 滑动手势，滑动距离为选区 **1/3**；完成后等 `autoIntervalMs`（默认 200ms，可设 128–1000）再取帧 | `ScreenTextService.kt:1041-1054`、`ScrollCapture:62`、`:285-302` |
| 自动停止 | 连续 3 帧重复或 3 帧无增长即停 | `:309-313` |
| 取帧上限 | 选区（裁剪后）每帧一次，无多帧缓冲 | `:39-44` |

> 实际自动间隔受系统限制：`autoIntervalMs=200` 仍会被 350ms 最小间隔和系统截图频率上限拉到约 350–460ms。
> 即**两次采样之间页面可能已经滚过 0.35–0.46 秒的惯性距离**。

### 1.2 拼接（Rust）

| 项 | 现状 | 位置 |
| --- | --- | --- |
| 特征 | ORB 二值特征，32px tile，最多 2500 特征；Lowe ratio 0.8、Hamming | `estimator.rs` 常量区 |
| 估计 | 先降采样（长边按面积压到约 512×extent 的等比，1080 宽约降到 743）再全分辨率重试；候选位移整数像素 | `sampling.rs`、`estimator.rs:1062` |
| 置信门槛 | `min_confidence=0.65`；至少 8 个内点、覆盖 4 个 tile；最大位移 = 视口 **60%** | `types.rs:178-187`、`estimate` 常量 |
| 重复判定 | 上一帧与当前帧**逐像素完全相等**才判重复 | `stitcher.rs:322` |
| 失败处理 | 未匹配/无位移时，**把当前帧设为新的 `previous_raw`** | `stitcher.rs:374-380` |
| 合成 | 画布按 tile 精确拷贝，**没有羽化/混合**；重叠区直接截断 | `stitcher.rs:390-430`、`tiled_canvas.rs:152` |
| 上限 | 20000px 或 16MP 先到者 | `ScreenshotStitch.kt:31-33` |

### 1.3 输出

- 保存走 `ScreenshotStitch.render(start,end)` 全分辨率 → `ScreenshotStore.save()` **PNG 无损**；
- 预览 `render(4096)`，工具条缩略图 `render(160)`；
- `ScreenshotStore` 限制：≤1600 万像素、PNG 文件 ≤16MB（`ScreenshotStore.kt:79-110`）。

**因此“画质模糊”多数来自 160px 缩略图和预览缩放，不是成品**；成品是原生 1080 宽、无重采样。

## 2. 快速滑动

### 2.1 原理与真实路径

- 惯性期每 350ms 才允许一帧；一帧的位移 = 滚动速度 × 0.35s。
- 估计器只接受 **≤60% 视口高** 的位移（`max_motion_ratio=0.6`）。
- 超过 60% 或重叠不足 8 个内点/4 个 tile → `NoMovement/UNMATCHED`。
- 失败时 `previous_raw` 被替换成这一帧，**这段未匹配的内容在继续向下滚动时不会再进入画布**（只有回滑触发 prepend 才可能补回），形成缺带。

### 2.2 具体不足

1. **丢带不可恢复**：一帧未匹配就丢掉 0.35s 的滚动内容，后面再稳也补不回来。
2. **只提示“请慢滑”**：没有回滑引导，用户不知道缺口已经发生。
3. **60% 上限偏保守**：一次轻快 fling（约 2 屏/秒）在 350ms 内就超过 60%。
4. **固定内容（sticky 栏、悬浮按钮、进度条）占比高时**会被判 scene-cut / 固定内容主导，整帧拒收。
5. 精确重复判定对时钟、光标闪烁、抗锯齿敏感，快速滚动时又常伴随动态内容，重复与未匹配会交替出现。

### 2.3 优化方向

| 优先级 | 改动 | 预期 |
| --- | --- | --- |
| P0 | **未匹配不推进参考帧**：保留最后成功匹配的帧作为 reference，直到再次匹配；同时在缩略图标记“缺口，请回滑补拍” | 不会静默丢带；最坏情况可控可补（**未落地，需改原生 stitcher**） |
| P0 | **仅自动模式停稳再拍**：自动手势结束后等 90ms 无滚动事件再取帧；手动仍保持最高采样率（等停稳会整屏丢失） | 自动帧间位移稳定，匹配率上升（已落地） |
| P1 | **粗到细搜索**：1/4 降采样相位相关先估到 90%，再全分辨率精修 | 2 屏/秒的 fling 仍可匹配，减少“请慢滑” |
| P1 | **自动模式下失败即回退**：把本次步长减半并重拍，不把失败帧计入 `stalledSteps` | 自动模式不再因一次快滑直接停 |
| P2 | **高速模式（可选）**：MediaProjection 连续取帧 15–30fps，只在用户主动开启时使用 | 任意 fling 无缺口；代价是额外授权与功耗 |

**预期效果**：P0 + 粗到细搜索后，常规 fling（≤2 屏/秒）匹配率 ≥95%，无永久缺带；超过能力时明确提示并允许回滑补齐，而不是静默错位。

## 3. 缓慢滑动

### 3.1 原理与真实路径

- 慢滑时相邻帧重叠 80–95%，本应最容易匹配。
- 但估计偏移是**整数像素**（垂直方向 1px 量化；降采样只压缩横向宽度以降低特征计算量，纵向高度保持全分辨率）。
- 合成是精确拷贝，重叠区直接截断，没有 1px 级羽化。
- 位移为 0 或帧间仅有时钟/闪烁差异时，判 `NoMovement`，计入 stalled。

### 3.2 具体不足

1. **1px 接缝**：整数偏移 + 硬切，渐变/表格线上会出现一条重复或缺失的细线，慢滑最容易累积。
2. **亚像素缺失**：垂直位移以整数像素落位，合成又是硬切，没有 0.5px 级拟合；横向降采样只影响特征数量，不影响纵向偏移精度。
3. **微小滚动被判无运动**：`visible_interior_pixels_equal` 只看完全相等；时钟变化又会被当成新帧，二者都不推进画布。
4. **动态区域**（视频、加载动画、输入光标）没有排除，接缝可能切在动画中间。
5. 慢滑帧数多，每帧都要走 ORB + 相似度图，长时间采集 CPU 占用高（滤波压力测试已有 302ms 帧耗时的先例）。

### 3.3 优化方向

| 优先级 | 改动 | 预期 |
| --- | --- | --- |
| P0 | **亚像素精修**：相似度峰值抛物线拟合/梯度相位相关，输出浮点偏移 | 接缝误差 ≤0.5px |
| P0 | **2–4px 羽化**：只对静态 tile 做线性 alpha 过渡；动态 tile 保持硬切 | 渐变、纯色背景无缝；视频不重影 |
| P1 | **动态/固定 tile 排除**：复用估计器已有的 fixed/dynamic 分类，固定栏只取最后一帧、动态区不参与接缝 | 不重复 sticky 栏、不切断动画 |
| P1 | **容差重复判定**：像素差 ≤ 阈值或感知哈希相同即视为重复，更新参考但不计增长 | 时钟/光标不再造成假增长 |
| P2 | **增量预览**：每接受一帧就刷新缩略图（现在只在特定事件刷新） | 慢滑时用户能看到实时进度 |

**预期效果**：慢滑接缝在 100% 缩放下不可见；重复/无运动不再误判为失败；长页面慢滑不因 CPU 过热降频。

## 4. 自动滑动

### 4.1 原理与真实路径

- 每次注入 `1/3 选区高度`、`440ms` 的滑动手势（`scrollStep`）。
- 手势完成后等 200ms 取帧；实际被 350ms 最小间隔拉长。
- 匹配失败连续 3 次、或重复连续 3 次 → 自动停止。
- 步长固定，不读取“这次实际滚了多少”。

### 4.2 具体不足

1. **步长固定**：短页面/慢物理滚动时重叠过大（重复帧多），长页面/惯性大时又可能一次超过 60%（未匹配）。
2. **拍在惯性中**：440ms 手势结束后页面仍有惯性，200ms 后取帧可能正处在减速段，帧间位移不可控。
3. **停止条件语义错误**：`stalledSteps` 同时包含“真的到底了”和“匹配失败”，提示却统一成“画面未继续增长”。
4. **不会自适应**：失败后不会减小步长重试，重复后不会增大步长加速。
5. **到底判定弱**：只靠连续 3 次无增长，遇到吸底回弹/加载更多会误停或空转。
6. 1/3 步长对高视口（2400px）是 800px，重叠约 67%，理论上够；但对小选区（如 800px 高）只有 267px，重叠 67% 仍够，惯性一大就超限。

### 4.3 优化方向

| 优先级 | 改动 | 预期 |
| --- | --- | --- |
| P0 | **闭环步长**：以“上次实际位移”反馈，把目标重叠控制在 30–45%；未匹配→步长减半重试，重复→步长 +20% | 不同页面长度都能连续推进，不空转 |
| P0 | **滚动停稳检测**：手势完成后等 80–120ms 无滚动事件再取帧，而不是固定 200ms | 帧间位移稳定，匹配率高 |
| P1 | **区分停止原因**：未匹配提示“画面变化过快，已暂停”；真正到底提示“已到页面底部” | 用户知道该继续还是已结束 |
| P1 | **到底检测**：连续 2 次零位移 + 滚动容器 `canScrollForward=false`（可用节点信息） | 不多拍空白、不漏最后一段 |
| P2 | **可调步长 UI**：把 autoInterval 改成“每次滚动距离”（1/5–1/2 视口），间隔保持隐藏常量 | 参数对用户有意义 |

**预期效果**：20 屏长页自动采集，重复帧 ≤1、无漏拍、到底即停；中途失败可自动降步长继续，而不是整段中止。

## 5. 画质与输出（三档共用）

| 问题 | 现状 | 建议 |
| --- | --- | --- |
| 成品清晰度 | 原生 1080 宽、ARGB、PNG 无损 | 保持；不要为了体积改成 JPEG |
| 缩略图观感 | 工具条渲染 240px（本轮由 160 提升），仍标注为预览 | 避免用缩略图判断成品清晰度 |
| 上限截断 | 1080 宽最多 14814px（16MP），到达即结束，无提示 | 到上限前提示“已达单张上限，可分段保存” |
| 保存失败 | PNG >16MB 会被 `ScreenshotStore` 拒绝（照片型长图常见） | 长截图单独放宽上限，或提供 WebP 无损/高质量 JPEG 选项 |
| 色域 | 硬件缓冲统一转 ARGB_8888，广色域/HDR 会丢 | 普通 SDR 可接受；如遇偏色，保留 `colorSpace` 再编码 |
| 内存 | 16MP 画布 + 每帧整屏拷贝，峰值约 100–150MB | 超长页面分段落盘；限制并发帧 |

## 6. 建议落地顺序与验收指标

**第一批（P0，代码量小、收益最大）**

1. 未匹配不推进参考帧 + 缺口提示；
2. 停稳再拍（手动/自动共用）；
3. 亚像素偏移 + 2–4px 静态区羽化；
4. 自动步长闭环与失败回退。

**第二批（P1）**

5. 粗到细位移搜索（90% 上限）；
6. 动态/固定 tile 排除与容差重复判定；
7. 到底检测与停止原因区分；
8. 上限/保存失败提示。

**第三批（P2）**

9. 可选高速模式（MediaProjection 连续取帧）；
10. 长图分段落盘、WebP/JPEG 保存选项。

**验收指标（真机，K60 + 长页/表格/聊天/相册四类页面）**

- 快速：2 屏/秒 fling 连续 20 次，缺带 0、错位 ≤1px；超过能力时 100% 出现“回滑补拍”提示。
- 缓慢：慢滑 3 屏，100% 缩放无缝（渐变页无可见横线），接缝误差 ≤0.5px。
- 自动：20 屏页面一次到底，重复帧 ≤1、漏拍 0、无提前停止；到底提示正确。
- 画质：成品宽 = 选区原生宽，PNG 无二次缩放；16MP 内不降采样。
- 性能：连续采集 60 帧无 ANR，单帧拼接 P95 ≤250ms（当前滤镜压力基线 302ms 已是上限参考）。

## 6.1 本轮未落地（需改原生拼接器）

以下三项都在 Rust 侧，Kotlin 无法覆盖：

1. **未匹配不推进参考帧**（`stitcher.rs` 失败分支）——决定“丢带是否可恢复”；
2. **亚像素偏移 + 2–4px 静态区羽化**（`estimator.rs` / `compositor.rs`）；
3. **粗到细位移搜索**（`estimator.rs`，把 60% 上限提到约 90%）。

原因：`tools/build_snow_region.py` 每次构建都会从固定提交的源码包重新抽取 `crates/`，直接改
`.android/.../native/crates` 会被覆盖。要落地需新增一个可重复的 patch 步骤（或独立 crate），
再跑 `cargo test`（原生单测）+ `assembleDebug` + 真机长截屏回归。建议单开一轮，不和 UI 改动混在一起。

## 7. 明确不建议做的

- 为了“绝对无缝”把用户滚动锁死或强行降速：破坏宿主手感，且不属于截图工具职责。
- 默认开启 MediaProjection 常驻采集：授权成本、隐私提示和功耗都不适合默认路径。
- 用放大/锐化掩盖接缝：会牺牲文字边缘，属于假清晰。
